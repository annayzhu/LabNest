## 1. 修改目标与依据

用户反馈：系统中的“AI审核”目前为空，而是否启用 AI 的配置位于“设置”中。用户希望保留现有导航位置，将其改为统一的 AI 管理入口，把设置中的 AI 模块整体迁入，并在这里承接以后新增的 AI 配置。

**本轮决策：保留入口，名称改为“AI”；页面以“启用 AI”总开关为核心，承载现有 AI 设置。**

这样既能去掉不符合实际用途的“审核”名称，也能让用户直接找到开关。当前只有少量设置时，使用一个紧凑页面，不增加二级目录、空功能卡片或多层折叠。

v1.0 根据用户描述制定迁移要求；v1.1 已静态阅读 `annayzhu/LabNest` 的 `main` 提交 `65500d2e940e1b861ac9ec78950eeb14c7292fdc` 中相关源码，并查看用户的 WorkBuddy 截图。尚未登录用户运行中的 LabNest，也未使用真实 API 密钥测试。源码状态、部署状态与真实外部连接结果必须分别报告。下文涉及原有配置时沿用真实实现；此次明确新增的表单内测试要求见第4.4节。

## 3. 信息架构与页面布局

### 3.1 入口归属

| 当前位置或内容 | 调整后的位置与行为 |
| --- | --- |
| 主导航“AI审核” | 原位置改为“AI”，页面标题、面包屑、移动导航同步更新 |
| 设置中的 AI 开关及配置 | 整体迁入 AI 页面，沿用原配置和保存逻辑 |
| 原设置中的 AI 区域 | 删除可编辑控件，只留一条轻量入口“AI 设置 →”，跳转到 AI 页面 |
| 原“AI审核”网址及旧设置深链接 | 能继续到达新的 AI 页面；根据项目实际路由实现兼容，避免失效或跳转循环 |
| 实验、Entry 等页面的具体 AI 操作 | 若当前已存在，保留在其使用场景；启用状态和相关配置由 AI 页面统一管理 |
| 以后新增的 AI 配置 | 统一增加到 AI 页面，不在设置页再建第二套配置 |

AI 页面在关闭状态下仍然可进入。若以后真正实现“AI审核”，可以作为 AI 模块内的一项具体能力，不再占用整个模块名称。

### 3.2 页面从上到下的顺序

1. **标题“AI”**，下方一句说明：“管理 AI 功能与相关设置。”
2. **总开关**：左侧“启用 AI”，右侧标准开关；旁边明确显示“已开启”或“已关闭”。
3. **现有 AI 配置**：将当前设置中的相关内容迁入，按“连接设置”“功能设置”等实际存在的内容分组。没有对应内容就不显示该分组。
4. **必要的保存与反馈**：按第 4 节统一处理，不复制旧页面的多余留白或空说明。

总开关与主要设置应尽量在首屏可见。桌面使用紧凑表单；窄屏使用单列布局，标签、输入与开关对齐。当前内容少时不要做巨大卡片、仪表盘、功能广场或二级标签页。

### 3.3 控件与文案

- 使用项目统一的黑白简洁图标和表单控件；不要沿用容易暗示审批用途的图标。图标与导航文字大小、间距保持一致。
- 开关必须有可点击标签、键盘操作及可读状态，不能只用颜色表达开启与关闭。
- 下拉箭头沿用全站统一的右侧留白，不能贴边；输入宽度按内容设置。
- 必须折叠的低频配置点击后立即显隐，标题文字不移动，不增加展开动画；核心开关不折叠。
- 删除“暂无审核任务”“待审核”等与当前页面用途无关的空态。不存在的能力不展示“即将上线”卡片或无效按钮。
- 关闭说明使用简短文字：“已关闭 AI，现有记录保持不变。”
- 若开启后缺少必要配置，明确显示“已开启 · 待配置”，并定位需要填写的字段。开关开启不等于连接成功，不显示未经验证的“连接正常”。

### 3.4 API 配置字段与中文说明

WorkBuddy 截图中的“供应商”已经限定为 OpenAI 兼容协议，并把官方地址等细节预先配置好。LabNest 支持多种接口，必须让用户能理解这种区别。优先使用现有 DeepSeek 快捷配置降低填写负担；不为本次修改新建模型市场。

| 当前字段 | 调整后的标签 | 说明与实际行为 |
| --- | --- | --- |
| Provider name | 服务名称 | 仅用于自己识别，如“DeepSeek 官方”；名称本身不决定服务商或协议 |
| Type | 接口类型 | 按服务方提供的 API 协议选择，不能按模型品牌、是否推理模型或实验用途猜测 |
| Base URL | API 基础地址 | API 请求的公共地址前缀；不是聊天网页地址，也不是完整的单次调用地址。已选官方预设时自动填入，保留编辑能力 |
| Default model | 默认模型／模型 ID | 该连接实际发送给服务方的模型标识。不是任意备注名，也不会自动选择更强或更便宜的模型；Dify 例外见下表 |
| API key | API 密钥 | 服务方平台颁发的调用凭据；编辑时留空保留原密钥，不回显已保存的完整值 |
| Provider enabled | 启用此服务 | 控制这一条连接；与页面顶部的 AI 总开关分别生效 |
| Default provider | 默认使用的 AI 服务 | 从已保存连接中选择业务功能实际使用的连接，需点击“保存功能设置”；添加服务不等于自动选为默认服务 |

接口类型选项增加中文名称与短说明，保持原存储值和适配器：

| 存储值 | 建议显示名称 | 选择依据 |
| --- | --- | --- |
| `openai_compatible` | OpenAI 兼容接口 | 对方明确支持 Chat Completions 接口时使用；直连 DeepSeek 采用这一项 |
| `openai` | OpenAI 官方接口 | 用于 OpenAI 官方 API；当前代码与兼容类型共用对话适配器，并提供官方默认地址 |
| `anthropic` | Anthropic 接口 | 对方提供 Anthropic Messages 格式时使用；按其服务文档填写地址与模型 |
| `dify` | Dify 应用 | 接入已发布的 Dify 应用，例如相应的浙大 AIHub 应用。模型由 Dify 应用配置决定，此处模型字段仅为可选说明，不改变实际模型 |
| `manual_copy_paste` | 手动复制粘贴 | 生成提示词，手动到外部聊天工具运行；不填写 API 地址、密钥或模型，不显示联网测试 |

同一个 DeepSeek 模型，如果直接连接 DeepSeek 官方 API，应选择 OpenAI 兼容接口；如果通过 Dify 应用调用，应选择 Dify。决定类型的是“LabNest 与哪个接口通信”。

**DeepSeek 官方配置示例（2026-10-14核对）：**

- 服务名称：`DeepSeek` 或其他自定义识别名。
- 接口类型：`OpenAI-compatible endpoint`，中文化后为“OpenAI 兼容接口”。
- API 基础地址：`https://api.deepseek.com`；与当前快捷配置一致。
- 默认模型：按截图选择 DeepSeek-V4 Pro 时填写 `deepseek-v4-pro`；当前快捷配置预填的是 `deepseek-flash`，两者不同。
- API 密钥：从 DeepSeek 开放平台取得；不能填写聊天账户密码。

本项目适配器会在基础地址后追加 `/models` 或 `/chat/completions`。不要把 `https://api.deepseek.com/chat/completions` 填入基础地址，否则会重复拼接路径。保留已有兼容服务需要的 `/v1` 或自定义前缀，不统一删除，也不无条件追加。

模型字段应显示简短示例，并允许输入精确模型 ID；界面显示名与请求 ID 分别处理。预设模型名不是永久有效的保证，实际调用结果与账号权限为准。

## 4. 总开关的确切行为

### 4.1 状态与作用范围

| 情况 | 界面表现 | 实际行为 |
| --- | --- | --- |
| AI 已关闭 | 显示“已关闭”；配置仍可查看和编辑 | 不发起新的 AI 请求或 AI 自动任务；保存普通配置不调用 AI |
| AI 已开启且配置齐备 | 显示“已开启” | 允许按原有功能和触发方式使用 AI；仅开启开关不触发批量处理 |
| AI 已开启但缺少必要配置 | 显示“已开启 · 待配置” | 提示补充配置；相关 AI 操作不发送无效请求 |
| 配置读取中或读取失败 | 显示加载或明确失败状态 | 不把未知状态当作开启；保留重试入口，不覆盖已保存的配置 |
| 保存开关失败 | 恢复最后一次保存成功的状态，并在开关旁提示 | 页面与实际配置保持一致，不假装保存成功 |

必须沿用现有配置的用户或工作空间作用范围。此次“总开关”指**该既有范围内的全部 AI 调用**，不是擅自新增一个控制所有用户的开关。若现有系统同时有管理员限制和个人设置，保持原有权限及优先关系，页面简要说明当前可修改的范围，不额外扩建权限系统。

### 4.2 保存规则

- 总开关修改后立即保存；保存过程中防止重复提交，失败时回退并提示。不要让用户切换后还需寻找第二个“保存”按钮。
- 其他配置保留现有的自动保存或显式保存机制，但页面必须清楚显示是否已保存。显式保存仅作用于对应配置，不悄悄改变总开关。
- 若存在尚未保存的配置，点击总开关不得隐式提交这些草稿；开启状态以已保存配置判断是否可用。
- 关闭 AI 不清空连接信息、子功能选择或已有 AI 结果。重新开启后沿用已保存配置，不将所有子功能强制打开。
- 新用户没有历史设置时默认关闭；已有明确保存值按原值迁移，不因页面改名而重置或自动开启。
- AI 页面、业务页面、刷新后的页面须读取同一配置来源。多标签页通过现有同步机制或重新获得焦点时刷新状态，避免长期显示旧值。

### 4.3 关闭必须落实到调用层

仅隐藏按钮或禁用前端控件不算完成：所有已有 AI 调用路径须在合适的公共入口检查开关；存在服务端接口时，服务端同样执行对应范围的限制。若当前为纯本地架构，则在共享调用层统一限制，不为此任务强行引入新服务。

用户关闭时，应阻止尚未启动的请求、排队任务和自动重试；对已经发出的请求，在现有架构支持时尝试取消。不能声称关闭能够撤回已经发送给服务方的数据。关闭后晚返回的结果不得自动覆盖用户正文或继续触发后续 AI 任务。

启用开关本身不得自动扫描历史 Entry、批量处理实验、重试旧任务或发送附件。已有非 AI 功能、人工审核流程、普通计算和数据保存继续正常运行。

连接测试仅由用户点击触发；关闭状态下不提供可绕过总开关的外部 AI 测试调用。保存配置与测试连接应区分清楚。新增表单内测试沿用同一限制。

### 4.4 必须提供表单内“测试连接”

**按钮位置与基本行为**

1. 在添加和编辑服务表单的“API 密钥”旁放置“测试连接”；窄屏可换行放在密钥框下方。保存后的服务卡片保留同名按钮。无需先保存、再退出表单，才能测试新填写的连接。
2. 表单测试使用当前填写的类型、基础地址、模型 ID 和密钥；不自动保存，不更换全局默认服务，不开启总开关，不写入实验记录。成功时清楚显示“测试成功，配置尚未保存”。卡片测试使用已保存的配置。
3. AI 总开关关闭或当前服务停用时，禁用测试并说明原因。测试新连接不要求先把它选为全局默认服务，避免形成“先保存才能测试”的循环。
4. 缺少必填项时定位对应字段；测试过程中显示“正在测试…”，防止重复提交，提供有限超时。修改类型、地址、模型或密钥后，旧测试状态立即失效；旧请求晚返回不能覆盖新表单的结果。

**测试必须验证什么**

5. 对直接模型 API，“测试成功”须验证所填模型能完成一次简短调用并返回符合该协议的有效内容；使用固定无业务信息的测试文字，不读取 Entry、实验、规程、附件或聊天记录。仅 `/models` 返回成功，最多表示模型列表可访问，不能表示指定模型可用。
6. 可复用模型列表查询作为辅助诊断，但返回 HTML、空对象、无效响应格式不能算成功。列表接口不支持时仍可用有效的最小模型请求测试。所请求模型和服务实际返回模型若不同，要明确显示；不静默换成其他模型再报告原模型成功。
7. 采用与现有业务适配器一致的请求格式与密钥处理。按实际协议设置合理的输出上限和总时限；不对所有服务硬塞同一组参数，也不把推理模型因过小输出额度被截断误判为密钥错误。按钮附近简要说明“将发送一条简短测试消息，可能产生少量 API 费用”，不追加反复确认弹窗。
8. Dify 使用现有应用适配器验证对应应用；若仅验证到 `/parameters`，显示“应用接口可访问，尚未验证生成”，不能称为模型调用成功。需要验证生成时，只向该已配置应用发送固定测试文字；手动复制模式不发送网络请求。

**密钥与配置状态**

9. 新密钥仅经 LabNest 服务端完成测试，不从浏览器直接请求服务方，不写入浏览器持久存储或日志。编辑已有连接且密钥留空时，由服务端在同一连接与相同目标下复用保存的密钥，不回传给前端。改变服务目标或协议时不得默默把旧密钥发往新地址，须重新填写适用于新目标的密钥。
10. 复用现有 `validateAIRequest` 来源检查、AI 总开关限制及配置变更中止逻辑。只增加草稿配置的校验／测试入口，不复制一套独立 AI 请求逻辑。测试过程不影响其他用户业务请求，也不能通过未保存草稿绕过工作空间设置。

**反馈文案**

| 结果 | 界面应说明的内容 |
| --- | --- |
| 模型请求成功 | “测试成功”，本次模型、响应耗时；若为草稿注明“尚未保存” |
| 密钥鉴权失败 | “API 密钥无效或已失效，请检查密钥”；仅在服务返回对应证据时使用 |
| 余额不足 | “账户余额不足，请到服务平台检查”；与限流、权限不足分别处理 |
| 模型无效或无权限 | “模型不存在或当前密钥无权使用，请核对模型 ID 与权限”；不能一概归为地址错误 |
| 地址或协议不匹配 | “请检查 API 基础地址与接口类型”，提供脱敏后的状态码及简短详情 |
| 限流／服务繁忙 | 指明是请求过快或服务暂时繁忙，允许稍后手动重试 |
| 网络或超时 | “LabNest 服务器无法连接该服务／请求超时”；不能误称为用户浏览器无法联网 |
| 仅配置齐备或列表可达 | 明确标明尚未验证模型生成，不显示完整测试成功状态 |

错误分类结合状态码、服务方错误码和消息；不同服务含义不完全相同。不得仅凭所有404认定模型名错误，也不得把所有403都说成密钥失效。详情展示前脱敏；测试结果不是永久健康状态。

## 5. 配置迁移与实现要求

1. **优先迁移页面，复用现有配置源。** 能复用现有组件和字段时不创建第二套 AI 设置；Settings 和 AI 页面不能各保存一份独立值。
2. 将设置页当前所有 AI 字段逐项迁移，保留已有配置值、默认值语义及依赖关系。不要只迁移开关而漏掉已有参数。
3. 路由名称调整和存储字段重命名没有必然关系。无须为界面改名强行迁移存储键；确需迁移时，给出兼容策略并验证重复执行不会覆盖新值。
4. 保留原有权限校验。若已有密钥或令牌，继续使用原有安全保存方式，不在页面、日志、截图或导出中暴露完整值。
5. 清理没有用途的审核占位界面和文案；若查到真实审核逻辑或历史记录，保留其功能与数据，不以“空页面”为由删除数据库内容。
6. 未来新增 AI 能力的配置接入同一页面和同一总开关。具体“执行 AI 操作”的按钮仍贴近原业务内容，避免用户为了使用功能反复跳转到设置页。

本轮不要求开发新的模型协议、聊天窗口、AI审核算法、自动实验分析、用量看板或费用统计。v1.1 明确新增的是表单内连接测试、模型验证及易理解的字段说明；复用现有连接配置和适配器，不新建第二套密钥存储。
