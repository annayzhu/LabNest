# 账号与多工作区、实验室常开主机；所有设备本地优先并实时同步（Notion 式），Watch 经手机

日期：2026-10-22；修订：v2.0（2026-10-29）。Accepted 表示用户已确认总体方向，不表示账号、跨网、离线、实时同步或手表转发已经实现。

## 当前决定

1. 数据库与原附件放在实验室一台常开的主机（Q117）；各设备保存受保护的业务工作副本和待同步修改。不默认上公有云。
2. 账号、多工作区、成员与角色（拥有者、编辑者、只读者）、会话与全路径后端授权一开始就完整实施（Q121），不能只添加登录页面。暂不开放公众注册、订阅、按页面分享或多机构云托管。
3. 主机与手机所在的两个 Wi-Fi 均能上网但不能互访是首要验收场景。使用机构允许的私有 HTTPS 接入（Tailscale）；不依赖同 Wi-Fi 或让普通用户查询 IP。
4. Watch 默认通过随身 iPhone 交换任务、计时和操作；无需蜂窝套餐、VPN 或独立登录。即使同网也使用手机路径；现有直连受保护兼容，不建设双通道竞速。
5. Notion 式同步（Q118）：每条记录有版本；电脑浏览器与 iPhone App 都有本机副本和操作队列；服务器把变化实时推给在线设备，断开后按游标补齐。所有主要模块从第一天起使用同一套同步引擎。
6. 一套 TypeScript 客户端（Q120）：现有 React 界面改为从本机数据层读写，电脑浏览器、iPhone App（含 iPad）与以后的 Android 共用；业务规则只有一份，服务器与客户端共用。SwiftUI 只做外壳、本机存储桥、相机、计时与灵动岛、通知、手表。不做全部原生重写。
7. 首版不做多人同时编辑同一段文字（Q119）：同一内容两端都改时保留双方并核对；块 ID 保持稳定，以后可加 CRDT。
8. 用户、工作区、实例、设备和当前实验分别建模。切换网络/实验不改变身份；切换工作区就是切换本机分区；退出或换账号不串用队列，旧匿名事实不追认为新账号作者。
9. 恢复后以原操作 ID、当前授权和基础版本提交；冲突保留双方。Watch 已传手机不等于已同步服务器。
10. 正常断网可继续已同步内容的操作；全新安装仍需首次可信接入/登录。前台恢复自动同步，系统后台调度不保证即时传输。
11. 登录后自动同步获授权目录、正文与常规数据，大附件按需、项目可整包离线（Q9 = Q122）。
12. 一次发布（Q123）：按里程碑 N0–N7 开发，只在测试实例上验收；正式服务与现有 App 在发布前保持原样。

## 与旧决定的关系

v2.0 取代 v1.2 的 P0 快路、P1 单一工作区与 W 阶段、M0 路线决策关卡和分段发布；取代 v1.1 中“数据先留在二楼 Mac”的安排。v1.1 起替代的 Q8“无账号试用先行”仍然有效；首次接入后可离线的原则与 Q9 同步范围不变。旧无账号资料与设备队列需要一次性受保护迁移，不能删除。也扩展 `docs/mobile/mobile-app-20261021/MOBILE-APP.md` 的 Q104/Q116，替代 Q107 暂不做账号、Q108 Mac 作为服务器及 Q109 手表默认直连的目标安排；历史文档不改写成已实施事实。

## 取舍与实施限制

所有页面改为本机数据层、同步引擎、实时推送和多工作区授权，是比分段方案更大的一次改造：现有 95 个页面中 63 个直接读数据库，29 个服务端操作文件、57 个 API 路由都要改到同步层。换来的是电脑与手机同一套界面和规则、各端实时一致、断网可用。常开主机解决“电脑睡眠时连不上”，本机副本解决“断网时继续工作”，两者都需要。

先复用 Next.js、Prisma、PostgreSQL、版本化 API 和事务，不引入全系统 CRDT、微服务或消息平台。本机存储、推送方式、App 内客户端性能和 Watch 真机转交在 N0 验证，失败时按任务书二第 13 节的备选方案与用户共同决定。私有连接需要机构允许和真实两网/真机测试。当前修订仅授权更新规划，不代表产品发布或变更网络配置。
