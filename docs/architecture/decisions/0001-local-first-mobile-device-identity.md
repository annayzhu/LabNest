# 第一阶段账号与跨网接入；手机本地优先，Watch 默认经手机同步

日期：2026-10-22。修订：v1.2。Accepted 表示用户已确认总体方向，不表示账号、跨网、离线或手表转发已经实现。

## 当前决定

1. 数据库与原附件先留在本地 Mac；iPhone 保存受保护的业务工作副本和待同步修改，未来可迁移到常开服务器。
2. 账号、默认工作区、成员关系、会话与全路径后端授权纳入第一阶段，不能只添加登录页面。暂不开放公众注册、订阅或多机构云托管。（v1.2：单人登录与全路由登录要求在 P0 交付；P1 为单一默认工作区，写操作按角色检查；逐查询工作区范围与跨区隔离在按需的 W 阶段。）
3. 电脑在二楼、手机在一楼，两 Wi-Fi 均能上网但不能互访是首要验收场景。优先验证机构允许的私有 HTTPS 接入；不依赖同 Wi-Fi 或让普通用户查询 IP。
4. Watch 默认通过随身 iPhone 交换任务、计时和操作；无需蜂窝套餐、VPN 或独立登录。即使同网也使用手机路径；现有直连受保护兼容，不先建设双通道竞速。
5. P1 同时交付核心现场记录的本地持久化、重启恢复和自动补传；P2 扩展完整首版主要模块。两份任务书共用身份、存储与同步，不各写一套。
6. 用户、工作区、实例、设备和当前实验分别建模。切换网络/实验不改变身份；退出或换账号不串用队列，旧匿名事实不追认为新账号作者。
7. 恢复后以原操作 ID、当前授权和基础版本提交；冲突保留双方。Watch 已传手机不等于已同步服务器。
8. 正常断网可继续已准备内容的操作；全新安装仍需首次可信接入/登录。手机前台恢复自动同步，系统后台调度不保证即时传输。
9. 登录后自动同步获授权目录、正文与常规数据，大附件按需、项目可整包离线；不自动迁到公有云。

## v1.2 补充决定

10. **P0 跨网快路**：先交付 Tailscale 私有 HTTPS（只放行本人设备、只代理 LabNest 端口）、固定地址与全路由登录，使一楼手机可用二楼 LabNest 的现有功能；不等 P1。局域网入口在 P1 手表改经手机转交后再关闭。
11. **P1 单一工作区**：数据模型保留 workspaceId；多工作区隔离与成员邀请在出现第二个工作区或成员时另行实施。
12. **M0 决定离线路线**：比较 App 内打包的 Web 客户端（复用 TypeScript 组件与业务规则）与原生 SwiftUI，用离线新建实验并解析体系等判定用例决定；倾向前者，以免离线规则形成两份实现。
13. **M0 决策关卡**：M0 证据报告交用户决定路线、P1 范围与工期、是否继续；关卡前不写 P1 业务代码。各阶段写明结束时可用的功能。

## 与旧决定的关系

本版替代本 ADR v1.0 及 Q8 的“无账号试用先行、账号后置”顺序，保留首次接入后可离线的原则；Q9 同步范围不变。旧无账号资料与设备队列需要一次性受保护迁移，不能删除。也扩展 `docs/mobile/mobile-app-20261021/MOBILE-APP.md` 的 Q104/Q116，替代 Q107 暂不做账号及 Q109 手表默认直连的目标安排；历史文档不改写成已实施事实。

## 取舍与实施限制

本地业务库、跨网连接、人员授权和版本核对增加了工程工作，但只改善二维码或远程 WKWebView 不能满足跨网断连后重启继续记录。现有编辑器可作为 App 本地资源复用，不能依赖远程页面加载。账号无法让关机的 Mac 实时提供数据，若要此能力仍需常开服务器。

第一阶段先复用 SwiftUI、PostgreSQL、版本化 API 和事务，不引入全系统 CRDT、微服务或消息平台。具体认证库、本地存储和编辑器方案需验证；私有连接需要机构允许和真实两网/真机测试。当前修订仅授权更新规划，不代表产品发布或变更网络配置。
