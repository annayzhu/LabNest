# LabNest 反应配液模块精细化调整

日期：2026-09-16。版本：1.1，纳入本轮四项完整反馈。供本机 Codex 执行。

本文件是此前计算器 UI 任务书的增补。本轮明确替代“常用预设放在计算按钮下方”的旧要求：载入预设、载入示例、恢复草稿均属于计算前的输入准备，应放在输入区。其他已完成要求继续保留。

本文件依据用户反馈制定，尚未核验当前本机代码或实际页面；执行时先定位反应配液模块及其共用组件，再实施和验收，不得把本任务书当作修复完成记录。

## 1. 按操作顺序重新组织界面

默认顺序：载入或填写 → 调整反应参数及组分 → 计算 → 查看结果 → 复制或导出。

| 区域 | 内容和位置 |
| --- | --- |
| 输入区标题行 | “输入”标题旁放常用预设、载入示例、恢复上次草稿；可用紧凑菜单承载选项，不增加常驻说明块 |
| 基本参数 | 反应数、每反应总体积、余量或损耗设置等按实际计算依赖组织；数字与单位紧邻 |
| 组分表 | 组分名称、每反应用量、是否预混等采用紧凑行；添加组分放在表格附近，删除操作在对应行 |
| 分组设置 | 紧邻受其影响的组分和反应数，避免配方与分组设置分散；仅在实际需要时展开高级设置 |
| 加载配液组 | 若该操作用于载入或改变输入分组，放在输入区的配液组标题旁，不能夹在输入与结果之间；执行时核查实际功能。若实为选择查看某个已计算组，应改名为“选择配液组”，放在结果组导航处 |
| 计算操作 | 位于相关输入之后，以“计算”为主要按钮；不要在下面堆放载入入口 |
| 保存预设 | 作为输入区的次要操作，例如预设菜单中的“将当前输入存为预设”；其语义是保存输入配方，不与复制结果混用 |
| 结果区 | 核心汇总 → 分组配方及分装信息；复制、导出贴近结果标题 |
| 表格单位 | 放在受其控制的结果表格上方工具栏，靠近表头；统一表格可只保留一处紧凑“单位：µL”控件，不在结果下方独占一个区块。切换时同步换算数值及表头，不改变输入单位 |
| 低频功能 | 历史记录保留独立入口；离线使用收进“更多”，直接打开单层面板 |

桌面输入与结果并排时，载入入口仍归输入区；窄屏入口允许紧凑换行，不横向溢出，也不要挪到计算之后。

逐项检查模块的其他操作关系：

- 载入后同步更新反应参数、组分、分组及关联字段，不能只更新部分可见字段。
- 修改或载入输入后，旧结果应明确失效；重新计算前不能把旧值作为当前结果复制或导出。
- “恢复上次草稿”仅在存在有效草稿时可用；恢复操作不能先被自动保存的新空白表单覆盖。
- 重置应有清楚的作用范围；与计算保持次要视觉关系，不造成误触。
- 汇总数值只保留必要的一份，减少文字与表格重复列出同一配方。
- 单位、是否预混、组归属和余量含义保留；解释性长文按需展开，不用删掉关键条件来压缩页面。

### 1.1 “独立配液”与“完整结果”合并组织

采用一份主要结果：**配液清单**，按配液组组织。默认页面结构：

1. 结果标题行：复制、导出等操作。
2. 紧凑汇总：独立配液组数量；单组时显示该组预混总量。多组分别标注各组总量，不能用一个未标明含义的合计替代。
3. 表格工具栏：单位；多组时按需提供组选择。
4. 组标题及分装摘要 → 该组组分表，表内保留组分、每反应体积、加入方式和整批用量。组名不再每行重复。
5. “操作步骤”按需展开，呈现实际加液顺序。

“独立配液”是结果的分组方式，不再作为与“完整结果”平行且重复的一整块。若“完整结果”只有同一配方的第二种排列，合并后删除该区块；若确有必要的额外字段，保留为表格的按需展开列或“查看计算明细”，仅展示增量信息，默认不再复制整张表。

单组默认直接展示配方；多组可使用组导航展示选中组，保留明确的组数和“复制全部”入口，不能让未显示的组被误认为不存在。不要给每个组分再套独立大卡片。

### 1.2 “结果说明”“方法与假设”处理

- 删除只重复结果、解释页面操作或泛泛表示“条件成立”的“结果说明”常驻区块。
- 移除主流程中笼统的“方法与假设”面板。执行时逐条阅读现有内容，根据实际用途处理，而不是换标题后原样堆回去。
- 与具体参数有关的解释移到参数旁的帮助入口，例如余量如何计算、哪些组分参与预混。
- 确实用于核对计算的公式和依据，收入结果区单一的“计算依据”入口；用当前输入值解释，不能只展示抽象术语或内部字段名。若无独立信息则不保留入口。
- 影响本次配液的真实问题在相关字段或组内就地显示，例如体积无法满足设置；不让用户展开帮助才知道结果不可用。
- 保留关键数量差异：配制量含实际设置的余量，分装量按孔数计算；必要时用一句具体短注解释，不能删掉后让用户误读。

### 1.3 其他操作关系检查

Codex 应检查当前模块的每个常驻区块和按钮，按“改变输入／展示结果／执行配液／低频帮助”归位。交付时记录实际发现及处理，不得仅调整本文件列出的按钮。

- 明确全局参数与单组参数的作用范围，组内动作只作用于该组。
- 输入单位属于输入字段；结果表格单位只控制展示。复制、导出使用同一份有效结果，并明确每个数值的单位。
- 若选择了结果组，复制按钮清楚区分“复制当前组”和“复制全部”；默认全量复制仍包含全部组。
- 计算前的空结果区保持简洁，不常驻完整结果、操作详情和方法说明的空壳。
- 输入后的键盘访问顺序与视觉顺序一致；菜单不遮住关键字段，不用多层折叠菜单承载高频操作。

## 2. 手机和窄窗口计算后切换结果

以页面实际是否进入“输入／结果”标签布局为判断依据，不按设备名称或手机 User-Agent 判断。

1. 用户点击计算，校验通过且新结果生成成功后，自动激活“结果”标签。
2. 将结果区顶部置于可见位置；处理页面或局部滚动容器及固定标题栏的遮挡，避免切换后仍停在旧滚动位置。
3. 校验失败或计算失败时保留在输入标签，定位相应错误字段，保留全部已填内容。
4. 桌面宽屏仍保持输入与结果并排，不额外跳页。
5. 仅用户触发并成功完成计算时自动切换；载入预设、恢复草稿、切换窗口尺寸不应自动触发结果跳转。
6. 返回输入标签后保留原输入；连续修改和计算应展示最新结果。
7. 标签状态、可见面板与辅助技术可读取的选中状态保持一致；尊重系统减少动态效果设置。

## 3. 复制结果格式

中文界面复制纯文本，删除反复出现的“组分”“是否预混”“是 / Yes”“整批配制”“配液组”等字段前缀。使用真实换行和普通下划线，不输出 Markdown 转义字符。

单组示例的目标文本如下，数值是用户提供的验收样例：

```text
独立配液组: 1
各组预混总量（分别配制）: 237.6 µL

G_mix: 预混液: 9 µL × 24
Master mix每反应: 5 µL; 预混; 整批: 132 µL;
H2O每反应: 3.6 µL; 预混; 整批: 95.04 µL;
GAPDH-F每反应: 0.2 µL; 预混; 整批: 5.28 µL;
GAPDH-R每反应: 0.2 µL; 预混; 整批: 5.28 µL;
```

边界规则：

- 单组无需在每个组分后重复组名；组名和分装摘要放在组分清单之前，不再放到末尾。
- 多组按组分别输出：组名及分装摘要、该组预混总量、该组组分。组之间空一行。每个组只在标题标识一次，不把不同组混成无法区分的一串组分，也不把多组总和误称为每组配制量。
- 非预混组分明确写“单独加入”，不能统一写成“预混”。整批量的含义必须与现有计算结果一致，不得直接套用预混液的损耗规则。
- “每反应”“整批”和分装体积分别使用相应计算字段；复制功能只格式化已有结果，不另写一套计算公式。
- 样例中 237.6 µL 为预混配制量，9 µL × 24 为分装需求，二者不应为了文字一致而强行改成相等；按实际余量设置计算。
- 数字去掉无意义尾零，保留既有有效精度，不出现浮点长尾。每个体积都带单位；当前语言仅显示一种语言。
- 剪贴板写入成功后才反馈“已复制”，失败时允许重试。

## 4. 操作详情改为清晰的“操作步骤”

按用户指定顺序呈现，界面默认可折叠，展开后不混入来源重复标签或双语片段。组标题采用规范用词“配制”。单组目标示例：

```text
1. G_mix配制
2. Master mix: 132 µL → G_mix
3. H2O: 95.04 µL → G_mix
4. GAPDH-F: 5.28 µL → G_mix
5. GAPDH-R: 5.28 µL → G_mix
6. G_mix预混液: 9 µL × 24 孔加样
```

- 一步只讲一个动作，试剂名称、用量、去向之间保留清楚的间隔；禁止出现“µLMaster mix”这样的连字。
- 不再显示“G_mix · Master mix”后又重复“Master mix → G_mix”的双重描述。
- 最后一步明确从已配制预混液向反应孔分装，不再写成“已配制混合液 → G_mix”。
- 多组各自显示组标题、组分加液、分装步骤，按照组逐一完成，不交叉混排。
- 非预混试剂作为单独加入的步骤，按实际计算模型提供每孔体积和孔数，不能被写成加入预混管，也不能遗漏。
- 样例最后一步使用“24 孔加样”。其他模式如明确使用反应管，使用实际容器名称；未提供容器类型时可写“24 个反应”，不虚构具体孔位编号。
- 配液清单用于核对用量，操作步骤用于逐步操作，默认不同时展开两套重复体积明细；两者必须来自同一计算结果。
- 如现有功能支持复制操作步骤，复制文本应与此显示一致。

## 5. 验收清单

- [ ] 桌面和窄屏中，预设、示例、恢复草稿均在输入区，位于计算之前。
- [ ] 组分添加、删除、分组设置与其作用对象相邻；复制、导出位于结果区。
- [ ] 预设和草稿完整恢复关联输入，不保留与新输入不一致的有效旧结果。
- [ ] 手机宽度与桌面缩窄后分别计算成功，均自动进入结果标签且结果顶部可见。
- [ ] 输入错误时不切换结果，定位问题字段且不丢失输入。
- [ ] 宽屏计算后保持并排布局；缩放、载入或恢复本身不抢切标签。
- [ ] 从结果返回输入，修改后再计算，展示及复制的都是最新结果。
- [ ] 单组样例复制到纯文本编辑器，与上述格式一致，无反斜杠和中英重复标签。
- [ ] 多组、同名组分跨组、非预混组分均能明确区分，不改变原计算结果。
- [ ] 样例各组分整批量合计为 237.6 µL；分装仍为 9 µL × 24，余量语义不丢失。
- [ ] “加载配液组”根据实际作用移入输入分组区，或改为结果区的“选择配液组”，不夹在输入与结果之间。
- [ ] 表格单位位于对应表格上方，切换后体积与单位同步更新，不改变输入参数或数量含义。
- [ ] “独立配液”与“完整结果”合并为一份分组配液清单，单组和多组都无重复常驻表格。
- [ ] “结果说明”冗余区块已删除；“方法与假设”按实际内容分流，关键错误仍能直接看见。
- [ ] 复制文本中组名及分装摘要在组分之前，符合本轮最新样例。
- [ ] 操作步骤与六行样例一致，名称不重复、字符不粘连、末步明确向孔加样。
- [ ] 多组与单独加入试剂的操作步骤作用对象正确，复制全部不遗漏未选中组。

交付要求：列明修改文件和验证结果；提供宽屏、窄屏输入区及计算后结果区截图，以及单组和多组实际复制文本、操作步骤文本；列出移除或合并的重复区块及保留的关键计算信息。共用组件调整应验证其他使用方未出现载入入口错位、错误自动切换或复制格式异常。未实际验证的场景明确列出。
