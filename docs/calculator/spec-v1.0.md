## 1. 产品目标、边界与优先级

### 1.1 核心目标

- 找得到：常用计算从 Today 最多两次点击进入可输入界面。
- 填得少：只展示当前模式所需字段，用户无需手工计算换算系数。
- 算得对：单位、分子类型、体积关系及方法适用条件明确。
- 看得懂：结果优先用“取多少、补多少、分几孔”的操作语言表达。
- 能复用：支持个人配方、最近任务、批量计算和草稿恢复。
- 可追溯：正式记录保存当时输入、单位、结果、假设与方法版本。
- 好维护：复用核心计算和组件，避免为每个场景复制一份公式。

### 1.2 服务范围

以细胞培养、分子生物学、蛋白实验和基础微生物实验为主要场景。完整覆盖原有 31 个模块的可达性，并补充复溶、批量归一化、可执行梯度移液表等高价值能力。

本轮不新增通用 AI 聊天入口，不建设新的试剂采购平台或完整生物信息分析平台，不重做全站导航与品牌皮肤。计时器使用已有实验执行体系，不在 Calculator 内创建另一套 Timer。

拟合类功能保留，进入适合数据分析的界面；仍可通过 Calculator 搜索、收藏和旧链接访问。

### 1.3 需求等级

- **P0**：影响结果正确性、可操作性、数据完整性；任何涉及该计算的交付必须先满足。
- **P1**：本轮完整重构的核心功能，可按阶段上线。
- **P2**：可选增强，不阻断核心交付；不得冒充已完成能力。

原有不可行配方、单位误读等 P0 问题不能因为所属专业功能安排在后期而长期暴露为“有效结果”；必要时先增加阻止错误使用的明确校验。

## 3. 信息架构与访问路径

### 3.1 Calculator 首屏

页面名称为“实验计算 / Lab Calculations”。不以“31 个模块”“浏览器本地”等实现信息作为主介绍。

| 顺序 | 内容 | 规则 |

2. 称量配液

### 3.2 Today 与实验内入口

- Today 保留“计算”入口，允许展示最多三个用户固定工具；不能为此挤占进行中实验的核心区域。
- Today → 固定工具：一次点击；Today → 实验计算 → 常用任务：两次点击。
- 实验步骤内提供“计算”。带入实验、步骤以及明确选中的孔板和孔数，并可在计算前查看或调整。
- 有多个活动实验时，不静默绑定任意一个。独立打开的计算器无需强制选择实验。
- 桌面实验内使用侧栏/抽屉；手机使用完整计算页面。返回时恢复原页面及当前步骤位置。
- 支持深链接与浏览器后退。切换工具前保留各自草稿，避免丢失输入。

## 5. 所有计算器共用的交互规则

### 5.1 页面布局

统一为：任务与模式 → 必要输入 → 主要操作结果。公式、方法版本、来源、假设细节、历史和高级选项默认折叠。

- 简单公式在输入完整且有效后即时更新；保留键盘提交能力。
- 批量导入、图像识别、拟合分析使用明确的“计算/分析”动作。
- 求解项是只读输出，不要求用户填入或通过旧默认值绕过校验。
- 切换模式后，无关字段不参与校验；可保留草稿但不得影响当前结果。
- 修改输入后立即撤销旧结果的“可保存/可应用”状态。不得在新输入无效时继续展示旧数值为当前结果。
- 首次打开不以示例值产生真实结果；提供“载入示例”，并显著标记示例状态。
- 记住单位和布局偏好；关键样本参数通过“恢复上次草稿”明确恢复，不静默绑定上次样本。

### 5.2 数字输入

- 编辑阶段保留字符串，允许清空、小数未输入完成等中间状态，不能把空字符串变成0或NaN后污染页面。
- 支持标准科学计数法 `1e6`；细胞数允许友好的指数输入辅助。
- 标量字段按当前locale解析小数符号；混合分隔符等有歧义输入必须要求修正。批量粘贴使用明确的列/行解析规则，不把CSV逗号当小数点猜测。
- 计数、孔数和反应数要求非负或正整数，具体按字段定义；不允许静默向下取整。
- 小数步长不统一锁定0.01，避免阻止合法的低浓度输入。

### 5.3 结果状态

| 状态 | 行为 |
| --- | --- |
| 输入未完成 | 显示待填写字段，不显示有效结果 |
| 条件成立 | 操作摘要＋必要组分表；允许复制/记录 |
| 依赖估算 | 显示估算标签、假设和参数来源；记录保留这些信息 |
| 条件不成立 | 指向具体字段并说明原因；禁止作为有效配方应用 |

错误以中文/英文对应字段名表达，不向普通用户暴露内部key、堆栈或未经翻译的工程异常。

主要动作：复制操作步骤、记入实验、保存为常用配方。无实验上下文时可以保存计算记录或选择关联实验；不强制进入实验管理流程。

### 5.4 手机与可访问性

- 输入区单列，数值与单位同一行；主要触控区域至少44×44 CSS px。
- 支持窄屏、系统字体放大、键盘弹出、横竖屏切换。
- 不用固定底栏遮挡输入或结果；有底栏时预留安全区域和键盘空间。
- 长表支持逐样本卡片或受控横向滚动，页面本身不得横向溢出。
- 颜色不是唯一状态信号。错误、估算、有效均有文字。
- 抽屉/对话框具有焦点管理、Escape、关闭后焦点恢复；动态计算不会抢走输入焦点。
- 首屏采用既有主题token、字体及图标；不重新创建视觉主题，不用大幅装饰插图占用空间。

## 6. 统一单位与数值合同（P0）

### 6.1 数量必须包含数值和单位

不得用独立的文字标签代表计算单位。输入、结果、历史、配方及上下文传递中的数量都必须有明确单位和量纲。

推荐的概念结构如下；这不是现成仓库API，实施时按既有类型整合：

```ts
type Quantity = {
  value: number;
  unit: string;       // 来自受控单位注册表
  dimension: string;  // 质量、体积、摩尔浓度等
};
```

内部统一到各量纲的规范单位再计算，输出转换与格式化最后进行。不得在中间步骤按显示位数舍入，不把小量一律四舍五入成0。

### 6.2 支持范围

| 量纲/类型 | 基础支持 |
| --- | --- |
| 质量 | g、mg、μg、ng、pg；可按需要补kg |
| 体积 | L、mL、μL、nL |
| 物质的量 | mol、mmol、μmol、nmol、pmol、fmol |
| 摩尔浓度 | mol/L、M、mM、μM、nM、pM |
| 质量浓度 | 常用g/L、mg/mL、μg/mL、ng/mL、μg/μL、ng/μL |
| 细胞浓度 | cells/mL、cells/μL；以明确的活/总细胞语义使用 |
| 长度与面积 | cm、mm、m；cm²、mm²等 |
| 时间 | s、min、h、day |
| 温度 | °C、°F、K；使用带偏移的转换 |
| 离心 | rpm、×g；必须结合半径 |
| 百分浓度 | % w/v、% v/v、% w/w，彼此不当作同一量纲 |
| 活性或滴度 | U/mL、IU/mL、TU/mL、PFU/mL、TCID50/mL、VG/mL等明确类型 |

`uL`、`μL`、`µL`等常用别名可归一化；大小写不能被任意消除，例如M与m不是同一单位。

### 6.3 切换与跨量纲转换

- `1 mL`改显示为`μL`应成为`1000 μL`；切换显示单位不能改变物理量。
- 每个输入独立选单位；下拉仅展示适用于该字段的单位。
- 摩尔浓度↔质量浓度需要相应化学形式的分子量；水合物、盐形式和纯度必须明确。不得仅凭简称自动选择。
- 活性↔质量需要对应产品/批次的比活性；不凭通用常数换算。
- PFU、TU、IU、TCID50、VG不能假设等价。
- rpm↔×g需要转子半径，不能当作简单倍率换算。
- 密度仅在跨质量/体积或指定浓度类型转换时显示；无必要时不要增加字段。
- 百分数是带定义的浓度或比例，不能只保存一个裸`%`。

### 6.4 数值精度与移液显示

保留完整计算值，显示适当有效数字。若用户按移液步进舍入，保留“理论值”和“实际配制值”，按实际值回算浓度偏差；不得静默改变方案。移液量低于用户配置的设备下限时提示，不能宣称所有移液器共有某个下限。

## 7. 核心计算规范

### 7.1 稀释与加药

统一在兼容浓度单位下计算。

**模式A：配至指定最终体积**

`Vstock = Ctarget × Vfinal / Cstock`

`Vdiluent = Vfinal − Vstock`

要求`Cstock > 0`、`Vfinal > 0`、`0 ≤ Ctarget ≤ Cstock`。输出“取母液…，补充稀释液至总体积…”。稀释液差值采用体积可加和近似，假设可展开。

**模式B：向已有液体中加入母液**

若已有液体含同一溶质：

`Vadd = (Ctarget − Cinitial) × Vinitial / (Cstock − Ctarget)`

默认已有液体不含该溶质，`Cinitial = 0`；使用明确模式显示默认含义。正向加入母液提高浓度时，要求`Cstock > Ctarget ≥ Cinitial`；达到目标时可返回0加入量，其他无解条件说明原因。

输出加入量、加入后总体积与最终浓度；不得使用模式A替代。

**模式C：倍液**

允许`10×→1×`及`10×→2×`等：`Vstock = targetFold / stockFold × Vfinal`。倍数必须为正，目标不高于母液倍数。

**模式D：比例**

- “1:N稀释（母液占最终体积1/N）”：`Vstock = Vfinal/N`。
- “母液:稀释液 = a:b”：`Vstock = Vfinal × a/(a+b)`。
- 两者明确分开，不能让用户猜1:10是十倍还是十一倍稀释。

加药高级选项可计算载体终比例：将各来源载体体积分数乘以加入体积求和，再除最终体积。用户设定上限，无通用生物学安全阈值。

### 7.2 浓度梯度与连续稀释

支持等倍梯度、线性目标序列、自定义目标浓度。线性或自定义梯度不一定适合固定比例连续转移；允许输出从母液分别配制的并行方案。

标准等倍模式：

- `C0`为第一管目标浓度，第一管计入浓度点数N。
- `Ci = C0 / f^i`，`i = 0…N−1`，`f > 1`。
- 明确第一管是已备好的起始液，还是需要从更浓母液制备；不能给第一管套用与后续管相同的稀释步骤。
- 零浓度/载体对照独立于对数序列。

必须支持“混匀时体积”和“转移后所需保留体积”的区别。采用每管相同混匀体积V时，后续转移量为`V/f`，前一管剩余`V−V/f`；不能把V同时标成转移后保留量。

若每管需要最终保留Ri，可从最后一管向前计算：最后管准备`PN−1 = RN−1`；对于前一管，向下一管提供`Ti = Pi+1/f`，因此`Pi = Ri + Ti`。对第i>0管，来自前管的量为`Pi/f`，稀释液为`Pi−Pi/f`。第一管单独确定制备方式。算法可采用其他经过验证的方案，但必须逐管满足浓度和体积守恒。

输出列：管/孔编号、目标浓度、来源、取液量、加稀释液量、混匀体积、转移量、剩余量、所需用量、是否足够。移液死体积/余量要在明确的需求节点计入一次，不递归重复加百分比。

### 7.3 称量与配液

`m = C × V × MW`（规范单位为g、mol/L、L、g/mol）。反向求浓度和体积时仅校验已知量。

- 纯度修正仅在用户明确纯度定义和适用性时使用；质量分数p下所需称量为`m/p`。
- w/v：x%表示每100 mL最终溶液有x g溶质。
- v/v：x%表示每100 mL最终溶液有x mL指定液体组分。
- w/w：x%表示每100 g最终混合物有x g溶质；目标输入为质量，转换成体积需密度。
- 固体配液写“溶解后定容至…”，不能写成“加入该体积溶剂即可”。
- 分子量手工录入为基础能力。化学式解析/联网试剂查询为P2，必须带来源并由用户确认具体化学形式。

### 7.4 试剂复溶

支持：已知质量→目标质量浓度；已知物质的量→目标摩尔浓度；已知质量＋MW→目标摩尔浓度。

结果给出达到目标的最终溶液体积；对冻干试剂可按产品说明书使用复溶体积近似，并保留说明。寡核苷酸优先使用COA提供的量或MW；修饰寡核苷酸不能用普通碱基长度模型当精确值。

不自动替试剂选择溶剂或推荐储存条件；若模板含这些信息，需要可追溯产品来源。

### 7.5 配方配液

使用结构化组分表：名称、输入方式（称量/原液体积/目标浓度）、数值、单位、母液信息及备注。

- 旧配方支持按基准体积线性缩放。
- 新配方明确是“配成最终体积”还是“向已有基础液添加”；例如“500 mL基础培养基再加FBS”和“配成500 mL完全培养基”不同。
- 基础溶剂可设为定容补足行，最多一个；若其他组分已经超过目标，返回不可行。
- 比例混合配方的各比例应满足定义，不把超过100%的配方截断处理。
- 自定义配方可以保存；内置配方具有来源、版本、适用条件，不能把演示配方作为完整实验SOP。

### 7.6 细胞计数、铺板、传代和冻存

计数输入路径：直接录入活细胞浓度；总细胞浓度＋活率；或计数板活/死细胞数。三条路径互斥，防止重复乘活率。

标准计数板的大方格体积对应`10⁻⁴ mL`时，浓度为“平均每大方格细胞数×稀释倍数×10⁴”。该系数依赖计数区面积和深度；非标准区域要明确选择或输入几何参数。

常规铺板：

`Nrequired = wells × cellsPerWell × (1 + overage)`

`Vfinal = wells × volumePerWell × (1 + overage)`

`Vstock = Nrequired / viableCellConcentration`

`Vmedium = Vfinal − Vstock`

孔数来自用户选择；若来自已选择孔位，不能再乘一次整板孔数。余量仅用于总制备量，每孔目标保持不变。Vmedium<0时返回浓度不足。

3D铺板：细胞原液体积必须容纳于指定细胞悬液分量；超过时阻止方案，不把负培养基量改成0。凝胶比例不代表任何材料的普适推荐浓度。

传代：按面积换算需来源容器与目标容器面积；不同容器不能仅按份数预测汇合度。增长时间注明倍增时间、指数增长假设及未建模的贴壁延迟、密度效应；不能作为保证。

冻存：输出整管数、剩余细胞和实际配液量。配方比例之和不得超过100%；不同配方可以保存，默认示例不作为所有细胞适用的建议。

### 7.7 反应配液与转染

每行含组分名、母液浓度（可选）、目标浓度或固定用量、是否预混、分组信息。

- 基本总反应数为明确的样本反应数与对照反应数之和。重复数计入何处必须可见，不能重复相乘。
- 余量选择“百分比”或“额外反应数”，默认互斥；如支持组合必须明确，首期不需要组合。
- 单反应目标总体积、全部组分体积、每次分装预混体积和样本单独加样体积必须对应。
- 补水为总体积减去所有计入组分；负值返回不可行。
- 不同样本的DNA/RNA模板不能因为名字相同而加入同一预混池。
- 不同引物/探针/处理组若需不同预混，分成不同配液组；不可强行汇总。

转染专用模板至少纳入核酸量、核酸母液浓度、试剂用量规则、复合物体积及孔数。`VnucleicAcid = mass/concentration`必须扣入总量。RNA按摩尔量输入时必须有正确转换条件。需要两管混合的实验模板分别显示两管；不得对所有转染方法固定推荐某品牌试剂或稀释液。

### 7.8 批量浓度归一化

支持粘贴样本ID、原浓度及可用体积（可选），统一目标浓度与最终体积。逐行应用稀释规则。

- 保留样本ID、行顺序、原值与单位。
- 识别重复ID并提示处理，不能静默合并。
- 浓度低于目标、样品不足、缺失值、非法单位分别标记。
- 合法行可计算；无效行保留并说明，导出不能把无效量写为0。
- 批量导出加列标识可行性；复制纯移液表前确认是否排除无效行。

### 7.9 WB上样

`Vsample = targetProteinMass / sampleConcentration`

`Vbuffer = Vfinal / bufferFold`（目标为1×时）

`Vwater = Vfinal − Vsample − Vbuffer − VotherComponents`

若Buffer本身已含还原剂，不能重复加入独立还原剂行。支持批量样本，逐行检查可行性，显示浓度不足/总量超限。允许用户调整目标质量或总体积，不替用户静默改变实验条件。

### 7.10 核酸、设备及专业功能

- DNA/RNA换算：区分dsDNA、ssDNA、RNA；长度模型是估算，说明所用每碱基/碱基对MW系数。有COA/序列精确模型时保留来源，不能混用。
- 连接反应：`insertMass = vectorMass × insertLength/vectorLength × insert:vectorMolarRatio`；明确比值方向。
- Tm：不静默删除简并碱基；保留原序列并提示不支持或使用经过验证的方法。显示所用方法及盐条件，不能把简易估算包装为完整热力学分析。
- 离心：`RCF = 1.118×10⁻⁵ × r(cm) × rpm²`；支持反向求rpm，半径可保存并注明最大/平均等来源类型。不得凭转子名字猜半径。
- OD600：需要适用的经验关系和读数条件；不要把OD普遍等价为CFU或活细胞量。
- CFU/PFU：稀释度是原样在涂布样中的分数；涂板体积先转换到mL。零菌落不能报告log10值为0，应按所用方法处理未检出/检测限。
- 图像辅助计数：显示人工增减与最终确认；未确认结果不能直接记为正式计数。
- MOI：单位与滴度方法匹配；泊松概率仅在模型适用前提下作理论估算，不能表示确定感染率。
- TCID50：基线的“首次≤50%稀释点”只能称近似终点。正式滴度算法需选定方法、来源及验证，不能直接沿用近似值并改名。

## 8. 拟合分析的迁移与科学边界

IC50/EC50、ELISA及BCA/Bradford仍属于可访问功能，但使用分析工作区。已有分析模块能复用则复用，不另建第三套拟合系统。

要求：

- 支持结构化数据输入、单位、空白/对照、重复值和稀释倍数；非法行不得静默丢弃。
- 曲线方向、反应值定义、拟合模型必须一致。残存反应下降与抑制百分比上升不能仅凭“抑制”一词混淆。
- 4PL中点不自动等同于所有定义的绝对50%效应浓度；报告定义和归一化方式。
- 显示拟合曲线、模型、参数、是否收敛和有效范围；仅有R²不能代表拟合可靠。
- 超过标准曲线范围、缺乏平台、不可反算和不足以估计的区间必须提示。
- 标准曲线的量程判断基于实际被测稀释样本的反算浓度；再乘稀释因子得到原样浓度。不能拿原样浓度与稀释样本标准范围直接比较。
- 方法不支持的零浓度、缺失或非有限值不得悄悄过滤后给出看似正常报告。
- 合适的置信区间/不确定性方法若尚未实现，标注未提供，不编造。新增算法另给来源与独立基准。
- 迁移不要求本轮实现完整统计软件；无法可靠提供的专业结果应明确受限，不能以“更漂亮的结果页”掩盖限制。
