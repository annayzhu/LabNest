## 2. SAFE-01：失败时保护旧数据

### 2.1 必须成立的不变量

- 只有“成功读取并验证当前数据”或“确认原存储不存在”的状态，才允许正常持久化。
- 读取失败、解析失败、未知版本、迁移失败、备份失败或备份完整性无法确认时，进入受保护状态。
- **返回空界面状态不等于确认存储为空，不得由此开启自动保存。**
- 暂时恢复存储写能力、切换工具、组件重挂载、打开 Appearance、改变收藏或恢复自动保存，都不能解除保护。
- 不要只在按钮禁用：持久化入口自身必须拒绝覆盖，所有调用方共用该规则。
- 原始数据按原字节保留。迁移需要的备份不能只凭key存在视为可靠；必须与待迁移原文一致，发现冲突使用新标识或阻断。
- 本地历史保护与 Appearance 偏好分别存储，设置变化不得重新序列化 Calculator 历史。

### 2.2 建议状态合同

以下为设计概念，不是声称仓库已有的接口：

```ts
type StorageReadState<T> =
  | { status: 'ready'; value: T; source: 'empty' | 'current' | 'migrated'; canPersist: true }
  | { status: 'protected'; value: T | null; canPersist: false;
      reason: 'read-failed' | 'parse-failed' | 'backup-failed' | 'migration-failed' | 'unsupported-version' };
```

内部可使用不同实现，但不得依赖一个未经协调的模块级布尔值，让一次新的读取无条件解除另一次失败设定的保护。保存时还应确认自己基于的源数据未被其他标签页修改；发现不同版本时重新读取／合并，不能静默以旧内存状态覆盖新历史。

### 2.3 用户恢复路径

1. 提示“已有计算数据暂时无法安全保存，原数据已保留”，不要误报“没有历史”。
2. 可继续当前页面的临时计算；明确尚未持久保存。若原文可读，允许下载原始备份；不能把空内容导出为成功备份。
3. 提供“重试读取与恢复”。重试必须重新完成读取、版本判断、备份及迁移验证后，才能进入可写状态。
4. 恢复时保留历史和当前临时草稿的区别；不能把受保护期间产生的空历史合并为“删除所有旧记录”。
5. 常规恢复不要求清空历史。若已有显式重置功能，保留独立确认和影响说明；禁止自动调用。

### 2.4 必测故障

| 编号 | 故障注入 | 预期 |
| --- | --- | --- |
| S01 | 有旧历史；备份 `setItem` 抛出配额不足，随后普通写入恢复 | save仍拒绝覆盖；原始历史字节不变 |
| S02 | 首次 `getItem` 抛错，随后保存被调用 | 不能将空状态写入原key |
| S03 | 非法JSON或未知高版本 | 保护写入；不降级覆盖；可恢复原文 |
| S04 | 迁移中途失败 | 原始历史与已有备份保留 |
| S05 | 存储正常、原key确实不存在 | 正常首次保存，不误锁新用户 |
| S06 | 用户重试，全部保护前置条件成功 | 旧历史完整恢复，后续新记录正常追加 |
| S07 | 保护状态下切换图标／字体、工具或触发防抖保存 | 原历史不变 |
| S08 | 另一个标签页修改了同一历史，当前页仍持有旧状态 | 检测变化并保留新数据，不静默回滚 |

## 3. WB-01：配液表必须可完整执行

### 3.1 结果结构

每个有效样本同时显示／导出：样本ID、原蛋白浓度及单位、目标蛋白量、样品体积、Loading Buffer体积、独立还原剂体积、其他独立组分、补液体积、总量及有效性。

- 独立还原剂须有名称、添加方式和单位；“最终体积的5%”与“目标浓度为5%”不是同一输入定义。后者须提供原液浓度等必要条件。
- Buffer已含还原剂时，独立添加量为0，明确“已包含于Buffer”；若尚未确认，要求选择，不能同时计入两次。
- 每个非零组分必须出现在操作表。不能只从水量扣除，却不告诉用户要加入什么。
- 不得只修UI列而遗漏通用结果结构、CSV/XLSX、剪贴板及实验快照。
- 无效行保持样本ID和原因，不能以0替代无法计算值；有效行不能被邻行错误污染。

### 3.2 独立合成例题

下面是验证算术的合成条件，不是推荐实验配方。

| 条件 | 数值 |
| --- | --- |
| 蛋白浓度 | 2 μg/μL |
| 目标蛋白量 | 20 μg |
| 最终体积 | 20 μL |
| Loading Buffer | 4×，最终1× |
| 独立还原剂添加量 | 最终体积的5% v/v，即1 μL指定原液 |

预期：样品10 μL＋Buffer 5 μL＋还原剂1 μL＋水4 μL＝20 μL。这里没有推定还原剂有效成分终浓度。

数值体积平衡使用规范单位，建议误差界为 `max(1e-9 μL, |Vfinal| × 1e-9)`；界限仅处理浮点误差，不用于容忍缺失组分。显示舍入不得掩盖理论和实际配制差别。

必测：独立还原剂0和非0；Buffer内含还原剂；多行混合有效／无效；组分和超过总体积；单位改变；所有输出渠道回读同样组分。旧记录若已缺少还原剂列，只能标为“不完整旧快照”；重算产生新记录，不能伪造原记录。

## 4. PIP-01：移液检查覆盖所有真实操作

### 4.1 检查依据

从结构化操作量提取待执行移液动作，转换为统一体积单位后比较设备下限。不能依赖 `unit === 'µL'`、字段名以 `Ul` 结尾或对显示文字做正则推断。

建议为操作量提供 `quantity`、`role`、组分和样本/步骤关联。必须区分：

- 实际吸取／加液／分装量：需要检查。
- 总体积、剩余体积、库存可用量等汇总：不能一概当作一次移液动作。
- 多孔每孔分装量与整批制备量：分别评估，不能只检查总量。

覆盖细胞铺板、稀释加药、梯度转移、Master Mix、转染、归一化、WB以及所有生成操作量的模板。使用 v1.0 单位别名规则；输入与输出单位选择不影响检测结论。

### 4.2 警告及舍入

- 下限是用户／设备配置，不新增“所有实验通用1 μL”的默认科学结论。
- `0 < 实际操作量 < 下限`显示警告；0表示不需要加入时不触发低量警告。负值和非有限值为计算错误。
- 警告写出样本／组分、实际量和下限，如“细胞悬液：0.1 μL，低于所设1 μL下限”。
- 给出“调整制备规模，或评估中间液方案”等操作方向；只有实现并验证守恒的工具才可一键应用中间液。
- 理论量和用户明确启用步进后的实际量都需检查；非零理论量舍入为0时不能继续显示为正常可执行方案。
- 不支持步进的模式显式提示未应用，不静默声称完成舍入。

### 4.3 例题

活细胞浓度 `1e6 cells/mL`，1孔，每孔100个细胞，每孔总体积100 μL，余量0：细胞原液应为 `0.0001 mL = 0.1 μL = 100 nL`。设备下限1 μL时，上述三种输出都必须提示；培养基99.9 μL。

还要测试恰好等于下限不触发“低于”；无下限不捏造阈值；批量中只一行低于下限；不把剩余量误判成加样量；切换单位后无警告丢失／重复。

## 5. UNIT-01／COPY-01：结果展示与输出一致

### 5.1 结果单位

- 可转换的数值结果提供邻近单位下拉；批量表可按同一量纲列统一切换，避免每个格子都放控件。
- 量纲不兼容的单位不出现；无换算意义的状态、计数和比例不要显示伪下拉。
- 切换 `2 μL ↔ 0.002 mL ↔ 2000 nL`只改变显示，不重新求解、不改变输入、理论值、余量或警告。
- 从未舍入规范值转换，不从上一轮已格式化字符串继续换算；20次往返不产生累积漂移。
- 非零小量必要时使用科学计数法，不能显示为0。无效输入撤销旧结果有效状态。
- 当前草稿可保存显示偏好；旧快照保存当时单位。查看旧记录时如临时转换需标识，不改写原快照。

### 5.2 统一输出合同

一次有效计算产生一份结果对象；页面、复制、下载和记入实验均从它派生，不在各按钮中重新计算。至少保留：工具／模式、方法版本、输入与单位、结果与组分、状态、警告、关键假设、理论与实际配制差别及已有实验关联。

默认“复制操作步骤”顺序：任务 → 配制表／步骤 → 警告 → 关键假设。日常UI不常驻方法版本等工程信息；正式记录保留可追溯元数据。

- 有警告时不能复制成看起来无条件有效的配方。
- CSV为自包含结构：每行附状态和相关警告，公共假设可作为明确列重复；不使用破坏表结构的任意前置文字。
- XLSX保留组分表及说明页，不能只导出可见数值列。
- 正式快照与实验写入保留结构化警告，即使界面折叠帮助仍完整。
- 剪贴板失败给出手动复制路径，不提前显示成功。
- 仅改变配色、字体、icon不能生成新计算记录、改数值或触发重新同步。

## 6. HOME-01：半屏常用任务区

### 6.1 明确“全部”和“半屏”的含义

**默认六个固定任务全部可见，使用手机3列×2行，不是把31个工具全部塞入半屏。** 默认顺序不变：稀释与加药、称量配液、细胞铺板、反应配液、WB上样、离心换算。

- 六个首页槽位可替换、排序；不能靠横向滑动、轮播或内部滚动才能看到第六项。
- 既有收藏超过六项时保持原数据、原顺序；前六项显示于常用区，其余进入“全部收藏（N）”。不删多余收藏。
- 全部工具及所有可收藏工具仍可搜索直达。用户可以把复溶等工具换入六个槽位。
- 已主动设置少于六项或清空收藏的用户，不应被默认值覆盖；默认六项只用于未配置状态。

### 6.2 尺寸与布局合同

| 场景 | 默认布局 | 设计预算 |
| --- | --- | --- |
| 手机320–479px | 3列×2行 | 格间距6–8px；整格触控至少44×44px；常规格高约68–76px |
| 小高度手机320×568 | 仍为3列×2行 | 可收紧到约60–64px格高；icon约28–32px，保持文字可读 |
| 较宽手机／小平板 | 优先3列×2行 | 不因略变宽突然形成4＋2的松散布局 |
| 桌面内容区足够宽 | 6列×1行 | 不使用拉满宽度的大描述卡；不足则3列×2行 |

图标通常32–36px，文字13–14px，最多两行；名称与icon共同组成一个链接／按钮，避免嵌套交互控件。英文提供真正可理解的短标签，例如“Dilution”“Solutions”“Seeding”“Reaction mix”“WB loading”“Centrifuge”，不依靠省略号隐藏区分信息。

不要在每格常驻说明、版本、分类徽章或收藏按钮。编辑常用项从标题旁“编辑”统一进入；提供按钮式移动顺序，不要求拖动。

首屏上方只保留必要导航、短标题和搜索框；压缩其间距，移除大段介绍和装饰Banner。最近使用、全部工具、配方和历史放在常用区后。

### 6.3 可测的半屏定义

在首屏滚动位置0、默认字体及默认界面缩放、键盘收起、无临时弹层条件下：

`commonTasks.getBoundingClientRect().bottom - visualViewport.offsetTop <= visualViewport.height × 0.5 + 2 CSS px`

不支持VisualViewport时以 `window.innerHeight` 和对应视口坐标测量。测量包括页面顶部导航、标题和搜索所占高度；不能仅证明常用区自身高度小于半屏。测试容器必须是包括标题及六个格子的实际区域，不可用透明占位节点作弊。

至少在320×568、360×640、390×844 CSS px验证；每个入口自身可见、没有遮挡，均满足触控面积。390×844底界目标≤422px，360×640≤320px，320×568≤284px，允许上述2px布局容差。

字体放大、浏览器200%缩放、横屏和软键盘打开时，以可读、可点击、可滚动为优先，允许超过半屏；不得通过隐藏工具、缩小点击区域或截断文字满足几何指标。异常恢复提示存在时也可超出半屏，且必须优先完整显示恢复信息；单独验证此状态。

### 6.4 Today入口

Calculator 首页是六个常用入口的主展示位置。Today继续保留通用“计算”入口和既有最多三个固定任务快捷方式，复用同一icon映射。不得新增一套独立收藏排序。Today→已固定工具1次点击；Today→计算→常用任务最多2次点击进入可输入表单。

### 8.3 Image Gen 生产流程

1. 每个图案单独生成，一项一个文件；保持同一提示词模板、主体比例和风格参考。
2. 真透明背景，无文字、无品牌、无水印、无卡片背景、无人物表情；低饱和、弱装饰、高辨识度。
3. 源图建议512×512或更高方形；主体占画布约70–80%，留出完整边缘。根据工具实际支持能力生成，不虚构尺寸参数。
4. 确认透明通道和边缘，无棋盘纹理烘焙、白色矩形或裁切残肢。用Image Gen完成需要的图像修改。
5. 生产文件建议透明PNG或支持alpha的WebP，提供足以覆盖2×设备像素比的96/128px版本；目标单图≤30KB、六图总量≤180KB，超标需优化并报告。
6. 在28、32、40 CSS px和明暗背景下检查；没有通过的图不能只凭大图好看就接入。
7. 记录生成日期、实际可知的工具信息、完整提示词、资源版本；不编造后台模型版本，不把栅格图改扩展名冒充SVG。

### 9.5 偏好保存与应用

按现有架构整合下述概念，不要求创建同名类型或新依赖：

```ts
type AppearancePreferences = {
  schemaVersion: number;
  mode: 'light' | 'dark' | 'system';
  colorSchemeId: string;
  uiFontId: string;
  dataFontId: string;
  uiScaleId: string;
  iconPackId: string;
};
```

- 统一Provider／store作为真源；初始化读取、选择控件、跨标签页更新和根节点属性使用同一校验逻辑。
- 优先保留现有设备本地偏好的作用域；界面说明“在此设备生效”。不凭空承诺登录后跨设备同步。
- 如最新仓库已实现账号偏好，则复用其作用域和同步规则，补充账号切换／离线冲突验收，不另建平行本地设置。

- 从现有 `labnest.system-theme`及实际字号key迁移。新结构验证通过并写入成功前，不删除旧值；旧偏好合法时原样保留。
- 未知字段／套件ID采用安全显示fallback并保留可恢复原数据；遇到高版本结构不直接用默认值覆写。
- 初始化在首屏绘制前应用可知偏好，结合现有 `layout.tsx` bootstrap；处理SSR／hydration一致性与CSP，不制造主题闪烁。
- 只使用受控scheme/font/icon ID与资源清单，不能把任意存储文本拼成CSS或脚本。
- 多标签页通过既有订阅或storage事件同步；禁止读写循环。
- Appearance写失败不会改变Calculator历史保护状态；清除／恢复外观默认也不触碰Calculator key。

### 11.3 离线、记录及数据库

必须使用固定合成fixture、隔离测试数据库和明确测试账号，禁止生产样本。关键fixture不存在立即失败，不能用 `if (count())` 跳过后显示成功。

| 用例ID | 场景 | 证据 |
| --- | --- | --- |
| I01 | 在线加载→计算与改单位→刷新恢复草稿 | UI及存储断言 |
| I02 | 首次在线并完成缓存→断网→刷新Calculator | 页面／资源能加载；可计算；说明只覆盖已缓存情况 |
| I03 | 离线记入指定实验与步骤→重连 | 队列状态；服务器记录完整；单位和警告存在 |
| I04 | 同一mutation重复发送／重载重放 | 数据库仅一条目标记录，关联ID正确 |
| I05 | 保存权限变化／步骤不存在／服务器拒绝 | 保留本地意图，显示原因，不假报同步成功 |
| I06 | WB从页面→复制／导出→实验记录 | 浏览器结果、下载文件解析和数据库回读一致 |
| I07 | standalone Calculator打开、单位切换、资源失败 | 与主应用计算与警告一致；偏好作用域明确 |

如果实际离线实现只支持不刷新页面的计算，I02应为失败／未实现，不得写“已支持离线”。I03–I05依赖现有队列，不能将页面localStorage写入成功当作数据库同步成功。

### 11.4 构建与CI门槛

执行时先核对实际package scripts和锁文件。历史基线存在 `lint`、`typecheck`、`test`、`build`、`prisma:generate`、`test:calculator:e2e`、`test:calculator:integration`，不代表未来版本一定同名。

建议CI依赖次序：锁文件安装 → Prisma生成 → Lint／Typecheck／完整单测 → 生产Build → 隔离数据库初始化与fixture → 启动生产构建 → E2E与数据库回读。独立检查可并行，但下游必须等前置产物可用。

- 附Node、包管理器版本、commit SHA、命令、退出码、日志、测试数、跳过数及跳过原因。
- 核心用例跳过数必须为0；没有CI run或status应写“未取得CI证据”，不能写“CI通过”。
- 验收提交应对应最终待合入／合入状态；若后续又有相关改动，重跑受影响门槛，不能沿用旧SHA结果。
- 对已知库存日期问题，在Asia/Shanghai与America/Vancouver等相关时区验证日期语义；若仍失败，单独列原因和影响，不把全仓门槛改成只测Calculator。
- 构建成功不能证明数据库写入正确；截图不能证明单位转换或幂等；本地单测不能替代CI结果。
- Playwright移动视口不等于真实手机。至少补一次真实iOS Safari或Android Chrome输入与软键盘检查，记录设备／浏览器；尚无设备时列为待人工验收。
- 3–5名实验人员的找入口、稀释、铺板、WB小规模试用属于后续体验验证，报告实际观察；不得编造使用时间或成功率。不因无法完成试用而停止已授权的实现工作。
