## 1. P1｜实验元数据右侧属性面板

### EXP-01 顺序与层次

面板按以下顺序展示：

1. 所属研究方案。
2. 方法来源：依据实验规程／自行记录。
3. 选择Protocol及版本：仅在依据规程时显示。
4. 执行状态、记录状态及其他适用属性。

- 研究方案必须先于方法来源出现。沿用现有是否必填及权限规则，本轮不擅自扩大为“实验可不关联研究方案”的数据模型变更。
- 优先列出所属研究方案关联的Protocol，同时保留搜索其他可用规程的入口。
- 更换研究方案不能静默清除已选规程、已保存步骤或执行记录；已有历史执行遵守版本与来源保护。
- 状态选择按钮的字号、行高、字重与旁边同级控件一致，不受文档正文或标题字号污染。
- 分组用标题、细分隔线和对齐组织，取消装饰性卡片嵌套。

### EXP-02 精简Protocol选择提示

- 截图2的“What happens after Save”及“One Result per Experiment”长篇说明取消常驻展示。
- 必要帮助放入一个按需展开的说明入口；真正影响操作的错误／版本冲突仍清楚呈现。
- 已选项采用紧凑列表：Protocol名称、版本、移除操作；中文界面不显示内部对象名ProtocolVersion(s)。
- 多个规程保留执行顺序；研究方案右栏关联数量多时默认仅显示少量摘要及总数，通过“管理全部”搜索、筛选和批量管理。

## 2. P1｜实验文档简介单行化并进入正式输出

### DOC-01 只保留三个字段

显示示例：

> Experiment ID：EXP-006 ｜ 研究方案：细胞迁移研究 ｜ 方法来源：Migration assay · v2

- 只显示Experiment ID、研究方案、方法来源。
- 保留Experiment ID；研究方案显示名称，Protocol显示名称和版本；隐藏研究方案和Protocol编号。
- 不再显示“已锁定1个实验规程版本”“Select ProtocolVersion(s)”等无具体来源内容的提示。
- 日期、执行状态、记录状态移入属性面板，不占简介位置。
- 自行记录时方法来源显示“自行记录”；兼容旧记录缺失字段时使用明确空状态，不伪造名称或版本。
- 标签和值同排，整条简介保持一行，不采用标签一行、值一行的大网格。
- 屏幕长名称省略显示，点击或悬停查看完整值；多个Protocol显示紧凑名称／版本，空间不足首项＋N，点击查看全部。
- 手机不靠将文字缩到难以阅读维持单行；简介只在自身区域处理溢出，不撑宽整页。

### DOC-02 保存、只读与打印一致

- 简介进入保存后的正式文档呈现、只读页、打印／PDF及适用的正式导出，不能只存在于编辑页面装饰层。
- 实际使用的Protocol名称、版本及关联身份可追溯；之后发布新版本不能让历史实验自动变成新版本。
- 简介单行与完整追溯同时保证：打印使用明确短展示，完整研究方案名称及全部Protocol名称／版本在执行记录的来源位置完整列出；禁止打印后只剩省略号而无完整来源。
- 完整来源属于实验文档内容，不以内部编号和技术字段堆砌。
- 复用现有文档模型及统一渲染／导出路径，避免各页独立拼接造成内容不一致。

## 3. P0｜Run偏差／异常进入实验文档执行记录

### RUN-01 保存与展示链路

必须检查：Run输入 → 保存接口 → 持久化记录 → 回读 → 正式实验文档 → 打印／导出。

当前代码中的完成数和偏差数汇总不足以满足需求。记录中已有偏差不能只显示“记录了N项偏差”，也不能因为主文档没有相同字段而忽略。

- 按实际选定的Protocol顺序、每个Protocol的步骤顺序展示。
- 无偏差完成：一行“✓ 步骤名称”，不铺开全部原始操作说明。
- 有偏差：步骤名称＋红色“偏差”标记＋实际偏差内容。
- 有异常：步骤名称＋红色“异常”标记＋已填写的异常和处理记录。
- 已跳过／未完成：如实显示，不能因没有偏差文字就自动打钩。
- 跳过与完成资格遵守已有规则；本轮不允许绕过必需证据或强制步骤。
- 附件、实际参数与观察记录归属对应步骤；正常步骤详情按需展开。
- 红色之外保留文字标记，黑白打印仍能辨认异常。
- 未填写的原因、处理或影响评估保持未记录，不自动生成科研结论。

### RUN-02 一致性与历史

- 保存、刷新、重新编辑、只读及打印／PDF均能看到同一份实际执行信息。
- 更正后正确更新对应呈现，保留必要的来源和更正记录。
- 手动正文与Run派生内容明确对应，不能整段覆盖用户已有正文或产生互相矛盾的两份执行记录。
- 如果系统支持同一实验多次Run，按各次执行身份分别展示，不能覆盖或混写；不为此无依据地新增另一套Run模型。
- 旧记录先核对是否已有可回读数据；可恢复展示不等于允许补造缺失异常。

### MAT-01 主界面紧凑清单

- 标题左对齐，右侧“＋添加”；移除主界面的常驻大录入表单。

### MAT-02 添加弹窗与连续录入

一个弹窗内提供两个入口：

| 入口 | 工作流 |
|---|---|
| 手动添加 | 名称 → 可选用量 → 可选库存关联 → 添加 |
| 从Protocol带入 | 选择实际使用的规程版本 → 读取消耗／损耗规则 → 补齐计算参数 → 预览预计用量 → 勾选添加 |

- 手动录入至少要求名称；仅记录使用时，不强制数量、单位或库存关联。
- 数值与单位使用共享紧凑一体控件；唯一单位直接显示。
- 支持“添加”与“添加并继续”；切换入口和关闭弹窗时避免丢失尚未保存的输入。
- 用量依据由系统记录；显示“手动填写／依据规程”，不让用户输入manual、correction等内部值。
- 弹窗内按需展开追溯信息；不再卡片套卡片。
- 可键盘操作；打开聚焦合适字段，关闭返回触发按钮；不拦截中文输入法确认。

### MAT-03 消耗／损耗规则

- 使用实际执行所依据的Protocol版本及已有Consumption规则。
- 规则可能按样本数、反应数、重复数或固定量计算，以真实规则为准，不预设不存在的参数。
- 损耗比例、额外反应数和额外体积不能混为一种计算方式；已有规则包含损耗时不能重复叠加。
- 展示简短计算依据，可查看详情；缺少参数时要求补齐，不猜测。
- 预计用量与实际用量分别保存。用户可以“按预计量确认实际用量”，但该动作必须显式发生。
- 尚未执行的步骤不能自动生成实际消耗；失败实验可能已耗材，也不能自动回退库存。
- 重复带入同一规则需要明确处理，不能重复累加；不同批次、不同瓶不能仅按名称自动合并。
- 包装／体积／质量之间只在必要规格或浓度明确时转换。

### MAT-04 保存与库存扣减

工作流：添加条目 → 编辑预计／实际量 → 保存使用记录 → 核对待扣库存清单 → 确认扣减。

- 添加和保存使用记录不等于执行库存扣减。
- 仅记录、不维护数量的物料正常保存；不要求创建库存。
- 扣减前明确库存来源、实际量和可用单位换算；只处理用户确认的项目。
- 失败、不足、来源缺失或单位不兼容时，保留实验和使用记录，标记对应扣减待处理，不假报成功。
- 区分“仅记录”“待扣减”“已扣减”，避免用含糊的执行状态代替库存状态。
- 重复点击、重试、离线同步和重复保存只执行一次；复制实验不复制已执行库存交易。
- 已领用培养基按瓶身份关联，不再次从仓库扣1瓶；可选登记约剩多少mL，记录估计／实测属性和时间。
- 两次估计250→180mL不自动生成本次精确消耗70mL；估计观察与扣减不能重复计量。

### MAT-05 编辑与删除

- 未扣库条目允许编辑或删除，保存后列表和回读一致。
- 已扣库条目的更正必须关联原交易，预览调整并保留历史。
- 删除已扣库条目不能静默抹掉交易或自动假定试剂已经退回；明确选择正确的更正／撤销记录操作及库存影响。
- 更正来源、单位或批次遵守既有账本限制，不能把同一笔体积账本悄悄改成质量账本。
- 补齐前端入口、后端动作校验和实际持久化。本轮main中的接口只接受save/confirm，不能仅添加一个表面删除按钮。

### MAT-06 Origin mismatch保存失败

- 已知截图4出现Origin mismatch；当前接口在Origin不等于request.url.origin时返回403。
- 这确定了一个对应代码分支，但尚未确认用户请求经过哪些代理、使用何种地址，不能据此断言部署根因。
- 在真实访问方式的隔离复现中核对Origin、可信Host／代理转发及部署配置；不要输出凭据或完整敏感请求。
- 复用项目统一的来源校验策略，正确配置可信部署边界；不得直接删校验、允许所有来源或无条件信任外部转发头。
- 失败保留所有输入，中文错误说明简洁可理解；成功提示必须以服务端确认结果为准。
- 验收同时覆盖合法来源成功和非可信来源被拒绝，不能只验证错误文字消失。

参考：[Design Spells](https://designspells.com/)；[React Bits Pro](https://pro.reactbits.dev/docs/introduction)。参考用于交互方向，不要求复制某个未核实组件。

| 场景 | 要求 |
|---|---|
