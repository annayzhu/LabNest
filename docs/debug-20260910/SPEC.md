## 3. 实验文档与执行确认层级

### EXEC-01 正式文档中的层级

层级应清楚体现：文档标题 → 执行记录章节 → Protocol名称/版本 → 步骤 → 该步骤的确认项与偏差记录。

- Protocol名称使用组标题，不与“执行记录”章节同级；只在组开始出现一次。
- 步骤名称保留正常文字权重；确认Checklist在相应步骤下缩进一级，默认比步骤正文小一档。
- PC建议一级缩进12–16px，手机8–12px；多级内容设合理上限，避免正文被挤成窄列。具体数值纳入变量，而非逐组件硬编码。
- 正式文档无偏差完成可用紧凑的“✓ 步骤名称”；只有实际完成才打钩。
- 未完成不能因为无偏差就显示完成。Checklist的视觉缩进不能改变它是否需要独立确认的业务规则。
- 多行文字悬挂对齐：后续行对齐文字起点，不对齐复选框或勾号。
- 不重复展开整份原Protocol。正常步骤详情按需查看，真实偏差和关键观察在正式记录中保留。
- 用户手写正文及其字号不能被刷新派生执行记录覆盖。

### EXEC-02 只给偏差/异常标签加框

建议呈现示例，仅表示样式：

> ✓ 步骤名称　【偏差】实际记录内容

- 步骤外层不再有整块红边框、红底卡片或厚重提示框。
- 仅“偏差”或“异常”两个字使用小型描边标签；实际内容紧随其后，过长正常换行。
- 延续前次要求：偏差内容以清楚的红色文字强调；同时保留文字标签，黑白打印也能辨识。
- 已填写的影响评估、处理措施和记录人按实际字段呈现，不自动推断或生成。
- 别把所有通用critical提示框全局去框：仅修改Run派生执行记录的展示，不削弱其他真正的警告。
- 建议为执行记录保留明确的展示身份/元信息，复用统一文档渲染；避免靠匹配“偏差”字符串或DOM顺序识别。
- 编辑、保存回读、只读、A4打印/PDF使用同一层级与标签语义；导出文字仍包含“偏差/异常”与完整内容。

### EXEC-03 Run操作界面与正式文档分别适配

- Run用于操作的复选框可以保留足够点击范围，但可见图形和标签文字应紧凑，不使用放大文字来扩大热区。
- 正式文档的完成勾号是执行结果展示，不做成大型表单控件。
- 步骤确认、文档普通任务列表、实验状态按钮各有明确角色，避免共用一个过大的label样式。

## 4. 编辑器：常用Word式功能，紧凑呈现

### EDIT-01 功能范围与已有能力

本轮目标是科研日常编辑完整、可靠、容易发现。已有加粗、斜体、下划线、撤销重做、字体/字号、行距、列表、链接、表格等能力应先验证并复用。

| 功能组 | 要求 |
|---|---|
| 编辑 | 剪切、复制、粘贴、纯文本粘贴、撤销、重做；光标、选区、中文输入正常 |
| 文字 | 加粗、斜体、下划线、删除线、字体与字号、清除格式；保留现有文字颜色能力 |
| 样式 | 文档标题、章节标题、正文及图注有明确默认样式；常用正文/标题在样式菜单可见 |
| 段落 | 左对齐、居中、右对齐、两端对齐；增加/减少缩进；保留行距，段前段后间距放段落设置 |
| 列表 | 有序、无序、Checklist；列表层级增减与普通段落缩进分别处理 |
| 表格 | 插入、增删行列、删除表、单格/多格/行/表字号；单元格内文字对齐和粘贴内容保留 |
| 图像与链接 | 保留插入、删除、图注、图片属性及链接；不得回退已解决的保存/打印问题 |

标题结构沿用文档已有语义：例如文档唯一标题可承担H1，章节H2，下级标题H3；不因工具栏文案变化重编号Protocol步骤，或把普通小标题变成新执行步骤。

### EDIT-02 工具栏布局

- PC常驻一条紧凑主工具栏：样式、字号、加粗/斜体/下划线、对齐、列表、插入、撤销/重做；按宽度适当收纳。
- 字体详细选择、段落间距、缩进设置、颜色、清除格式等放“更多/段落”菜单；常用对齐不能藏得难以发现。
- 选择表格/图片时出现对应上下文操作，切换焦点后回到常用工具。
- 手机主工具栏单行，保留常用项；次要项进入菜单或工具栏自身横向滚动。正文不能被多排工具按钮挤占。
- 图标有明确名称、状态和快捷键提示；触摸设备也能通过可见菜单理解功能。
- 当前选区包含不同字号/对齐方式时显示混合状态，不错误显示某个统一值。
- 点击字号、颜色、对齐等控件后作用于原选区，不能丢选区或把格式应用到另一个编辑器。

### EDIT-03 快捷键与输入

以下是目标交互映射，需在项目实际支持的浏览器与系统验证；不能只根据安装了扩展就宣称支持。

| 操作 | Windows/Linux目标 | macOS目标 |
|---|---|---|
| 剪切/复制/粘贴 | Ctrl+X/C/V | Cmd+X/C/V |
| 纯文本粘贴 | Ctrl+Shift+V | Cmd+Shift+V，核验目标浏览器冲突 |
| 撤销 | Ctrl+Z | Cmd+Z |
| 重做 | Ctrl+Shift+Z；兼容Ctrl+Y时核验 | Cmd+Shift+Z |
| 加粗/斜体/下划线 | Ctrl+B/I/U | Cmd+B/I/U |
| 编辑区全选 | 编辑区内Ctrl+A | 编辑区内Cmd+A |

- 其他段落/标题快捷键建立一份映射表，优先复用当前编辑器已有键位；有浏览器冲突时提供可靠菜单入口，不在全站拦截浏览器快捷键。
- Tab在表格内优先单元格导航；在列表中按既有规则缩进；普通表单保持焦点导航。普通段落提供独立缩进命令，不能全局劫持Tab。
- 中文输入法候选词确认时，Enter只完成选词；不误保存、不提交Run、不关闭弹窗。
- 剪贴板按钮受浏览器限制时保留快捷键/原生菜单路径，简短提示用户；失败不能显示已粘贴，也不能清空选区内容。
- Word/网页复制的普通标题、列表、表格与基础格式应合理保留；纯文本粘贴去格式但保留文字、换行与科研符号。按现有安全规则清理粘贴内容。
- 科研字符示例用于验收：µL、μL、×、±、≥、CO₂、中英文混排。不能把符号静默替换为含义不同的字符。

### EDIT-04 保存链路必须同步支持

- 覆盖Protocol、研究方案、实验、结果、报告、随手记录、结果模板说明及嵌套编辑器。
- 对齐、普通段落缩进、列表层级、段前段后与文字格式必须有可保存的数据表达。
- 同步检查编辑器JSON→业务文档→服务端校验→存储→业务文档→编辑器，以及只读、Run与打印渲染。
- 当前Scientific编辑器注册TextAlign不等于端到端支持。已读取的 `protocol-tiptap.ts`、`scientific-tiptap.ts` 未见对齐属性的显式往返处理，应作为保存丢格式风险核验。
- 表格文字同样需要保存对齐/字号，不能只让外面的段落生效。
- 旧文档无新属性时使用合理默认值；保留旧编号、来源、快照及内容。不要以重新导入或重建实验作为通用解决方式。
- A4/PDF等可表达版式的输出保持格式；CSV等格式本身无法表达全部版式时保留完整内容，说明适用边界。
- 合并单元格不在本轮新增承诺中：旧Run验收已注明该模型不支持。若故障样例涉及合并单元格，先明确输入支持范围，不能静默丢单元格文字或把它当普通表格已通过。

## 5. 手机Run：表格完整可见，记录区减少纵向占用

### RUN-01 将缺表格作为用户仍遇到的问题重验

main已有 `runStepContent` 与 `ProtocolContentBlockView` 渲染路径，也已有手机宽表样例。不要直接另建一套表格；先确定实际故障发生在哪一层。

核查路径：Protocol原内容 → 实验锁定版本/快照 → 步骤投影与关联 → Run接口/页面数据 → 当前步骤渲染 → 手机滚动容器。

必须区分：

1. 当前部署尚未包含修复。
2. 原Protocol有表格，但创建Run时未进入完整快照。
3. 快照有表格，但步骤投影/旧引用未把它关联到当前步骤。
4. 数据和关联正确，但显示条件、折叠状态、宽度或overflow使其不可见。
5. 表格属于共同准备、材料或其他章节，当前只展示步骤块，用户无法找到该表。

这些是待排查情形，不是本轮已经确认的根因。

### RUN-02 保留步骤关系与版本

- 当前步骤相关表格应在该步骤操作区直接可见，不能只能退出Run去Protocol页查看。
- 共用准备/材料表提供清楚的“规程参考”入口，Run内即可展开；不能把同一张公共大表复制到每一步拉长页面。
- 保留标题、表头、所有行列、单位、注释和参数内容；步骤顺序不改变。
- 同名步骤不能凭标题合并；按实际版本和稳定步骤/源块身份定位。
- 旧Run仅从其锁定的同一版本可信内容恢复。不能读取最新Protocol替换历史方法。
- 只有纯文本且没有可核对同版本富内容时，不伪造表格、不强行猜测归属；保留文本与简短缺失提示，将该记录列为未恢复。
- 修复不能改变已有步骤勾选、计时、偏差、结果关联或库存状态。

### RUN-03 表格显示与滚动

- 表格优先适配内容，表格容器 `min-width: 0` 等布局约束应正确处理。
- 窄表完整显示；宽表只在表格自身横向滚动，页面主体不被撑宽。
- 不把整张表缩小到文字和数字无法辨认。最后列、最后行必须可达，不能被底部导航或操作栏遮住。
- 短表不强制固定高；长表可使用合理高度的独立查看区，并提供“展开查看”入口。
- 横向滚动与步骤切换手势不冲突；不能在表格上左右滑动就误切步骤。
- 表头/首列固定仅在确实有助于对应行列时使用，并核验不遮挡其他单元格。
- 手机展示收纳不影响正式打印：打印/PDF必须展开所需完整内容并正常分页，不能只打印滚动窗口可见区域。

### RUN-04 紧凑的一屏操作目标

- 当前步骤编号/总数、短标题与状态形成紧凑顶部。
- 把有限屏幕优先给步骤说明和表格；计算器/材料/记录工具采用紧凑行入口。
- 无偏差时不常驻大偏差表单；“添加偏差/记录”点击后展开或用底部面板输入。
- 已记录内容用“类型＋简短摘要＋数量/状态”的行展示，编辑时展开；未解决异常始终保留可见标记。
- 上一步、步骤目录、下一步和确认操作就近安排；固定操作栏不得遮挡表格、输入框或软键盘。
- 返回前一步、往返工具或打开/关闭记录面板后，保留当前步骤、草稿和合理的滚动位置。
- “一屏”以普通短步骤为目标：常用内容和主要操作尽量同屏。长表或长说明允许滚动，不能为凑一屏裁切内容、缩小到难读或取消操作热区。

**格式缺失提示：**

- 已确认正文、表格等内容完整，只是格式降级时，把说明放入实验信息或一个按需查看的状态入口，不占正文一整行。

**空状态与状态提示：**

- 全零统计仅在数据已成功读取、确认确实为空时隐藏；加载中或读取失败不能冒充0。
- 离线正常使用、尚有未同步记录、同步失败分别表达；有影响当前操作的情况才在主界面简短提示，详情按需打开。
- 手机中文界面每项只显示一种语言，不同时排列中英文相同意思的长句。
- 不因隐藏统计而移除添加观察、测量、附件、耗材等能力；通过一个紧凑“记录/添加”入口访问。
- 视觉精简不删除数据库字段、不改变审计与正式文档输出，也不影响桌面端访问完整信息。

**手机默认信息顺序：**

1. 简短实验名称、返回和更多入口。
2. 一处步骤位置/完成进度。
3. 当前步骤名称、状态、实际说明和表格。
4. 紧凑的计算器、计时器与记录操作；计时运行中保留时间反馈。

## 6. 全站Typography Scale与间距系统

### TYPE-01 统一文字角色

以下数值为本轮建议实施基准，用于建立明确角色；可根据实际字体小幅校准，并记录最终值。不是外部标准，也不是强制覆盖用户既有文档排版。

| 角色 | PC默认字号/行高 | 手机默认字号/行高 | 字重 | 间距/用途 |
|---|---|---|---|---|
| H1页面标题 | 24/32px | 20/28px | 600 | 标题后12–16px，页面唯一主标题 |
| H2模块标题 | 18/26px | 16/24px | 600 | 上16–24px、下8px，主要section |
| H3组标题 | 15/22px | 14/22px | 600 | 上12px、下6px，Protocol/属性组 |
| Body正文 | 14/22px | 14/22px | 400 | 段后6–8px；长文可用舒适档 |
| Caption辅助说明 | 12/18px | 12/18px | 400 | 靠近说明对象，间隔4px |
| Label字段标签 | 12/18px | 12/18px | 500 | 标签与值4–6px；优先同排 |
| Button text按钮文字 | 13/18px | 13/18px | 500–600 | 控件内间距由统一组件控制 |

- H1/H2/H3/Body/Caption/Label/Button分别定义语义变量，包含字号、字重、行高与相邻间距。
- 不只靠颜色区分信息层级；标题通过大小、字重、位置和空间共同区分。
- 继续兼容已有紧凑/默认/舒适档，但各档都保留层级关系，不再把section标题与所有正文混为同一种样式。
- 小字不等于小热区：移动端输入控件需要兼顾系统缩放行为，可保持16px输入文字；不靠放大状态按钮文字提供触控范围。
- 统一中文与英文的字体族、字重回退及基线；数字、单位、标签同排时垂直对齐。

### TYPE-02 系统UI与文档排版分开

- 上表用于系统界面。A4文档使用独立的pt排版变量，保留用户已选字号。
- 文档默认可按主标题18pt、章节14pt、组标题11–12pt、正文10–10.5pt、辅助/确认项9–9.5pt形成层级；这些是起始建议，应以既有模板与实际打印可读性校准。
- 手机Run是执行界面，不照搬A4的小pt字号；表格、步骤和参数仍应清楚可读。
- 新默认仅用于未指定格式的内容或系统生成记录；系统主题/字号档变化不能改写已保存文档字号。
- 已由用户明确设置的字号继续优先，不用全局 `!important` 强制覆盖表格和正文。

### SPACE-01 统一空间关系

建议间距阶梯：4、8、12、16、24、32px，少量精细对齐值也集中管理。

| 关系 | 建议间距 |
|---|---|
| 图标与文字、标签与值 | 4–6px |
| 同一条记录内字段 | 6–8px |
| 紧密相关的相邻行 | 8px |
| 卡片/面板内边距 | PC12–16px；手机10–12px |
| 同一section的分组 | 12–16px |
| 不同section | PC24px；手机16–20px |
| 页面主要区域 | 24–32px，按实际布局校准 |

- 关系越近间距越小，关系越远间距越大；卡片内紧凑、section间有呼吸感。
- 卡片允许单层，取消装饰性卡片嵌套和重复阴影。
- 不通过大量负margin、全局缩放或压缩所有段落修补问题。
- 为边界宽度、文字换行及数字单位预留实际空间，不把紧凑理解成裁切。

### SPACE-02 截图对应的Protocol属性面板

- Availability、Review stage、Scope、Source、Usage、Updated等优先“标签左、值右/紧邻”的紧凑行，减少上下双行堆叠。
- 长值允许合理换行或展开，不让状态胶囊撑出整行高度。
- 标签集合用紧凑换行或局部横向滑动；关联对象显示少量摘要和数量。
- Import history与Attachments默认显示摘要/数量，按需展开；没有附件时不保留空表头和大片空白。
- 列表采用一种主要纵向滚动；不要给每个属性分组各放一条滚动条。
- 右侧面板关闭后恢复原阅读位置；手机面板不挤压正文。

### SPACE-03 Record类页面

- 已保存记录用紧凑行展示标题、必要时间/状态和简短摘要；低频详情缩进展开。
- 同级标签/小摘要适合横向滑动，完整正文按需展开阅读。
- 不把所有记录改成横向轮播；主要文本仍可正常阅读、复制与检索。
- 用户保存的偏差/异常不能因收纳而完全不可见；数量、状态与进入详情的入口清楚。
- 屏幕折叠状态不影响打印的完整性。

## 7. 动效只服务状态变化

| 场景 | 行为 |
|---|---|
| Hover/按下/焦点 | 反馈哪个控件可操作、已按下或获焦；手机使用触摸反馈 |
| 保存/上传/加载 | 等待、成功、失败与真实请求状态一致；不制造虚假完成 |
| 展开收起 | 表达空间变化，保持阅读位置和焦点，不在每次开合重播内容入场 |
| 页面/面板切换 | 用稳定方向表达进入/返回，避免随机滑动和大幅位移 |
| 列表更正 | 让用户能辨认哪一行已更新；不造成布局跳动 |

- 默认反馈约100–160ms，面板/折叠约160–240ms；统一变量，可按实际效果校准。
- 不添加持续漂浮、粒子、光晕、弹跳标题或逐字入场等无状态意义的效果。
- 尊重减少动态效果设置；简化后所有信息和操作仍可用。
- 不延迟保存、重复提交或清空草稿；不因动画让光标跳动。
- #75曾修复主题颜色渐变中间帧对比度问题。保留前景/背景同步切换策略，不为“更顺滑”重新引入低对比中间帧。
