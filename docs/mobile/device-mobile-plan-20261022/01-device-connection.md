# 任务书一：账号、工作区、常开主机与设备接入

日期：2026-10-29。版本：v2.0（Notion 式，一步到位），尚未实施。适用对象：实验室常开主机上的 LabNest、电脑浏览器、iPhone App、Apple Watch 辅助端。

v2.0 按用户确认的 Q117–Q124 改写：服务器放在实验室常开主机（Q117）；一开始就是完整的账号、多工作区与角色（Q121）；不再分 P0/P1/P2 分段发布（Q123），本文件的工作按里程碑 N0–N7 开发、最后一次发布。手机和电脑可以接入两个无法直接互访、但均可上网的 Wi-Fi；Watch 默认经随身 iPhone 同步，不要求蜂窝套餐。

原文件名保持不变，避免已有链接失效。本文件描述待开发目标，不是账号、跨网或离线功能已完成的声明。

## 1. 目标、适用范围与里程碑

### 1.1 用户实际场景

- LabNest 运行在实验室一台常开的主机上（Q117），保存 PostgreSQL 数据库与附件；iPhone 和 Watch 随研究人员进入一楼实验室。主机所在网络与手机所在网络可能互不直通。
- 两个 Wi-Fi 都能访问互联网，但不能直接访问彼此设备。不能把“连同一个 Wi-Fi”作为产品使用条件。
- 用户不查 IP、不反复输入地址、不因换楼层或换实验重新扫码。
- Watch 通过系统已配对的 iPhone 获取任务、计时状态与回传操作。LabNest 不替代 Apple 系统配对。
- 同网时仍以手机转发为默认路径。旧 Watch 直连只作为受保护的兼容路径，不增加双通道自动抢占或竞速提交。
- 普通断网、主机重启、账号过期、撤销权限和业务冲突分别处理，不能统称“重新配对”。

### 1.2 三种职责

| 能力 | 解决的问题 | 不能替代的内容 |
|---|---|---|
| 账号与工作区 | 谁能查看、修改哪份资料；审计记录何种身份 | 不会自动打通被隔离的 Wi-Fi |
| 私有跨网接入 | 手机跨 Wi-Fi 访问同一套 LabNest 服务 | 不能让已关机的主机继续提供服务 |
| 本机副本与补传 | 无法联系服务器时继续工作，恢复后核对并提交 | 不等于所有设备此刻都看到相同数据 |

账号和业务数据由实验室里的 LabNest 管理，不自动上传到公有云。私有网络服务的登录与 LabNest 账号是两套不同职责，不能混为一套用户权限。

### 1.3 与任务书二、里程碑的关系

| 里程碑 | 本文件负责 | 任务书二负责 |

## 3. 账号与工作区（N1）

### 3.1 交付内容与不包含的功能

必须交付：首次受保护初始化、默认管理员/拥有者、默认工作区、新建工作区、成员加入与移除、登录/退出、密码安全存储与重置、会话续期/撤销、设备登记、工作区归属、服务端权限校验和必要审计。

一开始就是完整的多工作区（Q121）：一个账号可以属于多个工作区，每个成员在工作区内有拥有者、编辑者或只读者角色。所有读取、写入、搜索、附件与同步都按工作区范围与角色检查，并用 A/B 两个合成工作区及跨区伪造 ID 做负向测试。按页面单独分享、组织架构、公开注册、订阅计费、企业单点登录和多机构云托管不纳入首版。创建账号不代表开放公网。

这不是仅增加登录页面。必须完成当前所有含业务数据的访问路径清单（[03 第 1 节](./03-current-state.md)：95 个页面、29 个服务端操作文件、57 个 API 路由），逐项验证登录、工作区范围与角色，不能只保护新设备接口、留下旧接口直接读写全库。数据访问集中到按工作区授权的数据层，同步引擎（任务书二）也从这一层读写。

### 3.2 安全初始化与历史数据归属

1. 升级前备份数据库、附件与现有设备待同步资料，先在副本演练。
2. 通过已验证的本机管理控制创建首个拥有者；初始化入口不能向整个局域网开放“先到先成为管理员”。不得仅凭可伪造的 Host/转发头判断本机。
3. 初始化只允许完成一次，处理并发请求，成功后关闭初始化通道。密码或一次性秘密不写入源码、URL、日志或共享文档。
4. 为已有资料建立默认工作区。已经存在稳定 workspaceId 时复用；尚不存在时只创建一次，并保存设备迁移映射。业务 ID、编号、关联、文件哈希与历史版本不变。
5. 账号获得管理权，不等于成为所有历史记录的作者。匿名/设备来源记录保留原始身份类型、设备和时间；迁移操作者另行审计。
6. 失败时保留原数据并提供受保护恢复，不以删除数据库、清缓存或重建实验解决。恢复流程不能重新开放无鉴权写入。

### 3.3 登录与会话

- 使用受维护、适配当前服务端与原生客户端的认证实现；技术验证后记录具体依赖和版本，不自行发明密码算法或 OAuth 协议。
- 本地账号支持用户名和密码；密码仅存安全哈希，提供登录限流、通用失败提示和安全重置。重置可采用受本机管理控制的一次性流程，不要求首阶段搭建公共邮件服务。
- Web 会话使用安全 Cookie、适当的过期/轮换策略及 CSRF/来源校验；原生客户端凭据放入 Keychain。使用可信 HTTPS，不把明文 HTTP 当正式登录通道。
- iPhone 的原生请求与嵌入编辑器通过受控方式使用同一账号上下文；不向页面脚本暴露长期刷新凭据，不把 token 拼进 URL。
- 注册、登录、刷新与撤销按同一认证机制实现；设备记录服务于审计和撤销，不再并行开发一套绕过账号的全工作区设备密码。
- 临时断网不清除账号关联或本地记录。短期访问凭据过期先尝试安全续期；需要重新登录时仅暂停受保护同步，保护未提交内容。
- 明确退出应锁定该账号的本地内容并停止其传输；退出前提示未同步项、保留受保护副本的恢复方式。新账号不得查看或提交旧账号队列。
- 确认收到账号禁用、成员移除或设备撤销后，停止业务访问与新业务操作，不自动换身份重试；已有未同步资料进入受控恢复。完全离线时无法即时获知远端撤销，不宣传远程即时擦除。
- 会话时长、离线授权有效策略在技术验证中定稿并写入配置/测试；普通短时掉线不触发每日重新配对。

登录、授权和会话是不同控制点，需共同验收。[OWASP 授权原则](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)、[会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)

### 3.4 统一服务端授权

服务端从有效会话解析人员、工作区、角色、设备与能力；不能信任客户端自行填写的 userId/workspaceId/deviceId。对象查询、关联创建和附件所属关系均须验证工作区一致性，默认拒绝未明确允许的访问。

| 入口类别 | 必查内容 |
|---|---|
| Web 页面、Server Actions、普通 API | 登录、成员关系、角色、目标对象和关联对象的工作区一致性 |
| 搜索、列表、统计、导入导出、后台任务 | 查询范围和任务结果权限；后台任务绑定发起主体，不能通过导出绕过权限 |
| 附件、图片、下载、预览 | 与所属记录一致的读取/写入权限，不保留可绕过鉴权的旧静态文件路径 |
| 手机同步、操作回执、变化游标 | 用户与工作区范围、设备有效性、幂等范围和当前业务权限 |
| Watch 转发、旧 Watch API | 合法 parentPhone、原操作来源、用户能力；旧凭据不自动升级为全库权限 |
| 管理、配置、AI 服务密钥 | 管理权限；普通数据同步不下发数据库、供应商或其他成员的秘密 |

健康检查、登录和最小实例元数据可按明确白名单匿名访问，但不能返回科研内容或敏感部署信息。只读角色不能因 API 与页面不同而获得写权限。

### 3.5 工作区与同步

同步引擎的每次下载、变化推送、游标与提交都限定在一个工作区内；切换工作区就是切换本机分区，不会把一个工作区的数据带到另一个。成员被移除或角色降级后，服务器停止推送并拒绝越权提交，客户端按第 5.4 节处理本机资料。首版不做按页面单独分享，后续加入时沿用同一授权层。

## 4. 常开主机与跨 Wi-Fi 访问

### 4.0 常开主机（Q117，N1）

- **选择：** 实验室里一台常开的机器：Mac mini、小主机，或把现在这台 Mac 设为接电源永不睡眠。由用户本人选定和设置；实施方不擅自修改全机休眠或安全设置。科研数据留在实验室，不默认上公有云。
- **要求：** 能长期运行 Docker 与 PostgreSQL；有足够磁盘保存附件与每日备份；断电重启后服务自动恢复；能运行 Tailscale。
- **迁移（若不是现在这台 Mac）：** 先在新主机演练；停写旧服务→用应用自带备份导出→在新主机还原并核对表指纹与附件哈希→切换地址→旧服务保持只读一段时间。不能同时运行两个接受写入的主服务器。
- **备份：** 沿用现有每日备份与还原检查；备份位置在主机之外（另一块盘或机构存储）。
- **对外：** 只经 Tailscale 私有 HTTPS 提供服务；本机端口不对实验室 Wi-Fi 开放（现有 Watch 直连改经手机后即可关闭局域网入口，见第 7 节）。


### 4.1 主链路

```text
Apple Watch（无需蜂窝套餐）
        ⇅ 系统配对通信＋LabNest 持久操作转交
iPhone（实验室一楼 Wi-Fi）
        ⇅ 可信私有 HTTPS，使用账号会话
常开主机上的 LabNest 服务（与手机互不直通的网络）
        ⇅
同一份 PostgreSQL＋附件
```

默认方案为常开主机与 iPhone 使用 Tailscale 私有连接及 Serve 提供可信 HTTPS。两端均可上网是已确认条件，是否允许此类私有连接、是否与既有 VPN 冲突、真实网络是否可用仍须实测。Watch 不安装 VPN，也不假设它自动继承手机 VPN 路由。

Tailscale 是本阶段的连接候选，不是已安装成功的事实。需要一次性安装、网络账号授权和最小访问策略配置；这些前置步骤必须有操作指引。不得承诺“装上 LabNest 就已具备跨网连接”。[Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve)

### 4.2 安全与部署要求

- 只使用私有访问路径，不开公开 Funnel、不做无保护的公网端口映射；数据库端口不暴露给手机。
- 私有网络控制只准许所需用户/设备访问 LabNest 服务，不开放整台主机的无关服务；LabNest 内仍独立执行账号权限。
- 说明第三方协调服务及可能的加密中继依赖。数据库继续本地保存不等于网络流量从不经过第三方设施，不作“无第三方接触任何元数据”的保证。
- 实验室限制相关网络服务时，先使用机构批准的连接方式或可达常开服务器；不得擅自绕过机构网络政策。
- 常开主机必须保持开机、网络和 LabNest 服务运行；说明意外停机的影响。实施时不得未经同意修改全机休眠、安全或网络策略。
- 可信端点属于安装/部署配置，不从任意 Host 头生成。地址或证书变化须经过同一实例的信任核验。
- 拒绝 HTTPS 失败后的静默降级、忽略 ATS 错误、关闭证书检查。明确区分 VPN 关闭、服务停止、账号失效和内容冲突。
- 网络切换后优先沿用固定可信地址。不能要求手机回到主机旁重新扫码才能恢复。

### 4.3 局域网发现是补充，不是跨网方案

保留自动发现本机可用 LAN 地址的能力，供同网诊断或经验证的备用路径。Bonjour 和网卡枚举不能打通两个互相隔离的 Wi-Fi。

- 从宿主机获取活动网卡及真实发布端口；容器内部地址、0.0.0.0、host.docker.internal 不给手机直接使用。不能为发现地址挂载 Docker socket。
- 过滤未启用/内部虚拟接口；不能一律排除真实实验室也可能使用的整个私网地址段。
- 电脑自测只证明电脑可达；候选地址须由手机验证，并记录来源、检测时间与过期状态。
- 无可用地址时给出具体诊断，不要求普通用户猜 IP；手工覆盖仅保留为高级诊断。
- 相机、局域网权限与 TLS 信任分别处理，不把任何权限拒绝算作连接成功。

参考：[Docker Desktop 网络](https://docs.docker.com/desktop/features/networking/)、[Apple 局域网权限](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)。

### 4.4 必测真实网络场景

先证明两个 Wi-Fi 的 LAN 地址确实不能互访，再证明启用已授权私有通道后，iPhone 能访问相同 serverId/workspaceId。测试 Wi-Fi A→Wi-Fi B→手机蜂窝网络→关闭网络→恢复网络；记录请求、同步回执和最终数据核对结果。只测试本机 curl 或同一 Wi-Fi 不算通过。

如果机构网络条件导致跨网验证失败，应报告具体限制并共同选择替代接入，不把功能降级为“仅同 Wi-Fi 可用”后宣布完成。

## 5. 首次接入、日常使用与离线恢复

### 5.1 首次接入，允许零实验

1. 在常开主机上完成受保护的管理员与工作区初始化，登录后侧栏始终提供“连接设备 / Connect devices”。
2. 页面显示可信固定地址准备状态、二维码、简短步骤和设备列表；不加大面积看板。
3. iPhone 通过扫码或受信连接链接确认要连接的 LabNest 实例。二维码用于定位/确认实例，不代表已经取得工作区权限。
4. 在已验证的目标实例登录 LabNest；服务端列出当前账号获授权的工作区。一个工作区直接进入，多个提供选择，零个显示无访问权。
5. 在账号下登记设备，保存稳定身份与安全凭据，启动工作区目录/文档同步。登录成功不等于离线内容已准备完成。
6. 零实验仍可连接、浏览其他有权限内容或新建；不为配对制造空实验。
7. 已配对 Watch 由 iPhone 登记为辅助设备。Watch 暂不可达不阻塞手机；不要求手表第二次输入账号、IP 或扫描二维码。
8. 首次认识一套自托管实例仍需要可信连接信息；同一个用户名不能自动发现互联网中所有本地 LabNest。固定服务器/托管发现服务属于后续部署能力。

### 5.2 从实验进入与日常切换

原“其他设备”入口复用全局流程，可携带 requestedExperimentId 作为打开目标。切换实验不重新登记设备；实验不可访问时连接本身仍可成功，但不得打开该实验。手机换 Wi-Fi 后保持同一账号、设备、实例、工作区及本地库。

### 5.3 断网继续记录与自动补传

1. 在支持范围内，写入先持久保存到手机或手表的本地队列，再显示成功。纯内存状态或网页刷新后丢失不合格。
2. Watch 先写自己的操作记录，手机持久接收后回“已传手机”；服务器确认后才回“已同步 LabNest”。手机无网络时仍可接收手表操作。
3. App 在前台检测到网络恢复、从后台回前台或手动重试时自动恢复同步；用户不重新配对。系统允许时后台尽力补传，不承诺 iOS 被强制退出后仍即时联网。
4. 每次重试沿用原始操作 ID，带基础版本、原设备与工作区；同一动作只产生一次业务效果。
5. 服务端按当前账号权限与业务规则处理。冲突保留双方并提示核对；鉴权失败、被撤销或数据错误不能无限自动重试。
6. 电脑睡眠/服务停止时继续本地记录，服务恢复后补传；未下载内容不承诺离线可打开。
7. 具体存储事务、游标、附件和冲突规则使用[任务书二](./02-independent-mobile-app.md)第 6–10 节，不另写第二套队列。

### 5.4 切换账号、服务器或撤销设备

- “重新连接原实例”和“连接另一套 LabNest”是不同操作。切换前检查待同步项，不覆盖连接资料、不把旧数据复制进新工作区。
- 本地数据至少按 serverId/userId/workspaceId 隔离，待同步操作保留原始账号上下文。
- 撤销一台 iPhone 的服务器访问时，其 Watch 转发授权同时失效；界面明确这个联动。撤销与网络暂不可达使用不同文案。
- 本地已有内容不能被服务端瞬间擦除；获知撤销后按受保护恢复策略处理，不为清零待同步而改用别的账号上传。
- 替换手机或重装手表前，保护未同步数据；普通卸载重装不作为修复方法。

## 6. 数据对象、二维码与拟议接口

以下为待实现契约，不声称数据库已经存在这些表。可复用认证库模型，不重复建设自定义账号系统。

### 6.1 最小对象

| 对象 | 必需语义 |
|---|---|
| User／账号 | 稳定身份、凭据引用、可用状态；账号不是设备或工作区 |
| Workspace／工作区 | 研究数据空间；可从现有单库建立默认工作区 |
| Membership／成员关系 | userId＋workspaceId＋基础角色＋有效状态 |
| Session／会话 | 经验证人员、客户端/设备、到期与撤销、正规续期机制 |
| Instance／实例 | 稳定 serverId 与可信端点；IP 不作为身份 |
| Device／设备 | 安装 ID、所属人员、类型、可选 parentPhoneId、撤销、最后联系 |
| DeviceWorkspace／授权关联 | 设备可使用的工作区及能力，不能超过当前人员权限 |
| ConnectionOffer／接入信息 | 短期、有限用途、可幂等消费；不能替代登录或成员授权 |
| ActiveTask／当前任务 | 可选实验上下文；业务权限每次核对，身份不随任务变化 |

所有业务对象须能直接或通过明确父关联解析工作区。附件、导入任务、审计和同步回执也在范围内；不要求无理由地给每个子表重复加相同列，但禁止无作用域查询。

serverId 是标识不是秘密。地址改变、数据库复制到测试环境、备份恢复与实例迁移均要核对可信身份，不能只比较字符串。测试安装使用不同 serverId，保持与真实系统隔离。

### 6.2 二维码与设备授权

- 可携带协议版本、可信服务地址、实例标识、过期时间、短期接入信息及可选打开目标。
- 不携带密码、长期 token、数据库地址、科研内容或样本标识。
- 扫码不能跳过 LabNest 登录。接入信息被转发或截图泄露时，也不能让未授权账号读取工作区。
- 如果接入信息含一次性秘密，需足够随机、限时、限流、原子消费与回执恢复；不扩展现有四位码为全工作区授权。
- 发码/管理操作需要有效账号与相应权限、CSRF/来源校验。连接信息的创建不等于添加成员。
- 已开始登记但回执丢失时，通过同一账号和请求 ID 恢复，不重复创建设备；不能由另一账号重放。
- 相机被拒绝时提供受信链接打开/分享入口，用户不必手填 IP。系统相机是否能拉起 App 单独验收。

### 6.3 拟议接口组

| 接口组 | 行为与约束 |
|---|---|
| 受保护初始化入口 | 只在受本机管理控制、未完成初始化时可用；成功后关闭 |
| 认证库登录/退出/刷新/重置接口 | 共用人员身份，适配 Web 和原生，具体名称由选型决定 |
| GET /api/v1/instance | 最小产品/协议信息，不含科研数据或全部网络拓扑 |
| GET /api/v1/me、GET /api/v1/workspaces | 只返回当前人员与获授权工作区 |
| GET /api/v1/devices/discovery | 已授权管理入口，可信地址状态；不接受任意 URL 代探测 |
| POST /api/v1/connection-offers | 登录用户生成有限用途接入信息 |
| POST /api/v1/devices/register | 登录＋成员权校验＋幂等登记，不能仅凭二维码取得业务权限 |
| GET /api/v1/devices、POST /api/v1/devices/:id/revoke | 本人设备或有管理权的范围；撤销父手机联动 Watch |
| POST /api/v1/devices/:id/watch | 已授权手机登记自己的辅助 Watch，记录人员与设备关联 |
| PUT /api/v1/devices/:id/active-task | 合法会话选择有权限实验，不改变设备身份 |
| 任务书二同步/回执接口 | 同一身份、权限、幂等与审计，不另建匿名写入通道 |

命名可适配现有代码；权限和行为必须保留。默认不实现 Watch 直接持有人员密码或手机长期刷新凭据。

## 7. Watch 默认经手机同步

- 系统配对负责传输关系；LabNest 仍需业务协议、持久队列与确认，不把“系统已配对”当作实验数据已同步。
- iPhone 从本地库提供任务快照；Watch 的步骤、计时、简短记录经手机转交服务器。无蜂窝套餐、关闭 Watch 蜂窝均须验收。
- 同一 Wi-Fi 下也默认手机转发；首阶段不开发直连/转发双写竞速。旧直连凭据不静默扩大权限，旧接口需受限兼容或明确升级阻止。
- 迁移时清点旧 pending，保留操作 ID 与原来源；同一操作不得分别经旧直连和新手机转发产生两条记录。
- Watch 保留短时失去手机时的任务和操作队列；计时由本地持久截止时间恢复，不依赖每秒访问电脑。
- 手机被锁屏或系统限制后台时，显示真实待转交状态；不承诺每个动作立即跨网到达。收到手机持久回执与收到服务端回执是两种状态。
- Watch 不提供完整项目管理、富文本或独立账号登录；手机换账号后必须切换/锁定 Watch 上原账号内容，不串用队列。

详细通信、提醒和冲突规则由任务书二第 10 节统一定义；本节与 M03/M10 是同一实现的接入与业务验收，不开发两套 Watch 同步器。

## 8. 状态和错误文案

| 实际情况 | 推荐状态/行为 |
|---|---|
| 登录成功，但未完成内容准备 | 已登录；内容同步中；明确哪些可离线使用 |
| 账号有效，跨网通道未开启/不可达 | 暂时联系不到 LabNest；查看连接设置；已下载内容仍可用 |
| 手机本地保存成功 | 已保存到手机，N 项待同步 |
| Watch 已保存，手机未确认 | 待传手机 |
| 手机已持久接收，服务器未确认 | 已传手机，待同步 LabNest |
| 服务端已确认 | 已同步 LabNest，显示最近成功时间 |
| 401 | 尝试正规续期；必要时重新登录，不清空本地队列 |
| 403／明确撤销 | 无访问权/已撤销，停止越权访问，提供受控恢复说明 |
| 409 | 内容已变化，需要核对；保留双方 |
| 5xx／网络超时 | 服务暂不可用，稍后重试；不是重新配对 |
| 无实验或目标实验不可访问 | 工作区可用；没有实验/无法打开目标，不判为设备连接失败 |
| TLS／权限／版本不兼容 | 明确对应原因，不降级传输或按未知协议写入 |

全部文案中英双语；状态紧凑显示，诊断折叠。有效会话或设备登记不是“此刻在线”，最后联系时间不是服务端已保存所有操作。
