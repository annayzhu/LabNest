## v2.0 目标：像 Notion 那样

- **一处数据，所有设备都连它。** 账号＋工作区＋实验室里一台常开的主机；电脑浏览器、iPhone App、以后的 Android 都连同一个 LabNest。
- **每个设备都是完整客户端。** 打开时先读本机副本，改动先进本机队列，服务器把变化实时推给在线的设备；断网回来从上次的位置补齐。所以打开快、各端实时一致、断网也能用。
- **离线范围大。** 登录后有权限的正文与结构化数据全部同步到本机，大附件按需下载；实验室断网时能打开任何已同步的内容。
- **手表经随身 iPhone 同步。** 不需要蜂窝套餐、VPN 或独立登录。
- **首版不做：** 多人同时编辑同一段文字（保留双方并提示核对）、按页面单独分享、公开注册与云托管。

“一步到位”指不再分 P0→P1→P2 逐段发布：按上述目标架构一次建成，最后一次发布。内部仍按里程碑顺序开发，每个里程碑在测试实例上验收。

## 决定（Q117–Q124，按推荐）

| 编号 | 问题 | 决定 |
|---|---|---|
| Q117 | 服务器放哪 | 实验室里一台常开的主机（Mac mini、小主机，或把这台 Mac 设为永不睡眠）＋Tailscale 私有 HTTPS；科研数据留在实验室，不默认上公有云 |
| Q118 | 同步方式 | Notion 式：每条记录有版本；每个客户端有本机副本和操作队列；服务器把变化实时推给在线设备，断网回来按游标补齐；所有模块从第一天起用同一套 |
| Q119 | 多人同时编辑同一页 | 首版不做；同一段文字两人都改时保留双方并提示核对。块 ID 保持稳定，以后可以加 CRDT（如 Yjs） |
| Q120 | 客户端技术 | 一套 TypeScript 客户端：现有 React 界面改为从本机数据层取数；同一份代码跑在电脑浏览器、iPhone App（打包在 App 内）和以后的 Android；Swift 只做外壳、本机存储桥、相机、计时与灵动岛、通知、手表。不做全部原生重写 |
| Q121 | 账号与工作区 | 一开始就完整：账号、多个工作区、成员与角色（拥有者、编辑者、只读者）；所有数据与同步按工作区过滤；按页面单独分享以后再说 |
| Q122 | 离线范围 | 沿用 Q9：登录后自动同步有权限的全部正文与结构化数据，大附件按需，项目可整包离线 |
| Q123 | 中途是否先发布 | 不单独发布中间版本；里程碑在测试实例上验收，最后一次发布。用户要求时，可另行先做 Tailscale＋登录的快路 |
| Q124 | 设备 | iPhone＋Apple Watch＋电脑浏览器；iPad 使用同一个 iPhone App；Android 以后用同一套 TypeScript 客户端 |

## 目标架构

```text
电脑浏览器 ─ TypeScript 客户端 ─ 本机副本（浏览器存储）＋操作队列 ─┐
iPhone App ─ 同一客户端打包在 App 内 ─ 本机副本（原生 SQLite，经存储桥）＋操作队列 ─┤
Apple Watch ⇄ iPhone（持久转交、分级回执）                                          │
                                                        实时推送 ↑ ↓ 操作提交、按游标补齐
                          实验室常开主机：LabNest 服务器（账号与工作区授权、同步接口、推送）
                                              PostgreSQL＋附件
                          跨网：Tailscale 私有 HTTPS（只放行本人/成员设备、只代理 LabNest）
```

服务器仍是共享记录的确认来源；本机副本是可以独立工作的工作副本。业务规则（体系解析、规程版本、结果模板、计算）只有一份 TypeScript 实现，服务器与客户端共用，服务器接收时再校验一次。

## 内部里程碑与一次发布

| 里程碑 | 内容 | 验收（测试实例，合成数据） |
|---|---|---|
| N0 技术验证 | App 内本机库的持久性（强制结束、系统清理、迁移）；同步协议原型（版本、游标、幂等提交、实时推送）；Watch 真机持久转交；常开主机上的 Tailscale 私有 HTTPS 跨两网 | 每项有证据；若某项失败，按第 N0 节的备选方案处理并告诉用户 |
| N1 常开主机与身份 | 主机部署与从 Mac 迁移数据；账号、工作区、成员与角色、会话、设备登记与撤销；数据访问按工作区授权；现有数据归入默认工作区 | 任务书一的身份、权限、跨网验收 |
| N2 同步引擎 | 版本化记录、操作日志、变化游标、实时推送通道、幂等提交与回执、冲突保留双方；电脑与手机的所有写入都经过它 | 重复、乱序、回执丢失、断网补齐、实时推送测试 |
| N3 客户端数据层 | TypeScript 本机副本与操作队列、同步协调、页面订阅变化；浏览器与 App 两种存储适配 | 电脑浏览器离线与重开、两端实时更新 |
| N4 各模块接入 | 功能矩阵中的全部主要模块改为从本机数据层读写；附件按需下载与可续传上传 | 逐模块：查看、新建、编辑、搜索、关联，在线与离线 |
| N5 iPhone App | 打包客户端、存储桥、登录与工作区选择、离线准备进度、相机、计时与灵动岛、通知、前后台同步 | 真机：跨两网、飞行模式、强制结束重开、回网补齐 |
| N6 Watch 经手机 | 持久转交与分级回执、计时、表盘组件 | 真机：无蜂窝、手机离线、重启 |
| N7 迁移与发布 | 旧网页离线队列、旧 Watch 待同步、旧 App 的受保护迁移；GitHub、开发目录、常开主机服务与 App/Watch 安装包一次发布 | 全部验收矩阵；三处版本与安装包版本核对 |

**发布前你能用上什么：** 3001 与现有手机网页、App 保持原样；每个里程碑可以在测试实例上试用。**发布后你能用上什么：** 在一楼或任何网络下用 iPhone、电脑、手表使用同一个工作区；打开即看到本机副本，各端实时一致；断网时继续查看、新建、编辑，回网自动同步。

**量级：** 总量估计为数月，与 v1.2 的 P1＋P2 相当：省去中间版本的返工，但多了实时推送和多工作区。N0 结束时按实测重估。依据：现有 95 个页面中 63 个直接读数据库、29 个服务端操作文件、57 个 API 路由、58 个数据模型，读写方式都要改到同步层（见[源码事实](./03-current-state.md)）。

**用户本人需要做的：** 选定并准备常开主机（或同意把这台 Mac 设为永不睡眠）；安装并登录 Tailscale；确认机构网络允许；加入 Apple Developer Program（Q111）以便 TestFlight 安装。

## 整体完成标准

账号与工作区权限覆盖所有数据入口与同步；手机在两个互不直通的 Wi-Fi 下访问同一工作区；电脑、手机与手表的修改实时出现在其他在线设备；用户不查 IP、不因换网或换实验重扫；Watch 无蜂窝也经手机完成操作；手机与电脑浏览器断网、重开不丢记录；恢复可达后自动同步、不重写、不串账号、不静默覆盖另一端。

“自动补传”指前台或恢复前台且服务可达、授权有效时自动执行，后台按系统许可尽力运行；不能承诺强制退出后后台即时传输。登录、联网、已保存本机、已传手机、已同步服务器和离线准备完成分别验收。
