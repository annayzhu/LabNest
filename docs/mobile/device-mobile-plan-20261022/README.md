## M0 决策关卡

M0 结束后、开始实现 P1 业务代码之前，交给你一份证据报告，由你决定：

1. **离线客户端路线**：A（App 内打包的 Web 客户端，复用现有 TypeScript 组件与 `src/lib` 业务规则；Swift 负责存储桥、相机、计时与手表）或 B（原生 SwiftUI 页面与原生规则）。判定用例与比较方法见[任务书二第 5.2 节](./02-independent-mobile-app.md)。当前倾向 A。
2. **P1 范围与工期**：按 M0 实测重新拆分 D/M 工作包并估算；必要时进一步裁剪。
3. **是否继续**：证据不足或代价过高时，可以先停留在 P0，或改选其他路线。

关卡前可以并行推进 P0 和 M0 的技术验证；不先写 P1 业务代码，避免路线未定时返工。

## 目标链路与使用前提

```text
Watch（无需蜂窝套餐）⇄ 随身 iPhone（一楼 Wi-Fi）
                            ⇅ 安全跨网连接＋LabNest 账号
                     Mac 上的 LabNest（二楼 Wi-Fi）
                            ⇅
                     PostgreSQL＋附件
```

近期优先验证 Tailscale 私有 HTTPS；需要 Mac/iPhone 的一次配置、网络账号授权、最小访问策略及机构允许。它是已选的技术验证方向，不是已部署成功的事实；Watch 无需加入该私有网络。账号认证与跨网通道各司其职，不能互相替代。

Mac 必须在线且服务运行才能实时交换最新内容；Mac 休眠或网络中断时继续本地记录，恢复可达后自动补传。首次选择本地自托管实例仍需可信连接信息，不能只凭用户名自动找到任何电脑；固定常开服务器可在后续改善首次接入。

## 两份任务书的交付分工

| 总体阶段 | 任务书一 | 任务书二 | 验收范围 |
|---|---|---|---|
| P0 跨网快路 | P0-01–P0-06：私有通道、固定地址、单人登录、全路由登录要求 | 无（现有 App 与网页） | 一楼 iPhone 经私有通道使用二楼 LabNest；未登录访问被拒 |
| P1 第一阶段 | D01–D16：单一工作区账号/授权、设备与升级保护 | M0（含决策关卡）–M1：共用本地库、核心同步和 Watch 转交；首次迁移能力提前交付 | 两隔离 Wi-Fi、零实验接入、无 Watch 蜂窝、断网多步记录/重启/补传 |
| P2 完整主要功能 | 复用 P1 身份与连接，补全新增路径授权 | M2–M3：主要模块离线编辑、附件/大表、完整回归与发布 | 全功能矩阵，不只现场记录 |
| W 多工作区（按需） | 逐查询工作区范围、跨区隔离、成员邀请 | 同步范围按工作区过滤 | 出现第二个工作区或成员时另行确认 |
| 后续部署扩展 | 机构批准的常开服务器等 | 复用同步模型和稳定业务身份 | 另行确认，不自动开放公众注册或云端托管 |

P1 核心链路包括已准备规程/实验、连续步骤、文字、测量/小型结果、照片和计时，Watch 提供步骤与计时快捷操作。P2 扩展至全部已确认主要模块。两阶段不是两套账号、数据库或同步引擎。

P0 不等待 M0；M0 技术验证可先用合成数据开展，与 P0 并行。M0 决策关卡通过后才开始 P1 业务实现；M05 只依赖 D03/D04/D06/D08 的接入契约；D11/D14 在 M0–M1 完成后联调验收。不要把“先完成任务书一再启动任务书二”误解为循环等待。

## 整体完成标准

（P0 只满足其中的跨网访问与登录要求，不代表整体完成。）账号保护覆盖旧/新数据入口；手机在两个互不直通 Wi-Fi 下访问同一工作区；用户不查 IP、不因换网或换实验重扫；Watch 无蜂窝也经手机完成操作；手机/手表断网重启不丢记录；恢复可达后自动同步、不重写、不串账号、不静默覆盖另一端。

“自动补传”指前台/恢复前台且服务可达、授权有效时自动执行，后台按系统许可尽力运行；不能承诺强制退出后后台即时传输。登录、联网、已保存手机、已传手机、已同步服务器和离线准备完成分别验收。
