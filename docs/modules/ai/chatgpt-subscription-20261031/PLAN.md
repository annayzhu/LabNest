# AI：用 ChatGPT 订阅登录、推理强度、AI 设置页 UI

日期：2026-10-31
状态：Q201–Q214 已按推荐实现（Q208–Q214 于 2026-10-31 确认），已于 2026-10-31 发布到 3001（`3b3689d5`）。

## 1. 用户反馈（2026-10-31）

1. AI 模型目前只能用 API 配置，希望能用 GPT 或 Gemini 的订阅。
2. 点击配置订阅后，页面跳转去登录。
3. 不能选择推理强度（effort）。
4. AI 设置页的 UI 再调一下。

## 2. 调研结论

- **ChatGPT**：OpenAI 在 2026-09-29 推出“Sign in with ChatGPT”，开源和本地部署的应用可以使用用户 Plus/Pro 套餐的额度（[文档](https://developers.openai.com/siwc/token-sharing-open-source)）。调用走公开的 Responses API，必须 `store: false`、`stream: true`，不支持 `temperature` 和 `max_output_tokens`。用量计入 ChatGPT 的 5 小时额度，与 Codex 等其他应用共用。
- **Gemini**：Google 不允许第三方应用使用订阅额度。2026 年 2 月封过这样用的账号，6 月关闭了个人账号的 OAuth。只能用 AI Studio 的 API 密钥（有免费额度）。
- **回调地址**：OpenAI 只接受 `http://127.0.0.1:<端口>/auth/callback`。所以登录必须在运行 LabNest 的那台电脑上完成；登录后凭证存在服务器上，其他设备也能用。
- **网络**：3001 容器经美国出口访问 OpenAI 和 Google，无需代理。
- **推理强度**：模型目录给出每个模型支持的强度（low … max，部分模型还有 ultra）。API 只接受 none、minimal、low、medium、high、xhigh、max，ultra 会被拒绝（实测 400）。

## 3. 已确认的问题（2026-10-31，按推荐）

**Q201 入口**：连接设置里，在 DeepSeek、通义千问、Gemini 预设旁加“用 ChatGPT 订阅登录”。点击后跳到 OpenAI 登录和授权页，授权后回到 /ai，服务已保存。

**Q202 Gemini 按钮**：改名为“使用 Gemini（免费 API key）”。点击后在新标签页打开 Google AI Studio 的密钥页，同时填好 Gemini 预设。

**Q203 非本机地址**：用 localhost 打开时，先自动换到 127.0.0.1。用局域网地址或手机打开时，提示到运行 LabNest 的电脑上打开 `http://127.0.0.1:<端口>/ai`，并提供复制链接。

**Q204 登录后**：读取账号可用的模型，默认选第一个，可在下拉框里改。尚未选默认 AI 服务时，设为默认；AI 总开关保持原状。

**Q205 退出**：服务卡片上的“退出 ChatGPT”会在 OpenAI 撤销授权并删除服务。OpenAI 未确认撤销时，提示用户到 ChatGPT 设置里断开。

**Q206 存储**：新增接口类型 `chatgpt_subscription`。不变的注册信息（client ID、账号）加密存在 `AIProvider.apiKeyEncrypted`。会轮换的凭证加密存在新表 `AIProviderSession`，续期时不改服务的修订时间，因此不会打断正在进行的 AI 请求。续期在会话行上加锁串行执行。

**Q207 推理强度**（用户反馈 3）：卡片上并排选择“模型”和“推理强度”。强度选项只列出当前所选模型支持、且 API 接受的级别，并附 OpenAI 的英文名，如“高 · high”（用户要求加上英文）；默认项为“模型默认 · low”之类，跟随模型。加“更新模型列表”按钮，重新读取账号的模型和强度。存在 `AIProvider.reasoningEffort`，空值表示模型默认。

## 4. 实现与验证（3004）

- 迁移 `20261031180000_chatgpt_subscription`：枚举加 `chatgpt_subscription`，`AIProvider.reasoningEffort`，新表 `AIProviderSession`。排在样本模块的 `20261031120000_samples` 之后。
- 代码：`src/lib/chatgpt-auth.ts`（登录、ID token 签名校验、续期、撤销、模型目录），`src/lib/ai.ts` 的 `ChatGPTSubscriptionProvider`，路由 `src/app/api/ai/chatgpt/start` 与 `src/app/auth/callback`，`src/app/ai/page.tsx` 与 `src/components/ChatGPTModelForm.tsx`。
- 单元测试 `src/lib/chatgpt-subscription.test.ts` 19 项通过。
- 实测（用户已登录的 ChatGPT 账号，2026-10-31）：
  - 连接测试成功（gpt-6.1-sol，约 3 秒），reasoning effort 设为 high 后在页面上也测试成功。
  - 读图片：纯红图片答 “Red”。
  - 工具调用：namespace 形式可用，工具结果回传后得到最终回答。
  - 强度：low、max 可用，ultra 被拒（400），因此不提供。
  - 跳转：localhost → 127.0.0.1 → auth.openai.com；局域网地址被拦下；伪造的回调回到“登录没有回到发起它的页面”。

## 5. AI 设置页 UI 问题与推荐（2026-10-31 按推荐确认并实现）

现状：页面顺序是“启用 AI → 功能设置 → 使用 AI → 连接设置”。功能设置的两个下拉框高低不齐。新增服务区把 ChatGPT、三个预设的说明拼成一大段灰字。表单默认展开且比服务列表高很多。每张卡片的按钮换行不一致，“删除”有时单独占一行。

**Q208 页面顺序**
- 改为“启用 AI → 模型服务 → 功能设置 → 使用 AI”。
- 先有服务，再选默认服务和识别图片用的服务。

**Q209 功能设置对齐**
- “默认使用的 AI 服务”和“识别图片用的服务”两列顶部对齐，各自一行说明。
- 黄色提示只在所选（或跟随默认的）服务确实不能识别图片时出现，并直接说怎么改，例如“Gemini 需要在这里单独选择才会用于识别图片”。
- “允许附件”和“保存功能设置”放在同一行。

**Q210 添加服务区分成两块**
- 上面一块“用订阅登录”：ChatGPT 按钮和一行说明。不在本机打开时，显示 127.0.0.1 链接和“复制链接”。
- 下面一块“用 API 密钥添加”：DeepSeek、通义千问、Gemini（免费 key）、自定义四个选项。只显示当前所选选项的那一行说明，不再拼成一段。
- 已有服务时，这一块默认收起为“＋ 添加模型服务”，点开后再显示表单；没有服务时默认展开。

**Q211 服务卡片统一**
- 每张卡片都是三行：名称和状态；类型 · 模型（ChatGPT 再加 · 推理强度）；地址或登录账号。
- 按钮一行：左边“测试连接 / 编辑或重新登录 / 停用”，右边是红色的“删除”或“退出 ChatGPT”。
- 测试说明（会产生少量 API 费用、计入套餐用量）放进按钮提示，测试结果仍显示在卡片里。
- ChatGPT 卡片的“模型 / 推理强度 / 保存”保留在卡片中，“更新模型列表”改成小号文字按钮放在下拉框旁。

**Q212 列表与表单的布局**
- 桌面上服务卡片铺满整宽，每行两张；添加服务区在卡片下方整宽显示。
- 手机上单列。

**Q213 默认与识别图片的标记**
- 被选为默认服务的卡片加“默认”标记，被用来识别图片的加“识别图片”标记。
- 这样功能设置和卡片的对应关系一眼可见。

## 6. Q208–Q213 实现记录（3004）

- 顺序：`AISettingsPanel` 新增 `services` 插槽，页面把“模型服务”放在开关和“功能设置”之间。
- 功能设置：两列顶部对齐，各一行说明；默认服务不会自动识别图片时，提示写明服务名和改法；“允许附件”和“保存功能设置”同一行。保存后刷新卡片标记。
- 添加服务：`<details id="add-service">`，已有服务时收起；“用订阅登录”和“用 API 密钥添加”分两块，后者四个选项（含“其他服务”）只显示所选项的说明。
- 卡片：共用 `ServiceCard`（名称与标记、类型 · 模型、地址或账号、按钮行，删除或退出在右）。测试连接用 `inline` 模式，用量说明进按钮提示，结果整行显示在按钮下方。
- 布局：卡片桌面每行两张，手机单列（375 宽无横向滚动）。
- 标记：默认服务“默认”，识别图片的服务“识别图片”（按 `visionFromSettings` 计算，包括跟随默认服务的情况）。
