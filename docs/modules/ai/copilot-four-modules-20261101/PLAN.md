## 1. 目标与完成定义

用户要求：**工作流清晰、输出稳定、AI 建议可以选择和编辑后采纳；UI 具有高级感，风格、字体和字号与现有界面统一。**

四个模块采用一致的操作习惯：**确认输入 → 处理与检查 → 查看建议 → 编辑与选择 → 预览变更 → 采纳并回读。** 各模块保留自己的步骤、字段和质量检查。

稳定指关键事实、对象、字段归属、计算结果、来源及状态可靠；不要求同一输入每次生成完全相同的措辞。结构校验通过也不等于科学判断已经正确。

| 用户看到的效果 | 可验证的完成标准 |
| --- | --- |
| 知道按钮会做什么 | 开始前列明本次任务、选中资料、预计步骤；运行时显示真实阶段、需补充项、失败原因 |
| 输出符合当前模块 | 每个模块有独立 schema、必填项、字段映射和业务检查；缺项明确标记，不用通用长文代替 |
| 建议可选择、可修改 | 每条建议可编辑、勾选、忽略；显示目标位置、来源、修改前后及依赖；只写入已选内容 |
| 采纳可信 | 采纳前校验版本，采纳后核对保存结果；刷新可读；重复点击不重复创建或插入 |
| 分析结果可靠 | 数值来自可复算程序或已核验分析产物；AI 负责解释、提出方案和指出限制，不生成计算事实 |
| 出问题可以继续 | 保留已完成阶段与手动修改；失败从相应步骤恢复；取消后不再采纳迟到响应 |
| 视觉精致且全站一致 | 四模块复用全站字体、字号、颜色、间距与组件；层级、对齐、密度和状态表达通过页面对照验收 |

## 3. 所有模块共用的交互

### 3.1 一个工作区，三类内容

- **输入区**：本次目的、选中记录/附件/页码/数据表、缺少的信息。已有项目资料自动列为候选，用户可取消；术语或研究对象有歧义时就地澄清。
- **工作区**：当前步骤及其产物，可以回到前一步修改。简单 Entry 任务用紧凑面板；研究方案和结果分析用完整工作台，不强制所有任务点击同样多的步骤。
- **建议区**：按目标栏目组织可编辑建议，显示来源、待确认项及采用后的内容。用户无需了解 skill 名称或主动引用 skill。

开始前让用户知道发送给所选服务的资料范围；保存选择以减少重复操作。只读取本次必要资料，附件中的文字作为材料处理，不能覆盖任务规范或触发额外工具调用。

### 3.2 建议与采纳

每条建议至少保存：稳定 ID、建议类型、目标对象与栏目/块 ID、原值、新值、理由、来源、校验问题、依赖关系、用户编辑版本和处理状态。

1. 用户可修改 AI 草稿、仅重新生成选中项、单条/批量选择、忽略或保留待处理；重生成不能覆盖未确认的手动修改。
2. 替换、追加、建立关联、新建草稿分别展示；默认只作用于所选内容，不替换整篇文档。
3. 如果一条建议依赖另一条未选内容，提示一起选择或先补齐；程序检查依赖存在且无循环。
4. 编辑后重新运行受影响的校验。来源引用和人工补充明确区分，不把新写的内容继续标为“来自原文”。
5. 点击“预览采纳”展示差异，用户确认本次变更后写入；首次点击“分析/生成”不改变正式记录。
6. 一次采纳请求内的必要变更以事务完成；失败不留下半份结果。每次请求有幂等 ID，重复提交返回同一回执。
7. 采纳时核验源对象、目标记录及相关附件/数据版本；存在并发修改则重新展示差异，不能用旧草稿覆盖新编辑。
8. 保存原值、实际写入值、操作者、时间、来源和版本。支持在没有后续冲突时撤回本次文本/字段变更；新建且已有引用的对象不能通过“撤回”直接删除，应走现有归档/修订流程。
9. 生成、采纳与记录正式确认分开。采纳到草稿不自动把实验标为完成，不自动发布规程，不跳过现有记录签署要求。

### 3.3 真实状态与失败处理

| 状态 | 界面含义与允许操作 |
| --- | --- |
| 待补充 | 缺少影响当前步骤的输入；可补充或保存不完整草稿 |
| 处理中 | 展示当前步骤、已完成产物；允许停止 |
| 暂停 / 失败 | 明确卡在哪一步；可重试该步骤或选择已配置的替代来源 |
| 草稿可审阅 | 当前草稿满足其已声明范围的检查；尚未写入目标记录 |
| 内容已变化 | 输入、数据或目标版本改变；受影响的建议和审核需重新检查 |
| 已取消 | 不继续调用或接受迟到的模型/计算输出；之前的有效产物保留 |

建议另有“待处理、已编辑、已采纳、已忽略”状态；运行状态不代替建议决策，也不代替 `recordStatus`。

- 必需工具失败、响应截断、结构错误、计算失败不能显示“完成”。通过程序验证的阶段产物才可推进下一步。
- 文献工具可有限重试并切换已启用来源；两者都失败时暂停依赖文献的步骤。用户若主动选择仅按现有材料继续，则生成明确标为“文献未核对”的另一种草稿，不计为文献检索成功。
- 无检索结果、服务不可用、只有摘要、全文不可获得分别记录；无结果不等于无证据。
- 默认模型格式修复最多一次，仍失败即保留错误与可用草稿；工具重试、模型调用和总耗时均有上限。响应未知的中断请求先查运行回执，避免刷新即再次付费调用。
- AI 关闭时已有草稿仍可手动编辑，核心记录和已有分析工具继续可用。

### 3.4 UI 品质与全站视觉一致性（2026-11-02 用户补充）

四个 Copilot 的 UI 应呈现**克制、专业、精致的高级感**，与 LabNest 原有工作界面自然衔接。这是每批的交付要求，与功能验收同时执行。

1. **字体与字号统一**：工作界面继承全站 `--font-ui` 及外观设置；标题、正文、标签、表格、按钮分别使用已有语义字号。中英文、数字、单位和编号遵循同一套全站规则。文档编辑与预览继续使用既有文档排版，明确区分工作界面和文档内容。
2. **视觉语言统一**：颜色、边框、圆角、阴影、图标、控件高度和间距复用现有 tokens 与共享组件；需要调整的视觉参数集中在 `src/app/globals.css` 的语义变量中，避免四个模块各自维护一套样式。
3. **层级与密度精致**：用稳定的对齐、适量留白、清楚的分组和克制的强调色组织内容。页面标题、步骤标题、建议正文、来源说明层级明确；长建议按字段组织、按需展开，保持阅读和编辑效率。
4. **操作样式一致**：步骤导航、来源标签、建议勾选、编辑入口、修改前后对照和采纳操作在四模块中保持相同含义与视觉位置规则；每个工作区域明确当前主操作。已选择、已编辑、待核对、已采纳、失败分别有文字或图标标识。
5. **状态同样精修**：初始、空内容、处理中、失败、部分完成、草稿可审阅、内容过期、采纳成功均有完整布局；状态切换保持内容和操作位置稳定，保留用户正在编辑的内容与焦点。
6. **主题与尺寸一致**：跟随现有浅色/深色主题、字体及密度设置；桌面、平板和手机布局分别适配，保证长文本可读、表格局部滚动、按钮可操作、键盘焦点清楚。缩小屏幕时优先调整布局，字号继续服从全站规则。

当前源码的字号参考如下，仅用于核对现有设计，实施时以实际主题/密度下的计算样式为准；组件引用变量，不重复硬编码这些数值。

| 内容 | 现有样式依据 | 当前基础值 |
| --- | --- | --- |
| 工作页标题 | `--ln-page-title-size` | 20px，随全站密度/响应式设置变化 |
| 工作区与分组标题 | `--ln-ui-section-title-font-size` | 14px |
| 界面正文与建议说明 | `--ln-ui-body-font-size` | 13px |
| 标签、辅助信息与表格 | `--ln-ui-label-font-size` / `--ln-ui-table-font-size` | 12px |
| 输入框与常规按钮 | `--ln-control-font-size-md` / `--ln-control-font-size-sm` | 13px / 12px |
| 文档编辑与预览 | 既有文档字体与字号变量 | 沿用文档样式，与界面正文分别管理 |

每批 UI 开发前选取当前同类页面作为对照，明确复用的组件与视觉变量；完成后使用真实页面截图和计算样式核对，不仅检查设计稿。高级感不能仅以主观评价验收，还需满足第 10.3 节的具体标准。

## 4. 研究方案 Copilot

**工作流：确认情境 → 假设与竞争解释 → 所需证据 → 设计卡 → 审核 → 选择写入。** 在现有工作台上逐步补充，不并排增加第二套方案系统。

输入包括研究对象、模型系统、已有结果、目标主张、资源和限制；根据缺项按需读取相关规程版本与记录，记录已读和未读范围，不仅发送标题或静默截断的摘要。

固定输出：

- 情境卡：准确术语、研究问题、对象、样本、目标、已知事实和待定项。
- 假设与证据链：主要解释、竞争解释、所需证据、依赖关系、结果如何改变判断。
- 设计卡：实验目的、实验单位、分析单位、分组/对照、读出、重复含义、分析计划、判定标准、规程引用及不足。
- 证据记录：来源 ID、题名/标识符、来源版本或访问时间、相关段落、适用体系、支持/反对/方法/背景关系；模型的解释与实际取得的来源分开。
- 审核：具体卡片和字段、问题、严重性、修改要求、核查结果。审核绑定当前内容版本，修改有关字段后重新检查。

缺失关键分组/读出、未处理的关键澄清、空审核、无效依赖均不能被默认值掩盖。第二个模型审核只是补充，规则检查和来源检查继续独立执行；同一服务自审需如实显示。

写入现有前提字段和 `design`、`material_methods`、`acceptance_criteria`、`constraints`、`references` 五个栏目。新建计划实验与修改日程作为独立可选项，不能因采纳一段文字而隐式执行。

本轮回归案例采用用户已确认的术语和对象：ligand blot / far-Western；SRGN；候选 LRP1、ITGA3、ITGB4、MDK；细胞系 KYSE150 或 KYSE410。候选关系仍待验证，样本制备类型等未确认信息继续待定；不从项目背景虚构结果。

## 5. 说明书导入 Copilot

**工作流：读取原文 → 确认导入范围 → 按栏目整理 → 检查对应关系 → 编辑与选择 → 存为规程草稿。**

沿用两遍整理流程和现有 Protocol 文档 schema；模型输出领域内容，程序映射到现有编辑器，不要求模型自由生成编辑器内部节点。

固定输出包括规程说明、目的、背景、材料、步骤、记录/结果模板及适用条件，以当前 Protocol 契约实际字段为准。每个提取项附原文页码/段落/表格行等可用位置；无法定位的项目标待核对。

- 区分目录、页眉页脚、产品介绍与可执行操作；明确展示被排除的页面和未处理范围。
- 按“具体材料/试剂 + 步骤 + 适用条件 + 量值 + 单位”核对，不仅检查数字是否出现在全文。
- 同一数值在不同体系中不可互换；多体系参数复用现有系统/条件结构，不能猜比例关系。
- 原文未给出的内容留待定。原文提取与作者/AI 新增的记录建议分开显示。
- 长文件分段处理，并累计覆盖范围；不能把仅处理前若干字符显示为全文整理完成。
- 缺少 OCR、视觉或表格识别能力时说明哪部分未读到，允许用户补文字/确认表格，不静默按纯文本成功处理。
- 用户可以按栏目、步骤或参数选择采纳；依赖检查防止只选步骤而漏掉其必须的材料/条件。
- 说明书上传、图片转写、方法来源导入统一走这一条可检查草稿路径。保留原始附件、稳定 ID 和冻结的旧实验快照。

验收重点：目标栏目准确、来源可定位、参数归属不串换、草稿保存/重开一致；不能仅以“有 13 步”之类数量表示成功。

## 6. Entry Copilot

**工作流：读取当前记录 → 识别具体需求 → 匹配已有对象 → 提出可执行变更 → 编辑、选择与采纳。**

输入除正文外，还包括当前归属、已有附件引用、同项目可访问的实验/结果候选。图片需在用户选中且服务具备相应能力时读取；“记录含图片”不等于模型已经看过图片。

首版只开放有完整读写支持的动作：

- 整理标题/正文：保留原始内容和来源版本，预览哪些块被修改。
- 补充可确定的记录元数据：例如观察时间、组别、样本标记；未知项让用户选择。
- 建议归入已有实验或结果：显示候选编号、名称和匹配理由；多个候选不能默认选第一个。
- 确实需要时新建实验/结果草稿：展示将创建的字段及原 Entry 引用；不复制上传原有图片。

每增加一种动作，同批实现其独立 schema、候选对象检查、编辑表单、写入处理、来源记录和回读测试；未实现动作不提供可采纳按钮。相同目标/字段建议去重，相互冲突的变更要求择一。允许“当前没有值得采纳的建议”，不为凑数生成泛泛卡片。

## 7. 实验结果 Copilot

### 7.1 能力定位与首版范围

入口放在结果详情/编辑页；实验页可选中相关结果后进入同一工作台。任务包括“检查数据”“分析并解释”“只整理已有分析报告”“与原方案预期比较”。

首版同时支持三条清晰路径：

| 输入 | 首版能力 | 限制 |
| --- | --- | --- |
| 原始或已明确处理的数值表（CSV/TSV/XLSX） | 列映射、质控、描述统计、受支持的组间比较、图表与解释 | 必须确认分析单位、分组和数据含义；不支持的设计返回分析建议，不能伪装已执行 |
| qPCR/CNV 工具导出表、已有分析结果 | 用版本明确的解析器读取计算结果、参数和质量标记，再生成解释 | 首版先接入一种已核对格式，优先 qPCR；CNV 适配按实际导出结构验收后开启；保留原工具数值 |
| 图片、截图及文字观察 | 整理可见现象、检查标签/对照信息、提出需要的量化数据和解释限制 | 无定量数据时只给定性观察；不能从截图编造样本量、倍数、P 值或条带定量 |

`.xls` 目前可作为分析附件保存，但既有数据集解析器不支持它。首版明确列为“可归档、暂不可直接分析”，转换或增加解析器后重新确认表格。外部数据引用无法读取时同样不能声称已分析。大文件超过支持上限时给出可操作提示，不只分析预览或静默取前若干行。

首版不承担任意组学流程、任意代码执行、自动图像定量、混合模型或全部仪器格式；复杂设计可形成可导出的分析需求与待执行方案，之后通过单独适配器扩展。

### 7.2 完整工作流

1. **选择问题与数据**：选结果、附件、工作表和关联实验；读取完整选中数据，保留原件与校验和，显示实际行列数/读取范围。
2. **确认实验结构**：映射样本 ID、分组、结局、单位、批次、时间、配对关系、生物学/技术重复；能从记录读取的先展示，关键不确定项要求确认。
3. **质控**：检查缺失/非数值、单位混用、重复 ID、配对缺失、组别不平衡、处理状态及重复层级；异常值只标记，不自动删除。数据问题可修正映射或形成有来源的派生表，不覆盖原始文件。
4. **提出分析方案**：说明本次比较、分析单位、方法、适用条件、技术重复汇总、排除规则和多重比较处理。用户可编辑并确认；不能因看到了某个 P 值而自动更换检验。
5. **执行计算**：受控程序读取已确认数据与方案，生成完整结果表、质控记录和图表；失败保留输入与错误。程序产物经校验后才交给 AI 解读。
6. **形成解释草稿**：分开客观结果、对原假设的判断、竞争解释、限制和下一步建议；每个数字指向相应计算结果，推断指向支持它的资料。
7. **选择与采纳**：可只采用摘要、某张图、局限说明或某段解读；数字、图表、分析参数作为有依赖的产物一起追踪，写入相应结果栏目后回读。

只有截图的路径跳过计算阶段，明确标为“未执行定量分析”。缺少独立重复或关键设计信息时仍可保存观察和描述性摘要，但不能放行不成立的统计推断。

### 7.3 数值计算与科学检查

- 先支持连续结局的描述统计，以及满足已确认适用条件的两组独立/配对比较；具体检验不由关键词直接决定。方法、比较方向、效应量定义和置信区间算法在分析适配器中固定并测试。
- 不把技术重复、多个孔或多张视野当成独立生物学样本；汇总规则和实际独立样本数应可检查。
- 不把 KYSE150 和 KYSE410 自动视为同一条件的重复；是否分层、分开分析或引入模型由已确认设计决定。
- 保留全结果：效应估计、单位、区间、有效样本量、统计量、原始 P 值和需要时的校正 P 值；无法估计的值为缺失并附原因，不能写成 0。
- 缺失、排除、批次、归一化、已完成的转换均写入分析记录；缺少重复层级或归一化依据时不重复加工数据。
- “未发现显著差异”不自动解释成“没有效应”；支持、与预期不一致、证据不足、尚未检验分别表达。不给出伪精确的“结论可信度百分比”。
- 用户可编辑解释措辞；数值、样本量、单位和比较方向要与计算产物一致。修改数据、分组或方法应生成新分析版本并使旧解释失效，不允许直接改一个 P 值后仍标为计算结果。
- 再分析和事后比较标为探索性，保留原先预期与原分析；不会反向修改已签署方案来迎合结果。
- 每次计算记录数据/方案版本、工具与依赖版本、参数、随机种子（如适用）、排除清单和产物。图表由真实数据绘制，可导出，并保留绘图数据。

### 7.4 输出与现有字段的对应

| 结果产物 | 写入目标 | 采纳规则 |
| --- | --- | --- |
| 主要观察与摘要 | `summary` | 可编辑文字；数值引用必须保留依据 |
| 原始表、派生表、图和来源链接 | `data_media` + 原有附件/数据集引用 | 原件不覆盖；图表关联对应分析运行 |
| 方法、参数、完整统计表和计算回执 | `analysis` + 分析运行记录 | 依赖计算成功；改方法需重算 |
| 解释、与原假设的对应、下一步建议 | `interpretation` | 可逐条采纳；区分观察、关联与机制判断 |
| 质控问题、未解决项、排除与局限 | `quality_limitations` | 不允许采用结论时悄悄遗漏与其成立有关的限制 |

来源引用与计算产物必须和所选结论一起保存；用户可以隐藏非必要说明，但不能把必须的限定语删掉后仍通过同一质量检查。下一步研究建议可转为研究方案中的待审建议，需再次明确采纳，不自动启动实验。

## 8. 技术实现与 skills 接入

### 8.1 共享部分保持精简

保留 TypeScript / Next.js / Prisma、现有 AI 服务设置和编辑器。采用“共享运行与采纳能力 + 四个领域适配器”；首版不引入通用多智能体调度平台。

共享能力只负责：运行状态/回执、来源与内容版本、模型调用预算及取消、输出结构校验、建议差异展示、采纳版本检查及幂等、审计记录。领域 schema、检查规则、工具范围和字段映射仍由各模块管理。

实施时先复用 `ResearchPlanDesignRun`、`ProposedAction` 和现有来源记录；只为不能表达的运行产物、版本和分析任务增加必要数据结构。不先重建四套历史数据，也不把任意 JSON payload 当成通用动作接口。

| 必需记录 | 最小内容 |
| --- | --- |
| 运行回执 | 模块/目标、输入版本、任务规范版本、服务/模型、实际工具事件、调用次数、状态、错误与取消标记 |
| 草稿与建议 | 类型化内容、来源、目标字段、校验结果、用户修改、决定和相关版本 |
| 采纳回执 | 请求 ID、所选建议版本、写入前后内容、目标版本、操作者/时间、回读结果 |
| 分析运行 | 数据校验和、完整读取范围、确认的分析方案、执行环境与参数、日志及产物引用 |

模型支持严格结构化输出时传入相应 schema；不支持时依然执行本地严格校验和一次有限修复。模型能力按任务检测：纯文字整理不要求工具调用，图片解读需要视觉，统计计算由 LabNest 工具执行。更换模型不能绕过字段和业务检查。

长任务使用持久运行记录及阶段检查点；页面刷新只重新连接状态，不重启任务。受控计算采用固定、版本化的分析适配器，不执行 LLM 任意生成的脚本；优先复用现有 qPCR/CNV 计算能力，跨工具只通过明确的导出格式或接口交互，保持独立项目不共享数据库和内部状态。

数据进入新版本后，重新计算受影响的字段/图表/解释及审核；可以复用的已完成内容保留。快照应保存实际引用内容或不可变来源，不能只有一个无法还原输入的 hash。

### 8.2 每个任务规范都必须真正参与运行

每份产品任务规范包含：适用任务、所需输入、允许工具、输出 schema、来源要求、缺项处理、校验规则、写入映射、正反例和版本。运行记录保存实际加载的版本。开发代理的 `SKILL.md` 与产品运行规范分别维护，不假定安装后网页自动生效。

| 模块 | 参考规范 | 需要补成 LabNest 专用的部分 |
| --- | --- | --- |
| 研究方案 | K-Dense hypothesis-generation、experimental-design、paper-lookup、peer-review | 情境卡、设计卡、证据账本、审核失效与签署规则 |
| 说明书 | 本项目 labnest-structured-protocol | 分栏映射、条件与参数归属、来源锚点、覆盖检查 |
| Entry | LabNest 自定义 entry-triage 任务规范 | 对象候选、实际支持的动作、去重、字段变更 |
| 实验结果 | K-Dense statistical-analysis、scientific-critical-thinking；现有分析工具规则 | 数据/重复层级确认、计算适配器、解释结构、结果栏目映射 |
| 共用编辑验收 | 本项目 labnest-editor-qa | 编辑—采纳—保存—刷新—再次编辑—只读/导出回读 |

参考 K-Dense BYOK 的结构化下一步建议和由实际工具事件生成来源记录的思路；仅吸收需要的规范与机制，实施时固定上游版本并保留适用许可证。其 hash 一致性不等于科学正确性，第二个模型也不等于事实已经核实。

## 9. 分批交付与阶段出口

每批先写可失败的关键回归用例，再实现最小闭环；验收过一批才扩展下一批。以下是实施顺序，不是已完成清单。工期在第 0 批形成任务拆分后估算，避免把尚未核对的分析适配工作承诺为固定天数。

| 批次 | 交付范围 | 阶段出口 |
| --- | --- | --- |
| 0：稳定性与契约 | 固定四模块输入/输出/采纳规则；复现审核、来源、重复动作及失败状态问题；建立评测样例 | 空审核/过期审核不能放行；基础状态、版本和失败规则有自动化回归 |
| 1：共用采纳体验 + Entry | 以 Entry 验证可编辑建议、字段差异、选择采纳、重复/冲突处理和回读 | 一条真实记录能从生成走到编辑后选择采纳；未选字段不变化，重复请求不重复写入 |
| 2：实验结果首版 | 数值表全量读取、结构确认、质控、受支持的计算、图表、解释；一种 qPCR 导出适配；图片定性路径 | 一份完整数据与一份缺陷数据都跑通；结果可复算、缺陷可阻止错误推断、五栏目采纳正常 |
| 3：说明书完善 | 在现有两遍流程上接入共用采纳；参数归属和覆盖检查；相关入口统一 | 多体系/长文件/跨页表格例子可核对；错配不能被数字存在检查放过；草稿回读一致 |
| 4：研究方案完善 | 情境澄清、按需证据获取、内容版本审核、字段选择写回和可选新建实验 | 检索失败暂停或明确改变草稿范围；设计修改使相关审核失效；方案字段可直接采用 |
| 5：四模块联合验收与发布 | 重复真实模型评测、并发/失败回归、跨模块衔接；同一提交发布与演示 | 四模块关键场景过关，GitHub / 开发基线 / 3001 一致，形成验证与发布记录 |

结果 Copilot 已列为首轮可用交付的主体，不放到无限期的“未来扩展”。完整首轮完成条件仍包括四个模块；分批发布时明确哪些已交付、哪些未完成。

## 10. 质量验收与评测

### 10.1 自动化必须通过的场景

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| C01 | 输出非 JSON、字段错误或截断 | 不写入；一次修复失败后保留诊断并停止 |

| P01 | 空审核、缺关键字段、依赖循环 | 不允许进入可签署状态 |

| R01 | 完整数值数据与基准计算 | 行数、效应方向、样本数及统计结果匹配基准，在规定误差内 |
| R02 | 只有技术重复/配对缺失/单位混用 | 识别问题，阻止不成立的分析；仍可保存适用的描述性结果 |
| R03 | 后半张表含异常，或存在第二个工作表 | 按确认范围全量读取；不能只用 30 行预览下结论 |
| R04 | 图片或不支持格式 | 明示能力限制，无虚构数字、检验或已执行分析 |

| U01 | 四模块与现有同类页面对照 | 字体、语义字号、控件尺寸与视觉变量一致；无局部覆盖全站外观设置 |
| U02 | 建议编辑、选择、采纳及各种运行状态 | 操作层级明确，状态含义一致；无文字裁切、遮挡、焦点丢失或干扰编辑的布局跳动 |
| U03 | 主题、字体、密度与屏幕尺寸切换 | 全站设置生效；保持可读与可操作；长表格局部滚动，无整页横向溢出 |

对权限、请求幂等、版本冲突、必需字段和计算一致性这些确定性条件，验收集要求全部通过。科学解释另行人工核查，不以 schema 通过率代替内容正确率。

### 10.2 真实模型的稳定性

- 每模块先准备 10–20 个人工标注案例，含正常、歧义、缺资料、长内容、来源冲突和失败情况；至少留出未参与提示词调优的保留集。
- 对候选发布模型每例重复 3 次，记录首次通过率、修复后通过率、错栏、无依据新增、来源匹配、重复建议、需要的人工修改和耗时/调用次数；这是初始工程评测规模，不代表总体性能保证。
- 在评测集上要求关键数据错误、无来源数字、虚构引用、错误对象写入和失败误标完成为 0；出现即修复并回归。总体首次可用率暂定目标为 ≥90%，按模块及输入类型分别报告，不用平均分掩盖失败场景；需标明样本量与不确定性。
- 数值分析以固定基准数据和独立核对结果为准。不同模型可以解释措辞不同，但不能改变同一计算产物的数字、单位、样本数和方向。
- 检索评测保存来源快照和时间；对实时检索另测工具成功/失败行为，不要求不同日期返回完全相同的论文。
- 模拟模型用于验证流程和异常；真实模型用于验证输出质量。两类报告必须分开，不用模拟运行截图证明真实效果。

### 10.3 页面与保存验证

按 labnest-editor-qa 检查真实调用页面：桌面、平板宽度、手机宽度；键盘操作；建议编辑；未保存修改；保存/刷新/再编辑/只读显示；附件引用；受影响的导出。图片移动和附件复制分开验证，中文输入及触屏涉及真机的项目单列结果，未测则写未测。

UI 验收同时要求：

- 四个 Copilot 与现有同类工作页并排比较，检查字体、字号、字重、行高、间距、对齐、颜色、圆角、图标和按钮样式；共享组件与全站样式变量为主要依据。
- 至少覆盖默认及一种替代字体/密度组合、已支持的浅色/深色主题，以及桌面、平板、手机宽度；核对实际计算样式与页面截图。
- 检查初始、处理中、空内容、失败、待审草稿、编辑中、差异预览和采纳成功等状态；文字可读、主次操作清晰，来源和限制可查。
- 新增组件须有可追溯的共享样式依据；局部例外写明使用场景与理由。明显风格割裂、字号层级不一致或布局缺陷须修复后才算该批 UI 验收通过。

### 14.3 问题与推荐（Q331–Q342）

**Q331 K-Dense 技能怎么进入 LabNest。** K-Dense 的技能是写给能运行代码的智能体的：一份 SKILL.md 有几百行说明，另附 Python 脚本和参考文档。LabNest 的 Copilot 直接调用模型服务，不执行代码。推荐：
- **拆成任务规范**：每个 Copilot 步骤一份带版本号的规范，包括给模型的要点、输出结构、程序检查、一个正例和几个常见错误的反例。要点和检查标准从对应技能里摘取，逐条注明出处。
- **计算由程序做**：技能里的计算（随机分组、样本量、统计检验）改写成 LabNest 程序，用同一批数据核对结果。模型不做计算。
- **版本与来源**：每次运行记下用的规范版本。上游技能固定在某个提交（MIT 许可），在 AI 页面和规范文件里注明来源。

备选：把 SKILL.md 原文直接放进提示词。做得最快，但提示词长、费用高、输出更不稳定，脚本也用不上。

**Q332 哪个技能用在哪一步。** 推荐：

| Copilot 步骤 | K-Dense 技能 | 取什么 |
| --- | --- | --- |
| 研究方案 ② 假设与预测 | hypothesis-generation | 先列竞争解释，再选实验；写明主张类型和要估计的量；每个假设写出“成立时会看到什么、对立解释成立时会看到什么” |
| 研究方案 ④ 设计卡与规则 | experimental-design | 它列出的致命设计错误补进程序规则：实验单位、随机分配、区组与批次、多因素设计能否分开估计 |
| 研究方案 样本量 | statistical-power | 先定最小关注效应，再由程序算每组 n；模型只提议效应量和依据 |
| 研究方案 ⑥ 审查；结果解释 | scientific-critical-thinking；peer-review（本机未装，从上游取） | 偏倚、统计陷阱、证据层级作为审查评分表各维度的细则；意见必须可执行 |
| 证据账本 | paper-lookup、literature-review | 来源记录格式：数据库、ID、访问时间、相关段落、支持还是反对 |
| 实验结果 | statistical-analysis（本机未装）、statistical-power | 检验前先查适用条件；报告效应量和区间，不只报 P 值 |
| 说明书、Entry | 不用 K-Dense | 说明书用本项目的 labnest-structured-protocol 规范 |

备选：先只用在研究方案上，做到结果模块时再接。

**Q333 输出稳定靠什么。** 推荐每一步都走“约束 → 程序检查 → 修一次 → 记录”：
- **输出结构**：支持结构化输出的服务直接传入输出结构，本地仍严格校验。不合格就带着原因重问一次；还不合格就停在这一步，不显示“完成”。
- **示例**：每份规范附一个完整正例（如 SRGN 敲低设计），以及两三个常见错误的反例。
- **程序把关**：能算的由程序算，能查的由程序查，比如规则、单位、对象是否存在、数值在原文中的位置。模型只负责起草、提议和解释。
- **随机性**：服务允许时调低随机性。

备选：同一请求问三次，取三次一致的部分。更稳，但模型调用和等待时间都变成三倍。

**Q334 怎么衡量被采纳的概率。** 推荐：
- **逐条记录**：每条建议（设计卡、说明书条目、整理稿、结果解读）都记录生成后你改了哪些字段，以及采纳还是忽略。忽略时可以选一个原因：不对、不需要、已经有了、写法不好。
- **统计**：按“模块 × 规范版本 × 服务”统计采纳率、平均修改字段数和忽略原因。AI 页面为每个服务显示最近 30 天的数字。
- **只在本机**：统计不发给任何服务。

备选：不记录，只看评测集的结果。

**Q335 改过的和被忽略的内容怎么用来改进。** 推荐：
- **定期整理**：每攒够 50 条或每月一次，整理最常被改的字段和最常见的忽略原因。据此改规范、加程序规则或加反例，规范升一个版本。
- **先比后换**：新版本先在评测集上和旧版对比，不变差才换上。
- **不自动学习**：不自动把你的记录放进提示词。

备选：自动把你最近采纳的版本当作示例放进提示词。写法会更像你，但会把本地记录发给 AI 服务，例子也容易越来越单一。
