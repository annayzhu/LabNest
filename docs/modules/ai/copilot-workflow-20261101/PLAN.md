# 第一部分：说明书和图片识别

## 3. 现在怎么做、问题在哪

现在的流程：

1. 来源：PDF 文字、Word、文本，或照片转写。
2. 按写法读取，先给一个规则预览。
3. 点“用 AI 整理”：模型按“标题 / 说明 / 材料 / 步骤（体系、编号、仅…：）/ 结果（记录：）”排版，逐句照抄原文。
4. 逐行核对。
5. 由 `habitTextToDocument` → `convertLegacyProtocol` 读成规程，存为草稿。

“先整理成模板格式，再由程序识别”已经做了一半。问题在于：

1. **整理格式只是模板的一部分。**
   - 第 2 条规则让模型丢掉“产品规格、储存运输、常见问题”（`protocol-recognition.ts:118`），也没有目的和背景。
   - 首次使用前的配制、储存条件、安全提示恰恰常写在这些部分里。你手工整理稿里都保留了。
2. **“逐句照抄”与你要的整理稿相反。**
   - 规则要求逐句照抄原文措辞，英文保留英文（`:117`）；核对要求每行与原文重合 80% 以上（`:160`）。
   - 你手工整理的是中文、精简、带注释的稿子。按现在的规则，模型不能这样写；写了也过不了核对。
3. **核对只证明字和数在原文里出现过。**
   - 数值只要在全文任何地方出现就算通过（`:162`），所以 350/600 互换照样过。
4. **模型不知道这次要整理哪部分。**
   - 只提交 `sourceId`（`api/protocols/recognize/route.ts:22–24`）。细胞和组织两套流程、Mini / Midi / Maxi 由模型自己猜。
5. **长说明书被截断，也回不到原文位置。**
   - 超过 30,000 字截断（`protocol-recognition.ts:12`）。
   - PDF 各页合在一起，页码丢了（`protocol-source-text.server.ts:47`）；表格被展平。
6. **一次只能用一个来源。**
   - 说明书和快速操作卡的差异无处可写；你的手工稿里专门写了“原文差异”。
7. **还有一条不经过整理的路。**
   - “按目标设计”直接把方法原文变成规程草稿，Europe PMC 的每一段都成为一个步骤（`method-design.ts:97`），既没有整理也没有核对。
8. **没有真实评测**，改提示词或换模型只能凭感觉。

## 4. 设计：两遍整理、锚点核对、同一个读取器

```
来源（可多份）              第一遍：目录与范围           第二遍：按模板逐栏整理           识别（不用 AI）
PDF（保留页码）  ─┐       各部分 → 模板的哪一栏         说明 目的 背景 材料              与 Word 导入
Word              │       有几套流程、几个体系           步骤 结果 消耗规则               同一个读取器
文字 / 照片转写   ├──▶    哪些附录不要          ──▶     每行带原文位置〔p3:12–14〕 ──▶  → 编辑器预览
说明书检索        │       几份原文之间的差异                 ↓ 锚点核对（程序）           → 存为草稿
方法检索         ─┘       ▲ 作者确认                    ▲ 作者改整理稿、可下载 Word
```

### 4.1 来源

- 一次最多 3 份：说明书、快速操作卡、课题组笔记或照片。
- PDF 保留页码和行号；照片按页编号。
- “按目标设计”的方法原文、产品说明书检索的结果也走这里（4.6）。

### 4.2 第一遍：目录与范围

- 模型只读目录、各级标题和每页开头几行，用量很小。
- 输出：
  - 原文各部分（页码范围）对应模板的哪一栏，或者“不要”（订购、商标、参考文献；常见问题里的注意事项保留）；
  - 有几套流程（如“培养细胞 / 组织”），有几个体系（如 Mini / Midi / Maxi）；
  - 几份原文之间的差异。
- 作者在一个小表单里确认：要哪套流程、哪些体系、整理稿的语言、不要哪些部分。
- 只有一套流程、也没有体系时，自动跳过这一步。
- 规程名称和作者写的目标一并传给模型（补上 10-18 核查指出的缺口）。

### 4.3 第二遍：按模板逐栏整理

- 每一栏只发送选中的页，分批进行，不再整篇截断。
- 模型按 Word 模板 v1.0 的完整结构写，每行末尾带原文位置〔p3:12–14〕。
- 规则：
  - 数值、单位、浓度、试剂名、货号一律照原文写；
  - 选“中文整理”时，其余文字可以翻译和精简；选“保留原文”时仍逐句照抄；
  - 储存、首次使用前的配制、安全提示保留：配制写成准备步骤（“首次使用前：…”），储存与安全写进背景；
  - 厂家的典型产量、内毒素等写明“厂家参考值，不是验收标准”；
  - 几份原文之间的差异写进说明的“原文差异”，标“待作者选定”；
  - 材料表是“名称 | 用量 | 说明”：用量是每次用量（按体系写成 `a/b/c 单位`），包装规格和配制量写在说明里。

### 4.4 锚点核对（程序，不用 AI）

对整理稿的每一行检查：

- 原文位置存在；
- 这一行的每个数值连同单位都出现在它指向的原文里，而不是全文任意一处（单位先统一写法：µL / μl / ul，×g，°C）；
- 试剂名、货号也出现在指向的原文里；
- 体系取值的顺序与原文一致（这样能抓到 350/600 互换）；
- 原文里带用量的句子，如果没有被任何一行指到，列为“可能漏掉”；
- 整理稿与原文同语言时，再做现在的词重合检查。

没通过的行标黄“未核实”并写明原因。不阻止保存，未核实行数记入来源信息（与现在相同）。

### 4.5 整理稿就是导入模板

- 页面左边是整理稿，右边是原文；点位置标记跳到原文那一行。
- 可以直接改整理稿。
- “下载为 Word 模板”：与导入页提供的模板格式完全相同；在 Word 里改好再上传，走 Word 导入，不再经过 AI。
- “识别”就是用 Word 导入的同一个读取器生成规程，在真实编辑器里预览，然后存为草稿。

### 4.6 所有入口走同一条路

- 产品说明书检索、照片转写已经走整理流程，保持不变。
- “按目标设计”生成草稿时，把选中方法的原文（带链接和许可）送进这条流程，删掉 `designDraft` 里“每段一个步骤”的直接生成（`method-design.ts:97`）。

### 4.7 评测

- 用 10-29/30 手工整理的三份（NEL861、PureLink HiPure、慢病毒 shRNA FuGENE6）及其原 PDF 做第一批真实样本，只放在本机 `.local-runtime/protocol-recognition-eval/cases/`，不进仓库。
- 每份手工稿就是期望结果。按栏目逐项比对：步骤边界、关键参数、体系、条件、记录项、原文差异。
- 每次改提示词或换模型都跑一遍；结果记录服务、模型、提示词版本、分数和费用。

# 第二部分：研究方案设计工作流

## 6. 现在的 Copilot 怎么走、问题在哪

### 6.1 现在的流程

确认研究信息（方法、对象、样本、目标四个字段）→ 拆子问题 → 检索文献（模型调用检索工具，最多 8 次查询）→ 逐篇读论文里的实验（最多 20 篇，其中 8 篇读全文）→ 汇总成设计 → 写成建议（`copilot/types.ts:8`、`engine.ts`）。

采纳后有三种结果：
- 设计、材料与方法、验收标准、待确认项追加到各节末尾；
- 文献追加到“参考与工作笔记”；
- 每个实验建成一个“计划中”的空实验。

### 6.2 问题

1. **设计是从文献里“拼”出来的，不是设计出来的。**
   - 流程的核心是“别人做过什么 → 汇总”（`stages.ts` 的 `designPrompt`）。
   - 没有假设和对立解释，没有对照的逻辑，没有重复与样本量，没有随机、盲法与批次，没有分析计划，没有可行性和日程，也没有独立审查。
2. **没有文献就没有设计。**
   - 找不到核实过的摘录就停止（`engine.ts:53–56`）。今天的修复让它停下来而不是编造，这是对的。
   - 但新课题（如 SRGN 的候选结合蛋白）恰恰文献少，而对照、重复这些设计逻辑本来不需要文献。
3. **情境太薄，LabNest 自己的数据没用上。**
   - 确认只有四个字段（`types.ts:17–22`）。
   - 模型只能看到方案的标题、目的、假设、依据、设计文字，以及结果和实验的标题（`deps.server.ts:39–45`），而且只在拆问题时看。
   - 库存里的细胞系、质粒、抗体、引物，规程库，已有结果的数据，都没有用上。
4. **“核实”很脆，也不代表支持。**
   - “核实”只表示引文字符串出现在原文里。方法名要求逐字相等（`stages.ts:129`）：“Western blot”和“WB”“免疫印迹”对不上，就被降为“可选”并标“依据的论文里没有核实过的实验”。
   - 另一方面，引文存在不等于它支持这条设计。
5. **为了精简把科学内容截掉了。**
   - 对照、读出、判定标准各最多 3 条；每个子问题最多 2 项实验，总共最多 6 项；每个字段最多 120 字（`stages.ts:105`）。
   - 一个 siRNA 敲低实验就需要：NC siRNA、至少两条独立 siRNA、mRNA 和蛋白水平的敲低验证、转染试剂对照，最好还有拯救实验。3 条对照不够。
   - 精简应该靠结构（卡片、折叠），不能靠截断。
6. **写回是平铺文字，还会越堆越多。**
   - 建议是标题加段落，追加到各节末尾（`suggestions.ts:63`、`runs.server.ts:146–147`）。每运行一次就多一份“Copilot 实验设计（日期）”。
   - 方案的目的、假设、依据三栏不会被填写；分组、读出这类适合用表格的内容也只是文字。
7. **建出的实验是空壳。**
   - 只有标题和目的说明，状态“计划中”，日期取当前时间（`runs.server.ts:140`）。
   - 没有规程、分组、样本，也没有日程。方案和执行之间是断的。
8. **“调整方案”只是一句提示**（`stages.ts` 的 `context`）：不读现有内容逐条比较，也给不出改前改后。
9. **慢，而且贵。**
   - 一次约 33 次模型调用（`types.ts` 的 `estimateModelCalls`），每篇论文单独一步。
   - 必须用支持工具调用的服务。
10. **设置分散。** Europe PMC 的开关在“按目标设计”页的检索设置里（`CopilotStartForm.tsx` 的提示）。
11. **起草和检查是同一个模型、同一次调用**，没有独立的审查。
12. **界面**：一个很长的折叠面板，不少标签是英文；只能改子问题的文字；不能加入自己知道的论文（PMID、DOI 或本地 PDF）；采纳前不能修改设计。

## 8. 新的工作流：六步

### 8.1 原则

1. **情境卡是锚**：作者确认后，后面每一步都带上它；任何一步想改它，都要标出“偏离”，由作者决定。
2. **每步一个可以修改的成果**：下一步只读已确认的成果，不读聊天记录。
3. **AI 推进，人来放行**：机械检查自动做（字段齐全、PMID 能查到、样本量算好）；需要判断的地方必须由作者点确认。
4. **数字由程序算**：样本量、板位随机由程序算；不知道的值写成“待定”，不让模型编。
5. **证据机械核对**：每条引用绑定它支持的那一句；没核实的不进入依据。
6. **审查是独立的**：用单独的提示词，最好换一个模型；只看成果，按固定评分表打分，最多两轮。
7. **不替人选假设**：模型只列出来，选择由作者做。
8. **文献是证据，不是设计的来源**：没有文献也能做设计，只是相应条目标明“常规做法，未经文献核对”。

### 8.2 六步

```
研究方案 · 设计工作台                                        EXP 草稿 3 个 · 已签署 v1
① 情境卡 ✓ ─ ② 假设与预测 ✓ ─ ③ 证据链与子实验 ● ─ ④ 设计卡 ─ ⑤ 方法·可行性·日程 ─ ⑥ 审查与签署
┌───────────────────────────────────────────────────────────────────────────────┐
│ 主张：SRGN 敲低抑制 KYSE150 细胞迁移（必要性）                                    │
│ 最低可信证据：敲低效率（mRNA + 蛋白）· 两条独立 siRNA 表型一致 · NC 对照 · 拯救（推荐）│
│ 要排除：脱靶效应、转染毒性                                                        │
│ ┌ 实验块 ─────────────────────────────────────────────────────────────────────┐ │
│ │ 必做 1 敲低验证（qPCR + WB）   成功：两条 siRNA 敲低 ≥ 70%   失败：换序列或改 shRNA │ │
│ │ 必做 2 Transwell 迁移          依赖 1 通过                                    │ │
│ │ 可选 3 拯救（抗 siRNA 的 SRGN）  依赖质粒核查                                   │ │
│ └─────────────────────────────────────────────────────────────────────────────┘ │
│ 档位：(•) 标准  ( ) 轻量  ( ) 发表级                        [确认，进入设计卡]      │
└───────────────────────────────────────────────────────────────────────────────┘
```

**① 情境卡**（替代现在四个字段的确认）
- LabNest 先自动填（不用模型）：
  - 方案的目的、假设、依据和正文；所在项目；
  - 本方案和本项目已有的实验和结果（标题、判定、关键数值）；
  - 关联的规程；
  - 库存里与研究对象相关的细胞系、质粒（带核查状态）、siRNA 和引物、抗体；样本。
- 模型再从作者写的研究目的里补全，并指出歧义（保留今天修复的做法，如 ligation blot 的例子）。
- 字段：
  - 研究问题；
  - 主张类型：关联 / 必要性 / 充分性 / 机制 / 相互作用 / 直接结合；
  - 研究对象与候选；
  - 模型系统（细胞系、来源、STR 与支原体状态）；
  - 资源：已有 / 可以获得 / 没有；
  - 约束（时间、经费、仪器）；
  - 不做什么；
  - 成功的样子；
  - 已有的结果。
- 每个字段标“已确认 / AI 建议 / 待定”。
- 作者必须确认才进入下一步，且只问缺了会影响设计的字段。

**② 假设与预测**
- 模型列出主假设和 2–4 个对立解释，例如：siRNA 脱靶、转染毒性、过表达造成的假象、抗体非特异、参照基因不稳定。
- 区分性预测表：主假设预测什么、对立解释预测什么、哪个实验能区分、什么算“无法判断”。
- 可选的“证据边界”检索：快速查一次，填入证据账本（支持 / 反对 / 背景），并记下检索了什么。
- 作者勾选要排除的对立解释，它们变成对照或特异性实验。不打分，不替作者选。

**③ 证据链与子实验**
- 主张图：主张 → 最低可信证据 → 实验块；同时写出要排除的反主张。
- 用 LabNest 内置的“证据链模板”打底（Q302）。例如“基因功能（敲低）”模板写明：敲低效率要在 mRNA 和蛋白两个水平验证；至少两条独立 siRNA；NC 对照；推荐做拯救。
- 实验块按依赖排序：基线 → 操作是否成功（敲低 / 过表达效率）→ 表型 → 特异性或拯救 → 机制。
- 每块写成功标准、失败时意味着什么、备选做法。必做最多 5 块，其余为可选。
- 作者选档位（轻量 / 标准 / 发表级），系统只推荐一个。

**④ 设计卡**（每个实验块一张）
- 固定字段：
  - 实验单元与分析单位；
  - 因素与水平；
  - 分组表（组名就是 LabNest 实验里的分组名）；
  - 对照，以及每个对照排除的威胁；
  - 生物学重复和技术重复；
  - 样本量（Q305）；
  - 随机、盲法与批次（板位由板布局工具随机，图像定量盲法，记录批号与代次）；
  - 读出与时间点；
  - 分析计划（标准化、检验、主要比较、多重比较校正、剔除规则）；
  - 预先写定的判定标准；
  - 依赖哪个实验块。
- 规则检查由程序做，初版 12 条：
  1. 没有阴性对照或同期对照；
  2. 操作类实验没有安排效率验证，或表型排在验证之前；
  3. 只有一条 siRNA，又没有拯救；
  4. 过表达没有空载体对照；
  5. 把孔数或技术重复当作 n；
  6. 生物学重复少于 3（只提示）；
  7. 多组比较没写校正；
  8. qPCR 的参照基因少于 2 个，或没说明稳定性（转述 MIQE 2.0）；
  9. WB 没有上样对照，或定量没说明归一化；
  10. 图像定量没有盲法（只提示）；
  11. 判定标准缺失，或写在实验之后；
  12. 有的分组没有对应的处理。
- 取消今天加的数量截断（Q304）：卡片默认折叠，只显示一行摘要。

**⑤ 方法、可行性与日程**
- 每张设计卡的方法选择：列出考虑过的做法和选中的那个。依据先找 LabNest 规程库和库存说明书，再找文献（带原文位置）。
- 对应到规程：已有的直接关联；没有的标“需要规程”，链接到“识别说明书”或“按目标设计”。
- 物料清单与库存核对：已有 / 不足 / 没有。不足的生成采购申请草稿，不自动下单。
- 需要的样本和工具：板布局、配液卡、质粒核查。
- 日程初稿：各实验的日程段，以及实验之间的先后和继续或停止的节点（[多日排程](../../structured-protocol/multi-day-schedule-20261101/PLAN.md) Q266）。
- 风险登记：主要假设、风险 1–5、验证需要多久；最大的三个风险各设一个继续或停止的检验和备选。

**⑥ 独立审查与签署**
- 审查只看①–⑤的成果，用单独的提示词；可以在 AI 设置里选“审查用的服务”。用同一个模型时，提示“同一模型自审，独立性有限”。
- 固定评分表：对照是否充分、混杂与批次、伪重复、样本量依据、多重比较、结论是否过度、可行性、安全与伦理。
- 每条意见分严重 / 重要 / 次要，并指向具体的卡片和字段。
- 严重问题阻止签署，除非作者写理由豁免。最多两轮修改，剩下的写进“限制与依赖”。
- 签署：一次写回方案（Q309），建出计划中的实验（Q310），方案记为“v1 已签署”，并附 AI 使用说明（用了哪些服务和模型、哪些步骤由 AI 起草）。

### 8.3 证据账本与引用核对

- 证据账本的每一条：PMID 或 DOI、标题、年份、状态（已核实 / 待核实 / 已撤稿）、研究体系、它支持或反对的那一句、关系类型（方法依据 / 对象证据 / 背景 / 反证）、原文位置（逐字引文和来源段落）。
- 核对分三层：
  1. **存在**：PMID 或 DOI 能查到，并标出撤稿（用 NCBI E-utilities 查文献类型）；
  2. **出处**：引文逐字出现在摘要或全文里；
  3. **关系**：作者确认它支持的是哪一句、属于哪种关系。
- 方法名用同义词表比对（Western blot = WB = 免疫印迹 = western blotting……），不再要求逐字相等。
- 没核实的文献不写进依据，单列“待核实”。
- 作者可以自己加论文：输入 PMID / DOI，或上传 PDF。

### 8.4 写回方案

| 成果 | 写到方案的哪里 |
| --- | --- |
| 研究问题、主假设、依据 | 方案前提的目的、假设、依据三栏 |
| 主张图 + 设计卡 | “设计”：主张图一段，每张设计卡一张表（分组 × 处理 × 读出）加要点 |
| 方法与物料 | “材料与方法”：规程链接、物料清单（已有 / 不足 / 没有） |
| 判定标准与分析计划 | “验收标准” |
| 风险、终止条件、日程依赖 | “限制与依赖” |
| 证据账本（只取已核实） | “参考与工作笔记” |

- 写入前显示改前改后。
- 再次运行时，替换上一次 Copilot 写入的块（这些块的 ID 带运行编号），也可以选择两份都保留。不再在末尾越堆越多。

### 8.5 模型调用和费用

- 不检索文献时，一次完整的工作流约 8–12 次模型调用：①补全 1 次、②1 次、③1–2 次、④每张卡 1 次、⑤1 次、⑥1–2 次。
- 检索文献时另加约 1 次检索调用和每篇 1 次阅读；默认每次最多 8 篇、其中 3 篇读全文。
- 每一步开始前显示这一步大约调用几次；机械步骤（读 LabNest 数据、规则检查、样本量、核对 PMID）不调用模型。

### 8.6 落到代码（给实施时参考）

- 带版本号的任务规范放在 `src/lib/copilot/` 下，如 `plan-design-v1`。每个成果一个 zod 结构，每步一个提示词。
- 新增的检查程序：设计规则检查、样本量计算（两组 t 检验、单因素方差分析、配对）、PMID / DOI 核对、方法同义词表。
- 证据链模板是带版本的配置，可在设置里查看和修改。
- 今天的修复都保留，换成新流程的一部分：
  - 研究信息确认 → 情境卡；
  - 证据缺失就停止 → 证据账本的状态（缺证据不再停止整个流程，而是标出来）；
  - PubMed 排队与重试 → 原样保留；
  - 方法证据与候选证据的区分 → 关系类型。
- 旧的运行记录只读保留，可以查看，不能继续推进。
- 由 Codex 或接手的会话实施前，先核对 main 上 Copilot 的最新提交，避免与 Codex 同时修改同一批文件。

## 9. 结果回来以后（预留）

- 结果数据集回流后（[工具与实验联动](../../tools/experiment-linkage-20261101/PLAN.md) Q285），方案的每条判定标准旁显示实际值，并给出“支持 / 部分支持 / 不支持”的建议。
- 建议只引用数据集里的数值；AI 不下结论，由作者确认。
- 结论超出预先写定的范围时（如只做了关联却写成因果），审查规则会提示。

## 10. 问题与推荐（第二部分）

**Q300 工作流的骨架和入口。** 推荐：
- 按第 8 节做六步：情境卡 → 假设与预测 → 证据链与子实验 → 设计卡 → 方法、可行性与日程 → 独立审查与签署。替换现在“拆问题 → 检索 → 读论文 → 汇总”的阶段结构。
- 入口是研究方案页上的“设计工作台”：一个独立页面，左边是六步，右边是当前这一步的卡片。方案页上原来的长面板换成一行进度（“第 3 步，等你确认”）。
- 研究方案总览页的 Copilot 入口（新建或调整方案）都进这个工作台，不保留两套。

备选：保留现有阶段，只增加“设计卡”和“审查”两步。

**Q301 情境卡读哪些 LabNest 数据、发送什么。** 推荐：
- 读：方案前提与正文；本方案和本项目的实验与结果（标题、判定、关键数值）；关联规程；库存中与研究对象相关的细胞系、质粒（带核查状态）、siRNA、引物、抗体；样本。
- 只把摘要发给模型，不发原始数据文件和附件。
- 发送前列出将要发送的内容，作者可以去掉某项。

备选：只读方案本身。

**Q302 主张类型和证据链模板。** 推荐：
- 内置 8 类常见主张的模板：基因功能（敲低）、基因功能（过表达）、拯救、蛋白相互作用、直接结合、亚细胞定位、通路依赖、表达关联。
- 每个模板写明最低可信证据、必需的对照和常见的对立解释。
- 模板带版本，作者可以改，也可以新建。
- 写法沿用今天提示词里的区分：膜上结合、复合物关联、直接结合、因果作用分别表述。

备选：不做模板，全部由模型生成。

**Q303 假设和对立解释。** 推荐：
- 模型列出主假设、2–4 个对立解释和区分性预测表。
- 不打分、不排序、不替作者选（K-Dense 的原则）。
- 作者勾选要排除的对立解释，它们自动变成设计卡里的对照或特异性实验。

备选：只写一个主假设。

**Q304 设计卡和规则检查。** 推荐：

## 14. 做了什么

### 14.1 两遍整理（Q292、Q293、Q297）

- **第一遍：目录与范围**（`src/lib/protocol-recognition-scope.ts`）
  - 原文不超过 6,000 字时整篇发送；更长时只发每页开头几行和像标题的行（“Step 3:”“Day 2:”“Materials”“储存条件”等），上限约 14,000 字。46 页的 PureLink 手册发 12,494 字，74 页的 Gateway 手册发 10,761 字，都覆盖到最后一页。
  - 规程名称和作者写的“目标”（页面上新增的输入框）一并发给模型。
  - 模型返回 JSON：各部分（页码范围）对应哪一栏或“不要”；几套流程；几个体系；原文内部差异。读不出时，整篇当作一个“未归类”部分，照常往下走。
  - 有两套以上流程或两个以上体系时，页面弹出“目录与范围”表单：选流程、勾体系、选语言、逐部分勾选要不要；否则直接进入第二遍。整理后可以点“调整范围”重新选择。
- **第二遍：按模板逐栏整理**（`src/lib/protocol-recognition.ts`，提示词版本 `template-v1`）
  - 分四批，每批只发它需要的页：说明/目的/背景；材料；步骤；结果/消耗规则。材料和结果批也读步骤页（每次用量、记录项在那里）。两批同时进行，限两个并发。
  - 步骤页超过 36,000 字时按页分段整理，程序重新编号，只保留第一行“体系：”。不再有 30,000 字截断。
  - 每批先核对；有问题时把问题发回重做一次，保留较好的一次（与以前相同）。
  - 说明栏的“来源：文件名，读取第 x–y 页（共 n 页）”和“范围：流程；体系；语言；不含哪些部分”由程序写，不让模型写。
  - 模型写：体系对应、原文差异（标“待作者选定”）、目的、原理/储存/安全、“厂家参考值，不是验收标准”、材料“名称 | 用量 | 说明”（用量写每次用量，不同体系写 a/b/c）、步骤（体系行、编号、仅…：、首次使用前：）、结果（记录：/每个样本：）、可选的消耗规则。
- **语言（Q291）**：默认“中文整理”（数值、单位、浓度、试剂名、货号照原文，其余可翻译和精简）；可选“保留原文”（逐句照抄）。选择放在“用 AI 整理”按钮下方，也在范围表单里。
- `habit-v1` 存下的旧草稿就是普通规程，照常打开；来源信息里的 `promptVersion` 区分新旧。

### 14.2 原文位置与锚点核对（Q294）

- **页码与行号**（`src/lib/protocol-source-text.server.ts`）：PDF 按页保留，去掉页眉页脚和页码后每页从 1 编行号；Word 和纯文本是第 1 页；纯文本里的换页符分页。照片转写现在每张照片之间插入换页符，`p3:5` 就是第 3 张照片第 5 行。
- **位置写法**（`src/lib/protocol-anchors.ts`）：每行末尾〔p3:12〕、〔p3:12–14〕或〔p16:5, p20:7–8〕。模型读到的原文每行前面就是 `[p3:12]`。位置只在页面上，存规程和下载 Word 时去掉。
- **核对**（`src/lib/protocol-anchor-check.ts`），只对照这一行指向的原文行，不再在全文里找：
  1. 位置存在；
  2. 每个数值连同单位都在指向的行里（统一 µL/μl/ul、mL、×g/x g、°C/℃/“37oC”、min/minutes/分钟、h/hours/小时；“12,000”=“12000”；`10⁵` 是乘方；PDF 丢了上标的“7×105”“~109 cells”也认作 7×10⁵、10⁹；PDF 常见的“1OX”“300 μI”“TRIS-HCI”按 10X、300 μl、Tris-HCl 读）；
  3. 货号和带数字的名称（K2100-02、RW1、AR6、pLKO.1、15140-122）在指向的行里；整理稿与原文不同语言时，拉丁字母的试剂名、细胞名、缩写也要在；
  4. 体系取值的顺序与原文一致：同一行原文（表格的一行、一句话）给出几个值时按它的顺序；分散在几行时要能按原文先后找齐。范围的两端都算（“1–3 / 15–25”），原文自己的步骤编号“2.”不算数值。“原文差异”行并列两种说法，不查顺序；
  5. 整理稿与原文同语言时再查词重合：“保留原文”要 80%（与以前相同），“中文整理”60%（允许精简改写）；
  6. 读取范围内带用量的原文行，没有任何一行指向它，列为“可能漏掉”，在原文栏用黄色竖线标出。
- 没通过的行在整理稿里标黄，写明原因；不阻止保存，未核实行数记入来源信息（与现在相同）。
- 没有位置的文字（按写法读取后作者自己改的）仍用以前的全文核对。

### 14.3 页面与 Word（Q296）

- `src/components/RecognitionWorkspace.tsx`、`RecognitionScope.tsx`、`RecognitionDraft.tsx`、`recognition-draft.css`：
  - 左边整理稿，右边原文（按页、带行号，未读取的页变淡）；点整理稿行末的位置标记，原文栏滚到那几行并高亮；
