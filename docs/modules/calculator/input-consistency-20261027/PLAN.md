# 计算器输入区：示例菜单、对齐与选择控件统一

日期：2026-10-27  
来源：用户反馈截图（稀释与加药“向已有液体加药”、称量配液、连续稀释）  
基线：`main` 80552c15，开发目录与 `origin/main` 为 0/0

## 1. 用户反馈

1. “载入示例”只能载入一个示例，希望用下拉菜单选择多个示例。
2. 字段标签或选项文字换行后，输入框不再对齐（截图 1：已有液体初始浓度；截图 3：梯度方式选项）。
3. 分类选项有的是下拉菜单，有的是分段按钮，“摩尔浓度 / 百分浓度”又是文字链接，形式不统一。要求检查全部计算器。

## 2. 全量巡检（3002，1280×900，Chromium，逐个切换所有模式）

31 个独立工具全部实际打开。脚本对每个工具逐一点击每个分段选项、切换每个下拉选项，测量同一行各输入控件的顶端位置、标签和选项文字是否换行。

### 2.1 根因

| 编号 | 问题 | 根因 |
|---|---|---|
| R1 | 带单位的字段，标签换行 | 标签宽度只等于数字输入框，单位下拉框不计入；14 个汉字在约 150 px 内必然换行 |
| R2 | 同一行输入框上下错位 | 网格按顶端对齐，较高的标签把本字段的输入框推下去 |
| R3 | 分段按钮比相邻输入框低 8 px | 分段控件用 `fieldset/legend`，与 `label` 的间距不同 |
| R4 | 选项文字在按钮内折成 2–3 行 | 模式选项被放进半宽（配方页为三分之一宽）网格格子里 |
| R5 | 选择控件形式不统一 | 现规则按选项个数决定：2–3 个用分段按钮，4 个以上或含“请选择”用下拉；相关工具之间的切换是无选中态的文字链接 |
| R6 | 每个工具只有一个示例 | `exampleInputs` 是单个对象，多模式工具的其他模式没有示例 |

## 3. 待确认问题（推荐方案可直接实施）

**Q117 载入示例改为菜单。**  
推荐：“载入示例 ▾”打开示例列表，每项是一个具名场景（例如“向已有液体加药：10 mM 母液 → 10 µM，10 mL 培养基”）。多模式工具每个模式至少一个示例；连续稀释覆盖三种梯度方式及“从更浓母液制备”；单模式工具补到 2 个常见场景，确实只有一种场景的保留 1 个，并直接显示为按钮。示例由我按常用实验条件编写，每个示例都要有自动测试，证明能算出结果、没有报错。载入后仍标记为示例数据，不进入历史和实验记录（现有规则不变）。

**Q118 字段标签不再挤在输入框宽度内，同一行输入框始终对齐。**  
推荐：标签横跨“数值＋单位”整个字段宽度（解决截图 1）；同一行字段改为底部对齐，标签仍需换行时只向上增高，输入框保持在一条线上；分段控件与输入框使用同一套间距（消除 8 px 错位）。字段名称本身不改。

**Q119 选项文字不在按钮内折行。**  
推荐：所有“计算模式/类型”选择移出半宽网格，作为输入区顶部的整行分段控件（与“配液模式：单组/多组”一致，也符合 10-07 任务书“模式切换位于输入区起始处”）。选项文字单行显示；一行放不下时，整个按钮等宽换到下一行（每行 2–3 个），不把文字折断。

**Q120 选择控件按含义统一，不再按选项个数决定。**  
推荐：
- 改变输入内容的“模式/类型/方向”一律用分段按钮：稀释与加药的 5 种模式、单位换算的换算类型由下拉改为分段；Western Blot 的“Buffer是否已含还原剂”改为“否，单独设置用量 / 是，不再重复添加”两项分段，默认不选中，仍须明确选择后才能计算。
- 单位一律用下拉（数值旁单位、IC50/Bradford/ELISA 的浓度单位、MOI 的滴度单位、单位换算的原单位/目标单位），保持不变。
- 过长的选项名缩短，解释移入字段说明：“1:N稀释（占最终体积1/N）”→“1:N 稀释”，1/N 的含义放到该模式的说明中。

这条覆盖 10-07 任务书中“更多选项可用带标签的选择器”的规则。

**Q121 相关工具之间的切换。**  
推荐：称量配液与百分比溶液、PCR/Master Mix 与转染仍是独立工具（历史、预设分开保存），但切换入口改为同样外观的整行分段控件，显示当前选中项：“浓度类型：摩尔浓度 | 百分浓度”“反应类型：PCR / Master Mix | 转染”。不合并成一个工具。

**Q122 范围。**  
推荐：31 个工具全部适用，包括转染编辑器内部的分段控件、离线版计算器、手机宽度（390 px）和英文界面。按 10-07 的巡检方式，修改后重新跑全工具脚本，记录 1280/1440 桌面与 390 手机的结果和截图。

**Q123 发布。**  
推荐：先在 3002 给你验收；你确认后按标准流程提交 → GitHub main → 同步开发目录 → 部署 3001，三处版本核对一致后再报告完成。工作区里其他会话未提交的改动（CONTEXT.md、i18n.ts 等）不混入本次提交。

## 4. 实施记录（3002 验收通过，2026-10-29）

按 Q117–Q122 推荐实施，以下为与推荐的差异和实际做法：

- **Q117**：19 个多模式工具改为“载入示例 ▾”菜单，共 50 个具名示例（`src/lib/calculators/examples.ts`），每个模式至少一个；菜单外观与工具栏按钮一致（透明原生选择框覆盖在按钮上，键盘与读屏仍按选择框操作）。12 个单模式工具保留单个示例按钮，**未补第二个场景**，需要时再加。`calculator-engine.test.ts` 新增一项测试，逐个计算全部示例。
- **Q118**：带单位字段的标签横跨“数值＋单位”；输入网格底部对齐。反应配液“预混余量”的说明移到字段网格下方（否则会把同行输入框顶高）。
- **Q119/Q120**：判定规则集中在 `isModeField`（非单位的选择项）：一律分段按钮、独占整行、排在字段最前；单位仍为下拉。选项文字不折行，整个按钮换行。转染编辑器同一规则（“转染内容”6 项由下拉改为分段）。“1:N稀释（占最终体积1/N）”改为“1:N 稀释”，含义移入“稀释分母 N（母液占最终体积 1/N）”。
- **Q121**：两组相关工具切换改为“浓度类型”“反应类型”分段控件，带选中态，宽度不超过 28rem；导航名称（Solution modes / Reaction modes）不变，原有验证脚本仍可定位。
- `scripts/verify-calculator-refactor.mjs`（`npm run test:calculator:e2e`）改为通过菜单载入示例；其余带日期的历史验证脚本未改。
- 验证：31 个工具逐一切换全部模式，1280/1440/390 宽度下无行错位、无选项或标签折行、无横向滚动；英文界面抽查通过。单元测试全部通过；`test:calculator:e2e` 的示例与八个任务流程在 360/390 宽度通过，390 截图见 `evidence/`。
