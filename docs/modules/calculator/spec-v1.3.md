# LabNest Calculator v1.3 修改任务书

日期：2026-09-07  
用途：交给 Codex 执行的功能修复、布局优化与图标接入任务书。  
静态核对基线：`446bb9bf6ea5dd4f672bc5acd365dc8e4e3808b8`（PR #58 后本地版本）。  
状态：本文件是待实施规格，不是修复完成报告。本轮读取了四张用户截图、现有目录与相关代码；未复现用户设备上的运行环境，未测得性能结果。

## 1. 本轮目标与范围

修复手机与PC复制失败、缓存失败、重复或失灵的返回入口、工具切换与操作慢；将计算器首页改为按分类组织的紧凑 Bento Grid，并统一全部计算工具页。

本轮覆盖现有31个独立计算工具、计算器首页、最近使用、工具导航、共享表单和结果组件、相关外观设置及离线资源。既有两个旧入口别名继续兼容，不增加重复工具。保留 v1.0—v1.2 已通过的计算、历史保护、步骤归属、Run状态恢复与警告传递。

**缩放要求更正：真机验收最高160%，替代此前“真机真实200%”的要求。** 不因未完成真机200%而阻断本轮。此调整不要求限制用户缩放，也不能设置 `user-scalable=no`、人为锁定最大缩放或把字体缩小抵消放大。PC浏览器缩放与手机缩放分别记录。

推荐按两个可独立审查的PR实施：A修复复制、缓存、导航及定位性能问题；B完成首页、所有工具页和图标接入。两批均需页面证据，不能只报测试数量。

## 3. COPY：让复制真正可用

### 3.1 行为要求

1. PC、手机均提供清楚的“复制结果”按钮；按钮点击直接触发写剪贴板，不在前面插入网络请求或不必要的异步工作。
2. 写入成功后显示“已复制”；失败不得显示成功。复制内容包含结果、单位、条件、真实移液步骤、来源及全部警告，保留现有 `resultClipboard` 的计算含义。
3. 首选受支持的 Clipboard API。提取共享复制模块，供所有计算工具使用，避免各页维护一套实现。
4. 对API不可用或拒绝提供兼容降级。可按目标浏览器实际支持情况保留旧复制方法作为兼容分支；不能把已弃用方法当作唯一长期方案。检查返回值，失败继续降级。
5. 最后降级为可操作的复制面板：多行完整文本、清楚的边框与文字、可选择可滚动；“全选”按钮；PC提供快捷键提示、手机提供长按复制提示。不得只显示一个难以识别的小框，也不得自动反复弹软键盘。
6. 若权限拒绝后已失去用户激活，允许用户再点一次明确的复制按钮，不虚构后台自动复制成功。
7. 在真实记事本或其他可编辑输入区域粘贴验证；不得只测试被mock的 `writeText` 调用次数。保留结果失效时禁止复制旧结果的既有语义。

### 3.2 环境处理

读取实际部署协议、`window.isSecureContext`、浏览器与响应策略后再判断原因。HTTP内网地址通常不具备现代剪贴板和Service Worker所需条件；如实际使用此方式，部署整改应包含有受信任证书的HTTPS入口。不得通过要求用户关闭浏览器安全机制来验收。

对于嵌入页面，检查上层权限配置是否阻止复制，但没有嵌入证据时不要假设存在iframe。

## 4. CACHE：区分草稿保存和离线页面

### 4.1 对用户的表现

“输入草稿已保存”与“工具已可离线使用”是两种状态，不能混淆。刷新可恢复草稿，不代表断网能重新打开页面。

离线区默认紧凑显示状态，展开后有“准备离线使用”“重试/更新”“清除工具缓存”。运行时显示进度或阶段及禁用重复点击。清除工具缓存不得清除历史、配方或Run草稿。

缓存成功至少意味着：工具主页、当前工具、其必要脚本/样式/图标均已准备完成，断网后从主页能重新打开当前工具；若提供“全部工具离线可用”，则必须覆盖31个工具及所需延迟加载资源并逐个验证。只缓存当前路由时明确显示缓存范围，不能声称所有工具都可离线。

### 4.2 工程要求

- 统一处理注册、激活、消息确认和缓存阶段的超时/失败；监听器与MessageChannel清理；不能无限等待worker激活。
- 错误分为：环境不支持、注册或作用域失败、必要资源请求失败、空间不足、等待超时。向用户给出对应可执行提示；错误细节进诊断记录，不在主流程堆栈输出。
- 不以“HTTPS”解释所有异常；部署层核验实际worker MIME、路径、重定向及作用域响应头。
- 当前实现从 `performance.getEntriesByType('resource')` 收集已请求资源。这不保证覆盖未来路由或延迟模块，应生成明确的资源清单或等效可验证机制。
- HTML文档、Next.js RSC载荷和静态资源不可互相替代；不能用登录页或错误页响应充当成功缓存。检查重定向、响应类型与必要内容。
- 静态带内容哈希的资源优先缓存命中；导航采取有时限的网络尝试和明确离线回退。避免弱网时所有资源都一直等网络才回退，具体策略以路由/版本正确性为前提。
- 完成新版本所需资源后再切换，失败保留上一个可用版本；处理旧缓存清理、资源404与部署更新，不破坏当前历史。
- 离线资源按实际登录与数据范围隔离。已有Run快照可能含用户内容，须验证退出/换账号不会展示前一账号内容，不扩大缓存到无关API或写请求。
- 浏览器可能回收缓存，不承诺永久离线可用；再次打开时核验状态，不能仅靠一个本地“已缓存”标记宣告成功。
- 保留Run的独立离线写入队列与同步机制；缓存页面不能替代数据库同步，更不能自动重放所有请求。

## 5. NAV：手机只保留一个有效主返回入口

统一管理计算器页面导航，明确目的地，不单纯依赖浏览器历史。

| 当前页面/进入方式 | 主返回的目的地与状态 |
|---|---|
| 计算工具详情 | 返回计算器主页；恢复目录搜索、分类状态和滚动位置 |
| 计算器主页，从Run进入 | 返回原实验原步骤，保留备注、未保存输入与计时状态 |
| 计算器主页，普通工具入口进入 | 返回工具总目录 |
| 直接打开工具深链接，无站内历史 | 工具详情仍返回计算器主页，不跳外站或空白页 |
| 嵌入Run/孔板的工具 | 使用宿主关闭/返回语义，不意外改变整个应用路由 |

手机全局顶栏和计算器局部栏不能同时出现两个作用重叠的箭头。优先由统一页面标题组件承载当前页面的主返回，顶栏按路由避免重复。详情保留“返回计算器”语义；需要跨级返回实验时用明确文字菜单或次要入口，不能再造一个无说明的返回箭头。

外观：18—20px线性箭头，居中于至少44×44 CSS px触控区，轻量悬停/按压背景，不使用突兀的高窄描边框。`aria-label`明确返回目标，焦点可见。

排查失灵：实际点击命中元素、覆盖层、`pointer-events`、disabled、Link href、路由事件、未捕获异常、重定向及等待请求。不得以“删掉坏按钮”替代导航链验证。

返回不能等待服务器保存草稿完成。保留必要本地草稿，后台同步与导航解耦；避免同步写大历史导致阻塞。浏览器系统返回也需验证。

## 6. HOME：按分类构建紧凑 Bento Grid

### 6.1 信息顺序

顶部仅保留紧凑标题与搜索；其下常用任务；最近使用为轻量横排/网格；主体六个分类块；配方和历史置于紧凑折叠区。不要增加大标题横幅、介绍段落或装饰性留白。

每个分类一个有清楚边界的块，块内使用同一个 `CalculatorToolTile`：固定图标区＋短名称。取消当前每个工具占一整行的大卡片。桌面分类默认展开，避免隐藏工具。分组可非等面积，但不使用视觉顺序与键盘顺序不一致的瀑布流重排。

建议桌面12列外层网格：

- 第一行：配液占5列、细胞占4列、微生物占3列；块内分别按可用宽度采用3—4列、3列、2列工具。
- 第二行：核酸、蛋白、单位与设备各占4列；块内采用2—3列工具，较少工具不强行拉高。
- 配方与历史保持页底紧凑入口；不为它们另建大面积空卡片。

此为起始布局，按实际内容宽度调整；不得强行固定行高导致160%内容裁切。容器基于可用主内容宽度响应，而非只看整屏宽度，需考虑侧栏。

### 6.4 帮助、固定、最近使用

- 默认工具入口只显示图标和短名。桌面悬停与键盘聚焦显示完整名称、一次简短说明和一条使用建议；气泡不超出视口。
- 触屏点击工具直接进入，不把第一次点击吞掉用来模拟悬停。帮助由分类块可展开说明或独立帮助按钮提供；不能仅依赖长按。
- 固定操作采用独立可聚焦按钮或统一“管理常用”模式，不能把button嵌套在Link内部，也不能误触固定时跳转。
- 最近使用仅保留短名，可选显示实际结果摘要或时间；若摘要等于工具说明则不再渲染。用户只是打开而未计算时，不虚构结果摘要。去重同时覆盖中英文与旧数据。
- 搜索保留别名匹配与分类信息；筛选结果去重，清空搜索恢复原位置。常用/最近是有意的快捷区，不因此从完整分类目录删除工具。

## 7. WORKSPACE：全部31个工具页统一美化

### 7.1 标题与整体结构

同一行：返回按钮 → 工具图标 → 标题 → 右侧帮助/固定。工具图标不再单占一行。标题默认18—22px，32px左右图标垂直居中；标准宽度下保持紧凑同排。长标题或160%允许标题文字自然换行，但图标不另起整行、不截断关键信息。

图标/品牌Logo与对应标题使用统一横向布局。副说明至多一行，较长方法进入帮助，不在标题、输入区、结果区反复解释。

简单工具PC采用输入左、结果右，建议比例约1.1:1，内容最大宽度约1040—1120px；批量表格类允许更宽。手机单列输入后结果。空结果区不强行撑高，输入框较少时不要把卡片拉到整屏。

方法、设备与舍入、历史等默认折叠；关键安全提示、无效输入、缺少必要参数不能折叠隐藏。示例与草稿为次级操作，计算是主要操作。运行后手机将结果提示放到可感知位置，不能每改一位数字就自动滚动。

### 7.2 字段统一

建立共享 `CalculatorField`/`QuantityField`，优先从已有组件提取。相同类型统一高度、边框、圆角、标签间距与错误位置。

数值＋单位是一个整体字段组：PC总宽度建议240—280px，数值区域弹性伸缩，单位约88—104px；手机按实际列宽100%并受容器约束。特殊长单位可增加宽度或使用合适的可访问选择面板，不靠裁掉单位解决。

普通数值、短选择框与带单位字段遵循同一列宽基准。模式选择最长可跨两列，但不得所有输入默认拉满整张大卡。不同业务字段不必机械等宽，需在同一栅格上对齐。

- PC输入高40—44px；手机至少44px。手机输入文字默认16px，减少聚焦时浏览器意外放大。
- 标签位于字段上方；数值与单位底边/高度对齐，图标居中，错误提示不挤歪邻列。
- 数值允许需要的负号、小数和科学计数法，不能为了调用数字键盘破坏合法输入。
- 手机优先单列；成对的简短字段在足够宽度可双列，160%应自适应单列。不要使用全局 `transform: scale()` 压小页面。
- 结构化配方、样本行、标准曲线和分组编辑器全部纳入统一组件样式；表格局部可横向滑动，整个页面不得横向溢出。

### 7.3 每个工具的专门检查

| 工具id | 页面整理与必须保留的内容 |

| percent-solution | w/v、v/v、w/w切换清楚；实际取液与定容含义保持区别 |
| serial-dilution | 模式与体积含义清楚；结果完整显示来源、加入量及剩余量 |
| resuspension | 按量/质量模式显示必要字段；最终体积不误写成加入溶剂体积 |
| normalization | 批量输入局部表格；低浓度不可行行不消失；结果行与样本id对齐 |
| media-recipe | 基础液与添加组分层级清楚；定容/已有基础液模式不混淆 |
| buffer-recipe | 同一配方编辑器；组分单位、原始输入与输出完整 |

## 8. PERF：先测慢在哪里，再修复

对全部31项至少完成打开、输入、计算、返回的基本检查；对用户未指定名称的“几个慢工具”，按测量识别最慢项，不预先猜测根因。

记录设备、系统、浏览器、网络、构建版本、登录状态、是否冷启动、是否缓存命中。核心动作重复10次，报告中位数与最大值；更大的样本才用适合的分位数描述。不能用开发服务器首次编译代表生产性能。

建议验收目标（待实现后的实测值，不是当前成绩）：

| 动作 | 目标 |
|---|---|
| 按钮点击后的可见反馈 | 100ms内 |
| 已加载简单工具的数值输入 | 无明显逐字卡顿，交互延迟目标≤200ms |
| 热打开/返回目录恢复可交互 | 目标≤500ms |
| 简单本地计算 | 典型输入下目标≤200ms |
| 曲线拟合或图像类较重任务 | 超过300ms显示计算状态；可取消/忽略过期结果，主线程保持可操作 |

冷启动和弱网单列实测，不把上表作为所有网络环境的绝对承诺。

优先查：路由等待服务器、目录加载整个计算/拟合模块、主线程长任务、全历史反复序列化、重复请求、图片解码过大、同步存储、组件无效重渲染、网络优先缓存长等待。

目录元数据与重计算代码按需要解耦；体积或轨迹证明有必要时再延迟加载/Worker。预取常用路由需有预算，不预取31页全部大模块；离线准备则明确加载对应资源。草稿节流要处理离开前保存，不牺牲数据保护换速度。异步计算要防止旧结果覆盖新输入。

优化前后使用同设备同例题对比，保持方法版本、计算结果和警告一致。不能用骨架或动画遮住长时间不可操作而宣布性能改善。
