## 0. 执行摘要与证据边界

本轮需要解决六类问题：图标过于单薄；同类按钮的位置和形态不统一；单组/多组等切换入口不明显；下拉箭头贴边；说明性展开区域冗余；展开时文字与内容出现不必要的动画。

**请以反应配液为首个落地页面，再把同一规则应用于当前全部实验计算器。不能只修改截图里的一个页面。**

本任务书依据用户反馈及 `Screenshot 2026-10-07 at 16.44.36.png` 编写，原截图副本位于同包 `evidence/reaction-mix-before.png`。截图对应“反应配液”，可以直接观察到：

- 页面标题使用双试管细线图标，按钮与导航图标的视觉重量不一致。
- “单组配液 · 切换多组”外观接近普通文本；用户也报告了反向状态“多组配液 · 切换单组”的同类问题。
- “存为预设”“载入示例”“重置”“添加组分”等操作采用不同的图文组合，缺少明确的共同规范。
- `µL` 下拉框的箭头接近右边框。
- “余量与组分用量”“移液设备与舍入（可选）”使用展开入口，后者截图中为展开状态。

**静态截图无法验证动画、点击行为和其他页面。本交付没有修改应用代码，也没有宣称完成全工具实测。下面的全量检查与修复由执行 Codex 在真实运行环境完成。**

本任务不重开此前已完成的任务书；如与旧的局部样式要求冲突，以本次用户明确要求为准。历史记录中的工具数量只作检索线索，必须根据当前路由、导航和工具注册表重新列出清单。

## 2. 黑白图标：实心轮廓与留白

### 2.1 设计方向

- 采用黑白、实心轮廓、少量镂空的简洁图形，统一圆角、重心和视觉重量。
- 不再继续使用细弱的单线条图标，也不要只把现有描边整体加粗后当作完成重设计。
- 无渐变、阴影、纹理、噪点、彩色装饰或繁密的实验器材细节。
- 采用可缩放 SVG；深色按钮上使用反白图标，镂空部分应透明，不能用硬编码白色遮盖。
- 本轮“黑白”指图标体系，不要求把整个应用及语义状态颜色全部改成黑白。
- 操作图标仍配清楚的文字。图标不替代“添加分组”“添加组分”“计算”等动作名称。

### 2.3 接入要求

- 建立统一的语义映射与渲染入口；同一操作在所有页面使用同一图标，不逐页任意替换。
- 建议以 `24 × 24` 为源图标坐标；标题实际显示约 24–28 px，普通按钮约 16–20 px，按小尺寸视觉效果微调。这是本轮设计起点，不是外部标准声明。
- 校验 16/20/24 px 显示、浅底黑色和深底反白。必要时给小尺寸制作简化版本，不用堆叠细节保证辨识度。
- 有文字的按钮内图标对辅助技术隐藏；确需仅图标的按钮提供明确可访问名称，不能只依赖鼠标悬停提示。
- 保留清晰的悬停、聚焦、按下和禁用状态；不要通过图标位移、放大或弹跳表达这些状态。

## 3. 按语义统一按钮，而不是把所有控件做成一种按钮

统一的是“同一作用 → 同一形态、同一相对位置、同一名称规则”。不同复杂度的页面无需硬塞进相同绝对坐标。

| 角色 | 统一外观 | 统一位置 | 例子 |
|---|---|---|---|
| 主操作 | 现有主色实底＋清晰文字；统一圆角和高度 | 当前输入流程末尾 | 计算 |
| 区域新增 | 中性描边按钮＋新增图标＋对象名 | 对应区域标题右侧 | 添加组分、添加分组 |
| 输入载入 | 紧凑的次级按钮/菜单触发器；始终可识别为可点击 | 输入区标题旁，位于计算前 | 常用预设、载入示例、恢复草稿 |
| 输入管理 | 统一低一级按钮；与载入功能分清 | 输入区工具栏 | 存为预设、重置 |
| 模式切换 | 有边界、有选中态的分段控件 | 输入区起始处/相关模块标题附近 | 单组配液、多组配液 |
| 行操作 | 紧凑图标按钮或图文按钮 | 该行末尾，位置固定 | 复制行、删除组分 |
| 可选参数展开 | 单层统一触发条，标题＋静态状态箭头 | 输入区对应参数附近；全局设备设置在输入区末部、计算前 | 移液设备与舍入 |
| 简短帮助 | 字段旁轻量帮助入口或必要的一句话 | 被解释的字段旁 | 预混余量计算口径 |
| 结果操作 | 统一次级按钮 | 结果区标题/工具栏 | 复制结果、导出 |

具体要求：

1. “添加组分”与“添加分组”共享按钮样式，但必须保留不同对象名称，不能统一成含糊的“添加”。
2. 不再让同一新增操作在不同页面分别成为裸文字、带框按钮、悬浮圆按钮或一整行大卡片。
3. 桌面常规控件可从 36 px 高、8 px 圆角、12 px 水平内边距、图文间距 6–8 px 起步；窄屏触控目标建议不少于 44 px。以当前设计体系统一调整，不逐页硬编码。
4. 窄屏允许工具栏换行，保持操作顺序和区域归属，避免横向溢出、文字挤压和点击区域相互覆盖。
5. 区域标题、操作按钮、输入标签和图标应分别对齐，不混用不同垂直基线；长中文和单位也要验收。
6. 复用当前组件体系提取公共样式/组件；名称与文件位置按实际仓库确定，本任务书不假定某个现有函数或组件已存在。

## 4. 模式切换必须一眼可辨

把“单组配液 · 切换多组”和“多组配液 · 切换单组”替换为：

**配液模式：单组配液 / 多组配液**，两个选项呈现为同一分段控件。

- 两项均有清晰点击区域，当前项有明确选中背景/边界；不能只靠文字颜色变化。
- 不把“当前状态”和“操作入口”塞成一句普通正文；不使用“点击此处”弥补不可识别的设计。
- 鼠标、触控、Tab 和方向键/相应键盘语义均可操作；辅助技术能识别组名与选中状态。按照选用的控件语义正确实现，不混用不相符的角色。
- 对全工具中的模式、输入依据、计算方式等相似入口排查；两三个互斥选项优先明确的单选/分段控件，更多选项可用带标签的选择器，不机械全部改成分段按钮。
- 可点击的卡片、文字或图标必须有明确形态和焦点反馈，不能让用户靠试点猜测。

### 4.1 保护输入和结果

1. 单组与多组切换优先保留各自草稿；切回后应恢复原输入，不静默清空其他组。
2. 从多组进入单组时，明确单组当前对应哪一组；若尚无对应关系，先让用户选择使用的组，不默认合并全部组。
3. 不因 UI 切换静默改变样本数、反应数、余量或浓度依据。
4. 切换导致输入含义变化后，结果按项目已有失效规则处理；旧结果不能继续以有效结果身份复制或导出。
5. 不增加无意义的每次切换确认弹窗。只有确实无法避免的数据丢失行为才需要明确处理；优先通过保留草稿避免该情况。

## 5. 下拉箭头留白与选择器一致性

对单位、设备、计算依据、模式、预设等所有下拉选择器统一处理，不能只改截图中的 `µL`。

- 箭头的可见边缘距触发器右边框建议 12–16 px；图形约 14–16 px。数值是本轮视觉目标，按控件实际尺寸共同验收。
- 文本区为箭头预留约 36–40 px 的右侧空间；长文本不能进入箭头区域。
- 箭头在控件中垂直居中；同高度控件使用相同留白和箭头重量。错误、禁用、悬停状态不改变箭头位置。
- 单位选择器应保持紧凑，同时容纳 `µL`、`mL` 及项目实际存在的较长单位；不要为了放箭头把整个单位框无理由拉得很宽。
- 原生选择器和自定义选择器分别排查。避免原生箭头与自定义箭头重复；不要仅为调整边距换掉原本可靠的键盘或手机选择行为。
- 原生平台若不能稳定控制箭头间距，记录限制，并使用项目已经验证的选择器方案；不能依靠遮挡、裁切或覆盖点击区造成新问题。
- 弹出选项不被容器裁切，不超出窄屏边缘；选中后焦点保持合理，不造成页面异常跳转。

## 6. 精简“余量与组分用量”等说明性展开区域

先查看展开后的真实内容，再按下表处理，不按标题批量删除。

| 内容类型 | 处理方式 | 反应配液的例子 |
|---|---|---|
| 重复标题、重复表格解释、空泛说明 | 删除 | 仅重复“这里可设置余量和组分”的段落 |
| 理解字段所需的短解释 | 移到字段旁一句话或轻量帮助 | 预混余量的作用对象 |
| 低频的计算背景 | 放入单层、可选的计算依据/帮助 | 较长公式推导；仅在实际需要时保留 |
| 实际可编辑参数 | 保留输入并用准确标题命名 | 设备下限、移液步进 |
| 会改变配制或结果解释的条件 | 保留在相关输入/结果旁 | 未预混组分单独加入、补水口径 |
| 实际错误或超出设备能力 | 就近保留有效提示 | 负补水量、超出可执行移液范围 |

针对“余量与组分用量”：

1. 如果内部只有重复说明，删除整个展开入口及其容器，释放纵向空间。
2. 如果存在必要计算口径，把必要内容移到“预混余量”或相关组分控件旁。文案必须根据真实算法填写，不能为简短而改变余量作用范围。
3. 如果内部实际有参数，保留参数，改为准确的设置名称，不把参数当作“无关说明”删除。
4. 不新增“结果仅供参考”“请核实条件”等常驻空泛提示来替代原说明。
5. 对所有计算器采用同一判断方法，并在变更记录写明：删除了什么、保留或迁移了什么。

精简目标是减少无用内容，不是隐藏计算条件、单位、有效错误或实验操作差异。不要将探索性的数值结果加写成生物学结论。

## 7. 展开区域立即显示，标题不漂移

本轮用户明确要求：说明区以及“移液设备与舍入”等参数区，点击后直接展开/收起，不要展开动效。

### 7.1 必须取消的效果

- 内容区的高度、最大高度、透明度、平移、缩放、弹簧或缓动动画。
- 标题文字、图标、内边距或基线随展开发生的动画位移。
- 箭头旋转的过渡动画：允许展开前后立即换成不同方向，不允许旋转过程。
- 父级卡片、布局容器或共享动画组件间接触发的布局动画。
- `transition: all` 等导致点击后文字、间距或边框尺寸缓慢变化的通用样式。

取消动画应对所有用户生效，不能只在“减少动态效果”系统偏好下生效。

### 7.2 应保留的正确行为

- 展开内容出现后，下方内容自然向下排列；收起后自然回收空间。这种正常布局变化不算文字漂移动画。
- 同一视口、同一滚动位置下，触发条的标题左边缘、顶部位置和文字基线保持一致，只有下方内容显隐。接近页面底部时浏览器自身滚动校正应单独识别，不能用自动滚动掩盖错误。
- 保留清晰焦点、悬停和选中反馈；无动画不等于没有可操作状态。
- 展开不主动聚焦第一个输入、不自动调用平滑滚动、不把视口跳到别处。若原有浏览器自然行为造成明显跳跃，查明并修复，不盲目全局禁用滚动。
- 若以快捷键或其他入口收起了当前焦点所在的面板，把焦点安全移回触发按钮，避免焦点留在不可见元素。
- 收起后不丢失已填参数，不卸载后自动重置默认值；再次展开恢复原输入。
- 使用真实按钮和展开状态/关联区域语义；只做一层展开，不把一个普通设置再套两层目录。

### 7.3 “移液设备与舍入”的特定要求

- 它包含真实参数，应保留为计算前的可选设置，不按“删说明”要求一并删除。
- 可命名为“移液设置（可选）”，内部保留“设备下限”“移液步进”等真实字段，单位单独规范显示，例如“设备下限（µL）”。若现有名称更准确，可保留名称。
- 打开后立即显示，关闭后立即收起；标题文字、图标和控件宽度不产生动画变化。
- 如非默认设备/舍入设置仍生效，收起状态可显示一行紧凑摘要，使用户知道设置有效；默认且未启用时不要堆叠“未设置”等状态文案。
- 不擅自改变设备下限、步进或舍入算法。保留舍入前后必要的结果含义；UI 精简不得掩盖舍入后总体积或组分比例变化。

## 8. 反应配液的建议最终顺序

| 顺序 | 区域 | 内容与操作 |
|---|---|---|
| 1 | 页面标题 | 紧凑新图标＋反应配液；保留必要的导航 |
| 2 | 输入区标题与工具栏 | 常用预设/载入示例/可用的草稿恢复；存为预设、重置按层级排列 |
| 3 | 配液模式 | 清楚的单组配液/多组配液分段控件 |
| 4 | 反应与体积参数 | 样本数、重复数、对照数、预混余量、单反应总体积；必要帮助贴近字段 |
| 5 | 配液分组（多组时） | 标题右侧“添加分组”；各组操作贴近对应组 |
| 6 | 组分 | 标题右侧“添加组分”；保留紧凑表格及必要操作含义 |
| 7 | 可选移液设置 | 单层、立即展开；保留真实参数 |
| 8 | 主操作 | 计算 |
| 9 | 结果区 | 组与组分关系清楚；单位控件、复制和导出就近归位 |

根据单/多组的数据模型调整区域嵌套：组分若属于某个组，“添加组分”必须出现在该组范围内，不能让用户误以为会添加到所有组。不要为追求统一视觉而破坏操作对象关系。

此前已提出的窄屏“计算成功后切到结果”、输入变化后的旧结果失效、复制文本分组要求，应核对当前实现；已实现部分进行回归验证，尚未实现部分列明，不因本轮修改退化。已经正确实现的部分不另行重写。
