## 3. 开放问题与推荐方案（全部已确认）

### Q404 选择范围与操作入口怎样统一？

推荐：只对当前列表中明确勾选的条目操作；表头“全选当前列表”，显示已选数量，提供清空选择。更改搜索或筛选后清空选择，避免带入不可见条目。单次最多 500 条，超出时明确要求缩小范围，不自动截取前 500 条。

勾选后，在列表上方出现一条紧凑操作栏：修改、归档／恢复、导出、删除。没有选择时不占一整行。选中操作只保留这一个入口；原底部导出按钮和导入／导出菜单中的选中导出项移除，菜单保留导入、筛选结果导出、全部导出。

### Q405 删除遇到引用、执行证据时怎样处理？

推荐：沿用各类记录原有删除和回收站规则。执行前逐条说明将移入回收站、保留关联回收、改为归档、不能处理的数量和原因。原规则禁止删除而允许归档的条目，在本次预览中明确列为归档，用户确认后才执行。关联条目与附件原文件不级联删除。

删除确认需输入所选条数；列表不提供永久删除。回收站仍是恢复或永久删除的唯一入口。

### Q406 归档是否连带处理下游记录，是否提供恢复？

推荐：只归档选中条目，不连带归档其下的方案、实验、结果、样本或库存。实验自身对应的运行对象依照既有规则同步管理状态，不改步骤完成事实。

在归档列表提供“恢复”。对本批归档，保存归档前状态，恢复时还原该状态；旧条目缺少可靠原状态时，要求选择合法恢复状态，不猜测为“运行中”或“已完成”。连续重复归档按无变化处理。

### Q407 批量修改首批开放哪些字段、采用什么形式？

推荐：从“修改…”打开一个抽屉。公共字段可以统一设置；名称／标题在所选条目表格中逐条修改，避免把所有标题覆盖成一个值。

| 列表 | 推荐可改字段 |
| --- | --- |
| 项目 | 名称（逐条）、项目管理状态、标签 |
| 研究方案 | 标题（逐条）、方案管理状态、标签 |
| 实验规程 | 标题（逐条）、可用状态、标签 |
| 实验 | 标题（逐条）、标签；运行状态继续由执行流程修改 |
| 结果 | 标题（逐条）、追加备注；标签见 Q408 |

默认每个公共字段均为“不修改”；标签支持添加、移除、替换，替换需明确选择。备注采用追加方式，保留旧备注。空白输入不隐式清空字段。执行状态、审核／签署状态、正文、实验数值、单位、质控结论、步骤与方法快照保留原有操作路径。

规程标题沿用现有身份字段和版本规则，确保列表、详情一致；历史实验、已冻结来源和已审核版本不因改名被改写。修改后保持当前筛选条件与合理阅读位置。

### Q408 结果目前没有标签，要在本批补上吗？

推荐：本批先复用已有的标题和备注完成结果批量编辑，不新增结果标签字段或迁移。这样五类都能批量修改，并保持本批数据模型范围最小。

备选：同步为结果增加独立标签字段、单条编辑入口、筛选与导入导出支持。若选择此项，应采用只新增字段的迁移，旧数据默认空标签，不从正文自动推断。

### Q409 是否同时支持批量改所属项目、研究方案或实验？

推荐：本批保持原归属关系，归属调整继续使用现有单条操作。研究方案、实验、结果和规程版本之间存在联动及冻结规则，批量归属移动应有单独的影响预览，不与这次常用元数据修改混在一起。

### Q410 混合选中了锁定条目，或预览后记录又变化，怎么办？

推荐：确认页逐条显示“将修改／无变化／跳过”及原因，只对预览中符合规则的条目执行。被单条规则保护的条目不自动解锁或重开。

提交时重新核对所选条目和预览版本；任何影响本次计划的变化都停止本次写入并刷新预览，用户再确认。非预期写入失败整批回滚，不返回一部分成功的假象。重复提交同一请求不重复追加备注或活动记录。

执行后保留每条条目的前后值、操作结果和本批关联编号。删除、归档均先预览确认；修改展示实际变化后确认。默认不新增覆盖其他会话修改的整批撤销功能。

### Q411 导入格式与模板区域改成怎样？

推荐：上传／拖入成为主要区域，常用 Word 模板保持直接入口；JSON、Markdown 等放进一个“其他模板”菜单，去掉每种格式一张大卡片。写法说明继续按需展开。

先比较现有两个 DOCX 下载的实际内容：用途相同则合并入口；确有不同用途则在同一下载体系中明确命名，保留历史下载地址兼容。文件识别、校验、预览编辑、确认导入和所有支持格式保持原有语义。

同一共用导入组件的其他调用页同步整理，常用 XLSX／CSV 模板保持容易找到。

### Q412 “全站更紧凑”本批覆盖哪些地方？

推荐：建立逐页覆盖清单，检查项目、方案、规程、实验、结果、报告、快速记录、库存、样本、工具入口与设置的主要列表、新建／编辑、导入、抽屉和展开状态。

处理结构导致的空白、重复说明、重复入口、控件堆叠与对齐问题。先修共用组件，再修具体页面；正文、孔板、图表仍占主要空间。保持字号至少 12 px，长名称能完整识别，一列一个主要纵向滚动区，不以缩字或强设高度凑紧凑。

其他会话正在修改的工具内部区域先核对其最新方案和差异，避免重复覆盖；本批逐页记录已处理、未处理及原因。只调整呈现和操作组织，不重写科学计算、记录内容或业务结构。

### Q413 规程体系／条件区怎样解决左右失衡？

推荐：名称列按实际长名称自适应，选项及编辑按钮紧邻排列，移除“选项列吃满空白、编辑笔远在右边”的分配。长名称自然换行，选项文字不拆字；窄屏改为名称在上、选项在下。

编辑、只读预览、实验创建时的规程预览沿用一致的布局规则；体系／条件选择的含义和参数解析保持不变。待处理范围值仍按原业务条件提示，呈现为紧凑数量与就近处理入口。

打印使用稳定的文档版式，不跟随窗口尺寸和临时交互展开状态改变科学内容。
