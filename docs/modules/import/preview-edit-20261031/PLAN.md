# 导入预览：逐条补充、修改、删除，改好后一起保存

日期：2026-10-31
前一批：[库存手机入口、编辑合一、流水与整体 UI（Q189–Q200）](../../inventory/refine-20261031/PLAN.md)。Q201–Q214 在 [AI 订阅登录](../../ai/chatgpt-subscription-20261031/PLAN.md)。
状态：用户回复“Q215–Q224 按推荐”，在 3002 验收后回复“Accepted, release”。

## 1. 用户反馈（2026-10-31）

1. 预览里提示字段不全时，没法当场补充或修改，只能先保存再去编辑。
2. 希望预览后能逐条补充、编辑和删除，全部改好后一起保存。
3. 不只库存，凡是有“字段映射”的导入都要改。
4. “字段映射”太工程化，改成“导入预览”或更好的词。
5. 中英文两种界面都要顾到。

## 2. 现状

**哪些导入用到“字段映射”**

共用一个组件 `StructuredImportWorkspace`，8 个模块的表格或文档导入都走它：

| 模块 | 入口 | 文件格式 |
| --- | --- | --- |
| 库存 | `/inventory/import` 的“表格” | CSV、Excel、JSON |
| 实际购买 | `/purchases/import` | CSV、Excel、JSON |
| 项目 | `/projects/import` | CSV、Excel、JSON、Markdown |
| 研究方案 | `/research-plans/import` | Excel、JSON、Markdown、Word |
| 实验规程 | `/protocols/import` | JSON、Markdown、Word |
| 实验 | `/experiments/import` | CSV、Excel、JSON、Markdown |
| 结果 | `/results/import` | CSV、TSV、Excel、JSON |
| 报告 | `/reports/import` | JSON、Markdown、Word |

**现在的流程**
- 选文件 → 点“预览字段映射” → 出现“导入检查 · N 条记录”。
- 每条记录是一张只读卡片，下面列出错误和警告。
- 只要有一条出错，“确认导入”就不能点。
  - 唯一的办法是改原文件，再重新上传。
  - 而且不能先导入再改：有错误时根本保存不了。
- 只有库存和实际购买能在“字段识别详情”里改某一列对应哪一项。改完要再点一次预览。

**其他导入入口（不用“字段映射”）**
- 库存的 AI 识别（发票、送货单、标签、粘贴文字）：读出的草稿每行都能改、能删，但不能补一行。
- 样本的批量登记表：能逐行填、改、删，粘贴或导入文件后也能改，再一起保存。
- 序列导入：在文本框里直接改。

**中英文**
- 界面文字有中文。
- 但预览里的检查结果只有英文，中文界面也显示英文。例如：
  - “Unit is required.”
  - “Inventory location “冰箱 9” was not found.”
  - “Expiry date is not a valid date.”

## 3. 问题与推荐

**Q215 名称**

“字段映射”不再出现，统一叫“导入预览”：
- 上传区的按钮“预览字段映射”改为“预览导入 / Preview import”。
- 结果区标题“导入检查 · N 条记录”改为“导入预览 · N 条 / Import preview · N records”。
- 折叠区“字段识别详情”改为“表头对应 / Column headers”。
  - 摘要写“已认出 N 列 · 不导入 N 列 / N recognised · N not imported”。
  - “源文件列名”改为“文件中的列 / Column in the file”。
- 统计格“已识别字段”改为“已认出的列 / Columns recognised”。
- 记录卡里：
  - “核心字段”改为“基本信息 / Basics”。
  - “高级原始/系统字段”改为“原始数据 / Raw data”。
- AI 列建议的提示改为“请在‘表头对应’里核对”。

**Q216 逐条修改**

每张记录卡右上角有“修改”和“删除”。点“修改”，卡片里就地展开表单：

- **能改的内容**
  - 除正文段落和 JSON 以外的全部字段。
  - 正文段落（如背景、步骤、结果分析）只读，旁边写“正文导入后在编辑器里改”。
- **字段顺序**
  1. 必填项，带 *。
  2. 这一行已有值的字段。
  3. 其余空字段收进“更多字段”，默认折叠。库存有 26 个字段，不会一下全铺开。
- **输入方式**
  - 固定选项用下拉框，显示应用里的名字（如“精确用量”“到货”），不显示代码。
  - 库位用下拉框，列出在用的库位，外加“不指定”。
  - 类型和单位用输入框，带应用里已有的候选。
  - 日期用日期框。
  - 数字用文本框，保留原样。这样单位精度的检查照常有效。
- **出错时**
  - 表单顶部列出这一条的问题。
  - 空着的必填项描红。
- **完成与取消**
  - 点“完成”，修改记在页面上，并马上请服务器把整份预览重新检查一遍。状态、统计和每条的问题都随之更新。
  - 点“取消”，丢掉这次的修改。
- **改过的痕迹**
  - 卡片上改过的值旁边标“已改”。
  - 卡片底部有“恢复为文件中的值”。

**Q217 删除**
- 点“删除”，这一条不参加本次导入。
- 卡片收成一行：“第 3 条不导入 · 恢复”。确认导入前随时可以恢复。

**Q218 补充新记录**
- 表格类文件（CSV、TSV、Excel、JSON）的列表底部有“添加一条”，打开同样的空表单。
- Word 和 Markdown 文档不提供这个按钮。一份文档就是一条记录，补一条空文档没有意义。

**Q219 一起保存**
- 确认之前，数据库里什么都不写。
- 按钮写成“导入 N 条 / Import N records”，删掉的不算在内。
- 以下情况按钮不能点：
  - 有表单还开着。
  - 剩下的记录里还有错误。
- 导入仍是一个事务：要么全部成功，要么一条都不写。

**Q220 来源与留痕**
- 原文件照旧作为导入来源保存（校验值不变），文件本身不改。
- 每条新记录的导入日志写明：
  - 在预览里改过哪些字段，例如“预览中修改：单位、库位”；
  - 或者“预览中新增”。
- 本次导入的日志写明删掉了文件里的第几条。
- 预览时的修改并入确认凭证。改了内容就会自动重新检查，旧的预览不能拿来导入。
- 同一个文件仍然只能导入一次。
  - 所以在预览里删掉的行，之后不能再用同一个文件导入。
  - 要么当场改好一起导入，要么改了文件再导入。

**Q221 表头对应开放给全部模块**
- 现在只有库存和实际购买能改“某一列对应哪一项”。改为凡是表格类文件都能改，也就是 8 个模块里有 CSV、Excel、JSON 的那些。
- Word 和 Markdown 没有列，照旧只读。
- 改了某一列以后自动重新预览，不用再点一次按钮。
- “AI 建议对应”照旧只在库存里有。

**Q222 中英文**
- 新加的文字都有中英两种。
- 预览里的检查结果补上中文，消息里的字段名也译出来。例如：
  - “Unit is required.” 译为“请填写单位。”
  - “Inventory location “冰箱 9” was not found.” 译为“没有找到库位“冰箱 9”。”
- 用 `src/lib/i18n-import.ts` 单独存放，像 `i18n-inventory.ts` 一样并入中文表。这样少和 `i18n.ts` 里其他会话的改动冲突。

**Q223 其他导入入口**
- 库存的 AI 识别草稿加“添加一行”。补一行后，可以和读出来的行一起导入。
- 导入失败时，问题前面写“第 3 行：”，不再只写“3: ”。
- 样本批量登记表和序列导入已经能先改后存，不动。

**Q224 手机**
- 表单在手机上排成一列，输入框高 44px。
- “完成”和“取消”放在卡片底部。
- 卡片上的“修改”和“删除”是图标加文字，不只放图标。

## 4. 实现要点（确认后照此做）

- 修改以“补丁”的形式随文件一起发给服务器：哪一行的哪些字段改成什么、删了哪几行、新增了哪几条。
  - 服务器先读原文件，再套上补丁，然后检查。预览和确认都这样做。
  - 新函数 `applyImportEdits` 放在 `structured-files.ts`。实验规程改了“可用状态 / 审核阶段”时，重新计算导入决定。
- 预览给每条记录多返回一份完整的字段值（按字段键），供表单预填。现在卡片上的值截到 180 个字，不能拿来回填。
- 确认凭证的内容加上修改补丁。确认时 8 个模块都核对凭证（现在只有实验规程、实际购买和库存核对）。
- 预览和确认两个接口都不再只对库存和实际购买读取“表头对应”。
- 验收用 3002 的 `labnest-inventory` 预览（测试库 `labnest_inventory_20261030`）。至少走一遍：
  - 库存：缺单位、库位写错，当场改好；删一条；补一条；一起导入。
  - 实际购买、项目或实验各走一遍。
  - 实验规程用 Word 走一遍。
  - 中英文界面、手机宽度各截图。

## 5. 实现（2026-10-31）

**服务器**
- `src/lib/structured-import-edits.ts`（新）：
  - 修改补丁的格式和读取（`parseImportEdits`），按固定顺序整理，同样的修改总是得到同样的确认凭证。
  - 哪些字段能在预览里改（`editableImportFields`）：不含正文段落、JSON 和只用于导出的列。
  - 表单里哪些字段用下拉框（`importFieldChoices`）。
- `structured-files.ts` 的 `applyImportEdits`：
  - 在文件内容上套补丁：改过的值替换文件里的值，清空就是删掉；移除的行不再参加；新增的行接在最后。
  - 每条记录记下来源 `origins`：文件第几行、改了哪些字段，或者预览中新增的第几条。
  - 实验规程改了“可用状态 / 审核阶段”时重新计算导入决定。
  - 拒绝以下情况：行号超出文件、全部移除、Word / Markdown 文档新增记录。
- 预览、确认两个接口：
  - 8 个模块都读“表头对应”和修改补丁。
  - 确认时 8 个模块都核对凭证，凭证里包含修改补丁。
  - 库存的预览带回类型、单位、库位的候选。
  - 导入来源附件的 `metadataJson.previewEdits` 记下改过的行和字段、移除的行、新增的条数。
- `structured-import.ts`：
  - 预览的每条记录多带 `origin` 和完整的可改字段值 `fields`。
  - 新记录的导入日志写明：
    - `sourceRow`：文件第几行；
    - `previewChanged`：预览中改过的字段；
    - 或 `previewAdded`：预览中新增的第几条。
  - 实际购买的问题改用和其他检查一致的说法，不再直接显示校验器原文：
    - 原文例：“Too small: expected number to be >0”。
