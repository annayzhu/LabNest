## 1. 用户问题（2026-11-11）

> 为什么现在 3001 中的 EXP-008 · PAX2 and pMD2.G plasmid transformation 都执行完了，还显示进行中，没有显示完成？

## 2. 原因（3001 只读查询 + 源码）

- EXP-008：`status = running`，ProtocolRun 也是 `running`；两组（PAX2、pMD.G）× 9 步 = 18 步全部 `completed`。后 6 步是 11-06 在实验记录页勾的。操作日志里没有一次 `intent=complete`。
- 勾步骤只会把“计划中”改成“进行中”（`src/lib/execution-step.server.ts` 67；`src/app/experiments/[id]/run/actions.ts` 140–146）。“已完成”只由“完成执行”写入，因为完成时要核对本次用量是否扣库存、核对未解决偏差。
- 实验记录页没有完成入口。执行页在桌面有底部操作栏的“完成执行”；手机和现场模式只有一个默认折叠的“审核并完成本次实验”。

## 3. 开放问题与推荐（用户回复“按推荐”）

**Q462 完成方式。** 保留手动完成（保留用量和偏差核对）。必做步骤全部勾完后，实验记录页“执行管理”的状态处直接出现“完成执行”。不在勾完最后一步时自动完成。

**Q463 已勾完未完成的旧实验（如 EXP-008）。** 不批量改库。发布后这些实验会出现“完成执行”，由用户逐个确认。

## 4. 实现

| 位置 | 改动 |
|------|------|
| `src/components/CompleteRunButton.tsx`（新） | “完成执行”按钮。本次有未登记用量时先弹出原有的“按本次用量扣减库存？”；没有时弹出确认（结构化执行：完成后步骤、实际值和偏差不能再改；普通执行：之后取消勾选会重新变为进行中）。调用原有 `saveProtocolRunProgress`（`intent=complete`、`checklist=saved`、执行方案版本号），完成成功后才写用量。 |
| `src/app/experiments/[id]/page.tsx` | 在“执行管理”卡的“步骤 n/n”下面显示按钮。条件：记录未锁定、状态为计划中/进行中/失败、必做步骤（排除不适用和可选）全部勾完。 |
| `src/components/ProtocolRunProgressForm.tsx` | 手机和现场模式的完成区不再折叠，按钮文字统一为“完成执行”。 |
| `src/app/experiments/[id]/run/actions.ts` | `checklist=saved`：在加锁的事务里按已保存的勾选完成，不用页面上的旧勾选覆盖。必做步骤的判断移到 `requiredRunSteps`（`src/lib/structured-run.ts`），记录页和保存共用。 |
| `src/lib/i18n.ts`、`src/lib/i18n-run.test.ts` | 三条新文案的中文。 |
| `scripts/verify-complete-run.mjs` | 真实页面写入检查（只用于测试库）：结构化执行先问用量后完成、普通执行确认后完成、未勾完不显示、手机现场模式完成。 |
| `scripts/verify-complete-live.mjs` | 只读检查（拦截一切非 GET 请求）：步骤勾完的进行中实验在 1366/1440/1920 首屏显示按钮，点开先询问，手机现场模式有一个可见的完成按钮。 |

与推荐的差异：原计划删掉执行页的折叠入口。实测发现它是手机和现场模式唯一的完成入口（底部操作栏在这两处隐藏），删掉后手机上无法完成，所以改为保留并展开。每个界面仍只有一个完成入口：记录页侧栏、执行页桌面底部栏、执行页手机/现场模式完成区。
