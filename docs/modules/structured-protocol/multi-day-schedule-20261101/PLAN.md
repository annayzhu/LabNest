## 1. 用户需求（2026-11-01）

> 我觉得scinote有很多值得学习的地方 但我们也要超越它。首先我觉得他的实验规划工作流很值得学习。很多实验都是连续做好几天的，那在规划一个实验的时候，每天要做的事情，可以用可视化的流程图来展示，让用户一下就能看见整体的实验安排。安排好之后同步到日历上去。

## 2. 现状（源码事实）

**一个实验只落在一天**
- `Experiment.date`（`prisma/schema.prisma:480`）是唯一的计划时间。表单叫“计划日期”，默认取 UTC 的今天（`ExperimentForm.tsx:58`）。
- 没有结束日期、时长，也没有每步或每段的计划时间。
- 状态只有一套；一个实验只有一个 `ProtocolRun`（`:622`，`experimentId @unique`）。

**一个实验可以有多份规程**
- `ExperimentProtocolVersion.order`（`:516`）：转染、RNA 提取、qPCR 可以放进同一个实验。
- 执行页把它们连成一张清单，按规程顺序、分组、步骤顺序排（`experiments/[id]/run/page.tsx:97`）。
- 步骤只能在规程内部调顺序，而且只在开始前（`experiment-step-order.ts`）。

**等待和计时已经是结构化的**
- 计时来自时间参数块（单位到“天”，`protocol-chips.ts:279–294`）或规则的 `timerParameterId`（`structured-run.ts:92–107`）。
- 倒计时存在步骤上，手机和手表到点通知（`TimerCenter.swift:47`）。
- “过夜”“overnight”没有解析；等待就是一个带计时参数的步骤（模板的 wait 行，`protocol-docx-template.ts:93`）。
- 长计时按分秒显示：24 h 显示成“1440:00”（`step-timer.ts:15–20`）。
- AI 识别曾把“30–60 秒”读成 60 min（`field-mode-compact-20261029/PLAN.md` R2/R3）。自动排程依赖计时，所以必须让人看得到、改得了每段等待。

**日历**
- `/api/calendar/export` 支持实验、研究方案、月三种范围。
  - 每个实验一个全天事件，UID 为 `experiment-<id>@labnest`；
  - 前一晚 20:00 提醒（`calendar-export.ts:39–56`）；
  - 没有 SEQUENCE，也没有取消。
- 一次性导入时 iPhone 不认 UID，重新导入会重复。webcal 订阅：用户 2026-10-29 说“先不做”。
- 日期按服务器时区算（`overview-calendar.ts:27–29`，靠 docker 的 `TZ`），没有用 `lab-time.ts`。
- 首页月历、手机周历和“今天”：一个实验只占一天，不能跨天显示（`src/app/page.tsx:66–180`）。

**实验之间**
- 只有“续做”会建 `ItemLink continued_from`（`structured-run.server.ts:87–103`）；复制只记活动日志。
- 研究方案只把实验归在一起，不表达先后。
- Copilot 采纳的实验没有步骤，日期取当前时间（`copilot/runs.server.ts:140`）。

**没有的东西**：每段的计划时间、段与段之间的等待约束、跨天显示、按段的日历事件；没有图形布局库，也没有日历库（只有 date-fns 4）。

## 3. 对标 SciNote

### 3.1 SciNote 怎么做（公开资料，核对日期 2026-11-01）

- 一个实验是一张画布：任务是节点，任务之间有连线。“Edit workflow”调整位置和连线；另有表格视图，切换后画布不丢（[Updated experiment view](https://www.scinote.net/blog/updated-experiment-view/)）。
- 官方的规划建议（[Managing work in scientific laboratories](https://www.scinote.net/?p=1112)）：
  - 先在画布上画出流程、连好任务，规程细节以后再补；
  - 在可以长时间停下的地方切任务；
  - 一个任务约一天的工作量；
  - 在分支、需要看中间结果再决定的地方切任务；
  - 一个工作流可以跨几天到几周。
- 任务有到期日、标签和指派人；项目和实验有开始日、到期日和状态（未开始 / 进行中 / 完成）（[Knowledge base](https://knowledgebase.scinote.net/en/knowledge/tracking-project-status-progress)）。
- 仪表板上的日历标出有任务到期的日子，点开列出当天到期的任务（[Dashboard](https://www.scinote.net/blog/scinote-dashboard-introduction/)）。公开资料里没看到导出到手机或外部日历。
- 任务里关联规程库的规程，用 `#` 提到库存物品。

### 3.2 值得学的

1. **一眼看到整个实验**：画布把先后、分支、并行都画出来。
2. **切分原则**：一天的工作量、可以停下的点、要看结果再决定的点。这正好就是多日实验的天然分界。
3. **第二视图**：表格视图适合批量改日期。
4. **先排流程，后补细节**。

### 3.3 要超越的地方

| | SciNote | LabNest（本设计） |
| --- | --- | --- |
| 时间 | 画布只表达先后，不表达几点、隔多久 | 横轴就是日期；连线写“孵育 48 h（24–72 h）”；拖动时检查时间窗 |
| 从哪里来 | 手工建任务、手工填到期日 | 规程本身带着计时，自动排出初稿，人再调整 |
| 改期 | 逐个改到期日 | 改第一天，全部平移；拖一段，后面跟着走 |
| 日历 | 仪表板里的到期日 | 每段一个手机日历事件、前一晚提醒；下一期 App 写入系统日历，改期自动更新 |
| 当天 | 打开任务 | “今天”列出各实验今天的段，一点进入执行页的那一段；手表显示下一段和正在等待的计时 |
| 准备 | 任务里 `#` 提到库存 | 每段显示要准备的试剂、样本、板布局、质粒核查状态，缺了就标出来 |
| 规划 | 手工 | 研究方案 Copilot 建出的实验直接带日程初稿 |

## 4. 设计

### 4.1 概念

- **日程段**：同一个实验里，同一天连续做的一段步骤，或一件不在规程里的事。流程图上一张卡片。
- **第 N 天**：从实验的第一段算起；第一段所在的日期就是 `Experiment.date`。可以把任意一段设为 D0（如“转染日 = D0”，铺板就是 D−1），只改显示。
- **等待**：两段之间的间隔，来自前一段末尾的计时步骤（如“孵育 48 h”）。计时参数是范围时，范围就是时间窗（“24–72 h”）。
- **事项**：复苏细胞、换液、送测序、等引物到货之类。不在规程里，但占用某一天；可以勾完成，不计入规程步骤。
- **旧实验**：没有日程段的实验当作“第 1 天一整段”，现有页面照常显示。

### 4.2 自动排出初稿（程序规则，不用 AI）

1. 按执行顺序走一遍步骤，跨规程也一样。
2. 遇到计时步骤，满足以下任一条就在这里断开：时长 ≥ 4 h；或者按当前时间推算，计时结束晚于当天下班（默认 18:00）。
3. 下一段的开始时间等于计时结束；落在下班以后就顺延到下一个工作日 09:00。工作时间可以在设置里改。
4. 每段的预计用时 = 段内计时 + 每步 5 分钟（每步可改）。
5. 时间窗：计时参数是范围时，下一段必须落在窗内；单值的计时不留余量，可以在连线上放宽。
6. “过夜”：新增时长写法“过夜”，表示到下一个工作日上班，窗口为 12–20 h（Q261）。
7. 结果是：各段及开始时间、等待连线，以及超窗、周末、冲突的标记。用户确认后才保存。

例：转染（含“孵育 48 h（24–72 h）”）+ RNA 提取 + qPCR 三份规程，11/03 周一 09:30 开始：

```
第1天 11/03 一          第2天 11/04 二       第3天 11/05 三          第4天 11/06 四
┌────────────────┐                        ┌──────────────────┐   ┌──────────────┐
│09:30 铺板 6孔板 │──过夜(12–20h)──▶┌──────┴───────┐            │   │09:30 qPCR    │
└────────────────┘                 │09:30 转染     │──孵育48h──▶│   │ 板布局 ✓     │
                                   │ 配液卡 ✓ 质粒✓ │ (24–72h)   │   └──────────────┘
                                   └──────────────┘            │
                                                  ┌────────────┴─────┐
                                                  │09:30 收样·提RNA   │─────▶
                                                  │ TRIzol 余量不足 ⚠ │
                                                  └──────────────────┘
```

### 4.3 流程图（桌面）

- **横轴是日期**：第 1 天…第 N 天，下面写 11/03 周一；周末浅色底，今天一条竖线。
- **泳道**：单个实验一条。研究方案的“整体安排”每个实验一条（4.6）。各组时间不同（错开转染）时每组一条，放第 3 期。
- **卡片**：开始时间、标题（规程名 · 第几步到第几步，或事项名）、预计用时、准备图标（试剂、板布局、质粒、计算），以及状态（未开始 / 进行中 / 已完成 / 有跳过）。状态由段内步骤推出，不另存。
- **连线**：前一段指向后一段，标签写等待及其来源步骤（“第 6 步 孵育 48 h（24–72 h）”）；超窗变红。
- **操作**：
  - 拖卡片换天或换时间；
  - 点卡片打开侧栏：步骤列表、准备清单、改时间、拆成两段或并入前一段、备注；
  - “＋ 事项”。
- **列表视图**：同样的数据按时间排成表，可以直接改时间。学 SciNote 的第二视图。

### 4.4 手机和手表

- 手机是竖向逐日列表：“第 2 天 · 11/04 周二”下面是卡片。不做拖动，改用“改到…”菜单。
- “今天”（手机首页和桌面今天面板）合并各实验今天的段，按时间排。点一段直接进执行页的这一段。
- 手表显示下一段的时间、名称，以及正在等待的计时（如“孵育还剩 31 h，周三 09:30 收样”）。

### 4.5 改期与执行

- 改第一天的日期：所有段一起平移。
- 拖一段：默认它和后面的段一起移，间隔不变；也可选“只移这一段”，这时检查时间窗。
- 已完成的段锁定，不能拖。
- 实验进行中改期要写一句原因，记为步骤事件 `schedule_changed`。沿用修订号检查和行锁（`CONTRACT.md:25`）。
- **执行页按段分节**：“第 2 天 · 转染”下面是这一段的步骤；当前段展开，其余折叠成一行。做完一段后显示下一段的时间。
- **按实际计时提示**：后续段依赖的计时开始后，按实际结束时间算出建议，只提示不自动改。例：“按实际计时，收样建议改到 11/05 09:40，是否调整？”

### 4.6 研究方案的“整体安排”

- 方案页新增“整体安排”：本方案所有实验的日程段，每个实验一条泳道，横轴相同。
- **实验之间的先后**：如“EXP-013 在 EXP-012 第 3 天之后开始，至少隔 1 天”。前一个实验改期，后一个跟着提示。
- **决策点**：前一个实验写了判定标准（如“敲低效率 ≥ 70% 才做表型”）时，后一个实验的段显示“待判定”；判定通过后才变为正常状态。
- Copilot 建出的计划中实验直接带日程初稿（见 [Copilot 工作流](../../ai/copilot-workflow-20261101/PLAN.md)）。

### 4.7 日历

- **.ics 改为每段一个事件**：
  - 有开始时间的段是定时事件，事项和没定时间的段是全天事件；
  - 标题如“EXP-012 第2天 转染（第 1–6 步）”；
  - 描述里写步骤摘要、准备清单、执行页链接（直接定位到这一段）；
  - 提醒：保留前一晚 20:00；可选开始前 15 分钟；
  - UID 按段：`block-<id>@labnest`，带 SEQUENCE。
- 导出入口不变：实验页、研究方案页、月历页头（`CalendarExportButton`），不新增第二个导出入口。
- 真正的同步（改期、删除都能自动更新）放下一期：iPhone App 用系统日历接口（EventKit）写入单独的“LabNest 实验”日历（Q267）。

### 4.8 提醒与冲突（只标记，不阻止保存）

- 同一时段两段重叠（同一个人做不了两件事）；
- 周末或下班以后；
- 等待超出时间窗；
- 这一段需要的库存不足、样本还没产出、板布局没建、质粒没有核查（见[工具与实验联动](../../tools/experiment-linkage-20261101/PLAN.md)）。

### 4.9 不重复的入口

- 新建实验表单的“计划日期”改名“开始日期”；保存后可直接“安排每天的事”打开日程图。不另设第二个日期字段。
- 实验详情页的日期显示改为“11/03–11/06 · 4 段”，点开就是日程图。
- 日历导出仍用现有按钮和对话框，只是内容改为每段一个事件。

## 5. 问题与推荐

**Q259 日程放在哪一层。** 推荐：
- 放在实验里：一个实验可以跨多天、包含多份规程，日程段把它的步骤分到各天。
- 研究方案页汇总本方案全部实验的日程，并可以设定实验之间的先后（Q266）。
- 理由：LabNest 的实验是一次具体执行，带规程快照、分组、样本和用量。转染、收样、qPCR 拆成三个实验，会把同一批样本和分组拆散。

备选：学 SciNote，一天一个实验（任务），研究方案就是画布。

**Q260 初稿怎么来。** 推荐：
- 按 4.2 的规则从规程的计时参数自动排出，人再拖动调整，确认后保存。
- 断开的阈值：计时 ≥ 4 h，或者结束时间晚于下班。工作时间默认 09:00–18:00、周一到周五，可以改。
- 每段都能看到断开的原因（“第 6 步 孵育 48 h”），排错了能找到是哪个参数。

备选：不自动排，全部手工建段。

**Q261 “过夜”和时间窗。** 推荐：
- 时长写法新增“过夜”：到下一个工作日上班，窗口 12–20 h。编辑器、Word 导入、AI 整理都认这个写法。
- 计时参数是范围时（“24–72 h”），范围就是下一段的时间窗。
- 超出窗口时连线变红并说明，但允许保存（有时只能这样排）。

备选：不加“过夜”，让作者写成“16 h”。

**Q262 流程图的样子。** 推荐：
- 桌面按 4.3：横轴是日期，卡片是日程段，连线标等待；可拖动，另有列表视图。
- 手机按 4.4：竖向逐日列表。
- 自己画（CSS 网格加 SVG 连线），不引入通用流程图库：横轴固定是时间，用不上自由布局。

备选：学 SciNote 做自由画布（不以时间为轴），用 React Flow（MIT）。

**Q263 改期的规则。** 推荐：
- 改第一天：全部平移。
- 拖一段：连同后面的段一起移；也可选“只移这一段”。
- 已完成的段锁定。
- 进行中的实验改期要写原因，记为步骤事件。

备选：任何时候都只移被拖的那一段。

**Q264 数据怎么存。** 推荐：
- 新表 `ExperimentScheduleBlock`，一个迁移，不改旧数据。
  - 字段：实验、标题、类型（步骤段 / 事项）、覆盖的步骤、开始时间、是否全天、预计用时、前一段及最小 / 最大间隔、间隔来源、备注、修订号。
  - “覆盖的步骤”按步骤的稳定标识记录。分组复制出来的步骤自动跟着所在的段。
- `Experiment.date` 继续表示第一天，保存日程时同步更新。月历、导出等旧代码不受影响。
- 能按日期范围查询，月历和“今天”跨实验取段时不需要逐个读 JSON。

备选：存进 `ProtocolRun.executionPlanJson.schedule`。注意它的 zod 对象会丢掉未声明的键（`structured-run.ts:11–44`），要先改 schema。

**Q265 事项。** 推荐：
- 可以在任意一天加“事项”：复苏细胞、换液、送测序、等试剂到货等。
- 事项可选关联库存物品或样本，可以勾完成，不进规程、不计入步骤数。
- 常用事项可以存成快捷项，下次一点就加。

备选：事项必须写成规程步骤。

**Q266 研究方案的整体安排。** 推荐：
- 按 4.6：每个实验一条泳道；可以设实验之间的先后和最小间隔；前一个实验有判定标准时，后面的段显示“待判定”。
- 先后关系存在日程段上（“在 EXP-012 某段之后”），不用 `ItemLink`。

备选：方案页只做只读汇总，不设实验之间的先后。

**Q267 日历怎么同步。** 推荐：
- **本期**：.ics 改为每段一个事件（4.7），时间按实验室时区，前一晚 20:00 提醒保留。导出对话框继续写明“一次性导入，改期后需要重新导入”。
- **下一期**：iPhone App 用系统日历接口写入单独的“LabNest 实验”日历。改期、删除在 App 下次同步时更新；不需要订阅地址，也不受“只能在实验室网络里刷新”的限制。第一次使用时请求日历权限。
- **webcal 订阅继续不做**：只能在实验室局域网刷新；没有登录，订阅地址不设防；iPhone 默认去掉订阅日历的提醒。和 2026-10-29 的结论一致。

备选：现在就做 webcal 订阅（2026-10-29 提出的方案：每个研究方案一个订阅，另有“全部计划中”的订阅）。

**Q268 冲突和缺口提醒。** 推荐：
- 按 4.8 在卡片上标记：时间重叠、周末和下班后、超出时间窗、库存不足、样本未产出、板布局未建、质粒未核查。
- 只标记，不阻止保存。
- 研究方案的整体安排和“今天”里同样显示这些标记。

备选：只检查时间，不检查准备。

**Q269 时间与时区。** 推荐：
- 所有日程计算用 `lab-time.ts`（Asia/Shanghai）。

## 7. 验收要点（建议）

- **自动初稿**：上例三份规程排出 4 段（铺板、转染、收样提 RNA、qPCR）；每条连线写明来源步骤；“过夜”和“48 h（24–72 h）”的窗口正确。
- **改期**：改第一天，全部平移；拖“转染”，后面一起移；“只移这一段”超窗时变红；已完成的段不能拖；进行中改期要求写原因并留下事件。
- **执行**：执行页按段分节；按实际计时出现调整提示，不自动改。
- **日历**：导出每段一个事件，导入 iPhone 后时间正确（Asia/Shanghai）；没有日程段的旧实验仍是一个全天事件。
- **旧数据**：已有实验在详情、执行、月历、导出中显示不变。
- 测试库照惯例从正式库克隆；开发工具不写 `labnest` 正式库。

## 8. 不做什么、风险

## 9. 第 1 期实施记录（2026-11-01，未提交）

**数据**
- 新表 `ExperimentScheduleBlock`，迁移 `20261101200000_experiment_schedule` 只建表，不改旧数据（Q264）。
- `Experiment.date` 跟随第一段：保存日程时同步为第一段的北京日期（UTC 零点，与表单存法一致）。

**排程规则**（`src/lib/experiment-schedule.ts`，纯函数）
- 自动初稿、拖动与连带移动、标记（超窗、早于前一段结束、非工作日、工作时间以外、与其他实验重叠）。
- 北京时间固定按 +8 h 计算（没有夏令时）。
- 每段的“覆盖步骤”记步骤的稳定标识（`protocolStepRef`，自定义步骤用行 id），分组复制出的步骤自动跟随。

**等待从哪里来**（`experiment-schedule.server.ts` 的 `stepWait`）
- 结构化规程：计时规则或时间参数块；范围就是时间窗。
- 写成文字的旧规程：读步骤文字里的时间（与编辑器识别参数块的规则相同），例如“培养12–24 h”。
  - 以“、”或逗号列出的时间点（“0、24、48、72、96 h”）不算等待，那是检测时间。
- 步骤文字里有“过夜 / overnight / O/N”，且没有 4 h 以上的时间：等到下一个上班时间，窗口 12–20 h。
  - 早上开始的过夜放宽到次日上班，以免初稿自己就超窗；跨周末仍会标出。

**页面**
- `/experiments/[id]/schedule`：
  - 流程图：按天分列、卡片、箭头；等待写在后一段卡片顶上，如“等待 第 2 步 · 12 h（12–24 h）”；
  - 列表视图；
  - 侧栏（窄于 1280 px 时为底部面板）：改日期和时间、预计用时、时间窗、拆段、并入前一段、移出日程、说明；
  - “添加事项”、“重新排初稿”、工作时间设置（存本机浏览器）、保存条；
  - 手机上按天竖排，空白天隐藏，用面板改日期。
- 实验详情的“执行管理”：显示“日程 11/03–11/06 · 4 段”，或“11/03 · 安排每天的事”，链接到日程页。新建和编辑表单的“计划日期”改名“开始日期”。
- 执行页按段分节：
  - 当前段展开，其余段一行，点“展开”才显示；折叠的步骤仍在表单里，提交不受影响；
  - 现场模式的步骤栏和手机单步视图也显示“第 N 天 · 日期 时间”；
  - 从“今天”或日历点进来的步骤（`#step-…`）会展开它所在的段。
- 首页：
  - “今日计划”按段列出：时间、段名、实验；没有日程的实验照旧；
  - 月历里有日程的实验按段显示在各天；
  - 手机“今日实验”先列今天的段，再列没有日程的实验，以及两段之间仍在进行的实验。
- 日历导出：有日程的实验每段一个事件。
  - 有时间的段写成 UTC 定时事件，事项为全天事件；
  - UID 为 `block-<id>`，SEQUENCE 取保存时间；
  - 描述里写实验名、步骤和链接；
  - 前一晚 20:00（北京时间）提醒；可选“开始前 15 分钟”；
  - 其余实验仍是一个全天事件；
  - 导出对话框说明会导出几个事件。

**改期与留痕**
- 已完成的段不能移动，也不能改动其中的步骤。
- 进行中的实验移动已保存的段，要写原因。原因记在活动日志 `experiment_schedule_saved`。
- 保存带并发校验：别处改过后再保存，提示“日程已在别处修改，请刷新后再改”。
- 编辑表单改开始日期 = 整份日程按天平移；有已完成段时拒绝，并提示去日程图里改。

**其他**
- 复制实验：日程一起复制，从下一个工作日开始，事项不带完成状态。
- 计时超过 1 小时显示“5 小时 20 分”，超过一天显示“2 天 3 小时”。
- 新建表单默认日期取北京时间的今天。
- 日历导出按北京时间计算日期。
