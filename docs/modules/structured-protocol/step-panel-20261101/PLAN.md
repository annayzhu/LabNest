## 1. 原因（3001 只读核对，1440 px 与 390 px）

- **R1 “必需操作”是步骤状态行，不是标题。** `StructuredStepRecord.tsx` 第 87 行的 `<p role="status">` 只写本步状态：完成 / 已跳过 / 待确定 / 可选 / 必需。必需是默认情况，这一行没有提供新信息。它也没有任何样式，继承现场模式的 `.ln-bench { font-size: 1.08rem }`，实测 17.28 px、正文色，看起来像一个空标题。
- **R2 “跳过操作”是浏览器原生折叠。** 同一文件第 99 行的 `<details>` 没有样式，显示原生 ▶ 三角，字号同样是 17.28 px。位置在步骤中部，与它真正的含义“不做这一步”无关。这个动作与“确认完成本步骤”是二选一，却离那个按钮最远。
- **R3 记录的三个入口是三种不同元素。** `ProtocolRunProgressForm.tsx` 第 285–289 行里：
  - “添加观察”是 `Link`，“实验结果”是 `a`，都只有文字，没有边框；
  - “测量值”是 `MobileMeasurementCapture` 自带的按钮，有边框，图标在上。

  三者是并排放的，不是有意区分。整行又直接接在工具行下方，样式相近，所以看不出这是“记录”展开的内容。
- **R4 桌面宽度下“测量值”点了没反应。** `MobileMeasurementCapture.tsx` 的弹层带 `lg:hidden`，宽度 ≥1024 px 时不显示。实测：1440 px 下弹层不可见，390 px 下可见。

## 2. 待确认问题

**Q243 步骤状态行。** 推荐：
- 删除“必需操作”行，必需是默认，不显示；
- 只显示例外情况，放在“第 N 步”旁：可选步骤标小标签“可选”，已跳过显示“已跳过 · 原因”；
- “待确定 · …”（不能完成的原因）移到“确认完成本步骤”按钮正上方，用小号警示色，说明按钮为什么不可用。

备选：保留状态行，改为小号灰色标签。

**Q244 跳过放哪里。** 推荐：放在“确认完成本步骤”下方，作为次要文字按钮“跳过本步…”。点开后原位出现原因输入框和“记录跳过”；已跳过时显示“撤销跳过”。同时去掉步骤中部的折叠。

备选：放进“记录偏差”折叠里。

**Q245 “记录”的三个入口。** 推荐：“记录”改为点开的菜单，复用页面右上 ⋯ 菜单的同一组件 `useAnchoredPopover` + `.ln-actions-menu`。三项样式统一，都带图标：
- 添加观察
- 测量值
- 填写实验结果（跳到页面底部）

不再在工具行下面多出一行卡片。

备选：保留展开行，改成浅底色的子面板，三项同样带边框；或把“添加观察 / 测量值”直接放进工具行（共 5 个按钮）。

**Q246 桌面“测量值”无反应（缺陷）。** 推荐：桌面宽度改为居中对话框（与“离线使用本次实验”同一样式 `.ln-run-dialog`），手机仍为底部弹层。

**Q247 本步需记录的数值。** 指规程为本步列出、点“保存实际值”的字段。推荐：
- 样式改成紧凑行：标签在左、输入框在右，用现场模式的小号控件字体；
- 位置不变，仍在步骤内容和工具行之后；
- 文案“Skip this operation / 跳过操作”改为“Skip this step / 跳过本步”。
