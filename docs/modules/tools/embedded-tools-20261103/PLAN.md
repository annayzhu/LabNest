## 1. 用户意见（2026-11-03）

> “/”中已经有板布局了，这一点你应该发现并且提醒我。qPCR 的板布局是外部工具，功能重复，且突然只加一个 tool 也很奇怪，既然要嵌入，那么应该单独一个 tools 的分类，把 tools 有的工具都做成可以嵌入的。

## 2. 现状（源码事实）

### 2.1 “/”菜单

写作编辑器的列表在 `src/components/WritingCommandMenu.tsx:21-44`，分组是每项的 `group` 字符串，新增分组不需要改菜单结构。

### 2.6 自由板布局的配液（2026-11-03 在 3002 实测）

用户补充：“板布局中其实还涉及配液，自由板布局的配液请你也检查一下，一起优化。”

**位置和布局**

| 检查项 | 实测 |
| --- | --- |
| 配液卡片 | 在右栏第三张。1366×768 下卡片从 1113 px 开始，要在右栏（672/1610 px）里往下滚 |
| 96 孔板，1366×768 | 孔板从 549 px 开始，固定 100%，第一屏只能看到 3 行，没有“适合窗口” |
| 宽屏，1920×1080 | 工作区限宽 1480 px，两侧各空 220 px |
| 滚轮 | 在孔板上用于缩放（`app.js:2263`），会拦住页面滚动 |
| 字号 | 150 处文字有 122 处小于 12 px，最小 9.5 px |

**抽屉里的问题**

- 一个抽屉里是两套界面。基础、转染、梯度、药物、归一化是自由板布局自己的；Master Mix 是 LabNest 计算器，以 iframe 嵌入。
- 打开 Master Mix 时高亮的是“基础配液”，标题也重复（“配液计算”和“反应配液”）。预混余量和单反应总体积是空的，组分表只有表头。
- 细胞铺板、水凝胶、杀灭曲线、MOI 四个计算器只在主页面卡片上有按钮，抽屉顶部没有。
- 药物要在文本框里按固定顺序写一行：“名称,母液,最高,最低,点数,生成方式,参数,复孔,加药体积,溶剂,母液溶剂%”。
- 结果区有 6 个并列操作，“保存到项目”和“确认写入孔板”是两步，容易只做一步。
- 孔位预览把内容截断成“Drug A · 100 · …”。
- 体积显示 `3.4375 µL`、`1,096.5625 µL`，超出实际移液精度。

**数值（只核对了两组；后来查到一个错误，见第 7 节）**

- 药物默认示例，按手算核对第 1 级：`1000 µL × 1.10 × 1000 / 10000 = 110 µL`，稀释液 990 µL，孔内溶剂 1%，与界面一致。
- 同一体系（24 反应、每反应 10 µL、余量 12%）：LabNest 计算器得到预混液 241.92 µL、Master mix 134.4 µL、引物各 5.376 µL、水 96.768 µL，和 qPCR 工具保存的结果相同。

**没有跑到的部分**：转染、梯度稀释、基础配液、浓度归一化的计算结果，跨板汇总，“复制表格”粘贴到 Excel。

**结构上的情况**

- 配液计算有四套：`calculator-engine`、自由板布局的 `liquid-core` 和 `preparation-kernel`、qPCR 的 `reactionCalculator`、CNV 的 `reactionCalculator`（CNV 只看到打包产物和文件名）。
- 默认余量不同：qPCR 12%，自由板布局 10%。
- 配液到不了记录。`plate-layout.ts` 里没有任何配液字段，所以从规划器备份导入“板布局”时，配液不会带过来（读代码得出，未实际导入）。
- `free-plate-integration.test.ts` 要求工具文件与上游发布包逐字节一致，而本机没有找到上游源码（`~/Desktop/Tools` 下只有离线包）。

## 3. 目标

在任何写作文档里输入“/”，都能看到一个“工具”分类，内容和工具目录一一对应。工具从当前位置打开，已有信息自动带入，完成后结果存回这个位置，之后能再次打开继续编辑。

新增工具时只需要登记工具并接上同一座桥，不再改编辑器。

## 9. 修复：同一文档只能插入一个（用户 2026-11-04 报告）

原因：工具结果、板布局插入后占掉了那一行空段落。它是这一段最后一块时，下面就没有可点的行，打不出“/”。板布局点“完成”后还会选中整块板，这时打字会替换掉这块板。

修复（`src/lib/editor-block-line.ts`）：
- 工具结果、板布局、文件、表格的后面和两个相邻块之间，编辑器始终留一行空段落；这一行不写进保存内容。
- 工具保存或板布局点“完成”后，光标落到下面一行，可以接着打“/”。
- 选中块时打字，文字进入下一行，块不会被替换；删除仍要明确操作。

实测（3009，基于 main `fb1ea959` 加工作目录改动，合成数据）：
- 脚本 15 条路径通过。其中报告连续 3 个 qPCR 排板；快速记录连续 3 块板加 3 个 qPCR 排板；同一结果里 2 个 qPCR 分析加 2 个 CNV 分析，文件各不相同，刷新后都在。
- 修复前，同一脚本在第二次“/”处失败。

已知不足：
- 工具保存后约半秒内立即打字，第一个字符可能丢失（脚本里出现过一次，加 400 ms 间隔后不再出现）。

## 10. 发布前审查修掉的缺陷（2026-11-04）

发布前做了一次独立代码审查，下面几条是读代码确认后修掉的：

- 旧的本机草稿会悄悄回退更新过的记录，表单值（含结果的测量值）也一样。现在草稿绑定记录的保存版本，版本变了就丢弃；没有改动不写草稿；恢复草稿时提示，并可放弃。
- 在段落中间打开工具后，后半段被挪到本段末尾。现在新段落留在原位。
- 工具保存会丢掉旧结果存在列里的数值、把未保存的段落误报为冲突。现在合并前按表单的方式整理服务器文档（`src/lib/tool-remote-document.ts`）。
- 新建结果页面用过后再填，内容被丢弃却显示成功。现在拒绝并提示打开已保存的结果。
- 工具文件计入快速记录的附件上限，多插几个就存不了。现在不计。
- 规划器超过 6 个参数时，板图静默少一列。现在在方法说明里写明哪些参数没显示。
- 工具保存和正式保存可能互相覆盖。现在工具保存也锁行。
