## 2. 现状（源码事实）

### 2.1 现有工具

工具登记在 `src/lib/tool-manifest.ts:4–98`：规划 3 个、计算 1 个、分析 3 个。`tool-manifest.test.ts` 把数量写死为 7，加工具要改测试。

| 工具 | 形态 | 数据进出 | 和 LabNest 的联系 |
| --- | --- | --- | --- |
| 自由板布局 | 外部产品的发布副本（`public/tools/free-plate-layout/release.json`），浏览器 IndexedDB | CSV、SVG、XLSX、JSON v2 备份 | 唯一的 postMessage 桥：在孔上打开计算器，结果写回孔（`labnest-bridge.js:15–31,79–96`）；JSON v2 与文档里的“/板布局”双向转换 |
| qPCR 板布局 | 单个离线 HTML（约 1.8 MB），iframe | 每板 Excel、批量 ZIP | 从实验进入时带入样本（`?experiment=`），靠向工具内的输入框注入文字（`EmbeddedSampleImport.tsx:13–16`）；什么都不回传 |
| CNV 板布局 | React 打包产物，iframe | XLSX、QuantStudio 样本表 | 同上，靠选择器 `textarea.bulk-input` 注入 |
| qPCR 分析 | 单个 HTML（约 2.5 MB），iframe | 读仪器导出，输出 QC 与分析表、图、XLSX | 只能手动把工作簿作为附件上传成“结果”，数值不读（`analysis-results.ts`） |
| CNV 分析 | 静态 HTML/JS，iframe | 读 QuantStudio 导出与布局，输出 11 张表的 XLSX | 同上 |
| 计算器 | LabNest 内的 React 页面，31 种计算 | 历史与预设存在浏览器 | 见 2.2 |
| 可视化 | 独立仓库和部署，新标签页打开 | — | 按设计不传数据（`visualization-link.ts:1`） |

### 2.2 已经接通的联动

- **计算器“记录到实验”**：在执行页的步骤里打开计算器，结果由服务器重算核对，写成一条“计算”类结果，并留下步骤事件（`api/mobile/calculations/route.ts:17–23`）。
- **规程里的计算参数块**：7 种计算可以写进规程，在执行准备时确认（`protocol-calculations.ts:27–49`）。
- **配液卡**：规程算出用量，执行时确认，回执存进 `executionPlanJson`（`run-mix.server.ts:27`）。
- **“/”引用**：样本、库存产品、库存批次（`record-references.ts:5`）；样本页和库存页显示“记录中提到”。
- **“/板布局”**：正文里一行 `<!--labnest-plate:…-->`，可以引用样本；与自由规划器的 JSON v2 互转（`plate-layout.ts:149–239`）。
- **用量与扣减**：规程材料带库存批次，执行完成时写库存流水（`run-materials.ts:86–156`）。

### 2.3 缺口

1. iframe 里的工具（qPCR、CNV、分析）不能回传；带入样本靠工具内部的页面结构，工具一升级就可能失效。
2. qPCR、CNV 规划器只导出 Excel，所以只能作为附件，不能变成板布局块，也回填不了样本“所在孔”。
3. 分析结果的数值没人读，研究方案的判定标准对不上数据。
4. 计算器不能从库存读浓度、从质粒读长度，只能手填。
5. 工具和日历、日程没有关系；“这天要用哪张板、哪管质粒”没有地方显示。
6. 实验只能产出样本，不能产出库存批次（例如大提得到的质粒）。
7. “/”引用不了质粒图谱和实验。
8. 没有一处能看到“这个实验用了哪些工具、产出了什么”。

## 3. 对标

- **SciNote**：任务里关联规程、用 `#` 提到库存物品；工具类功能靠外部集成。
- **Benchling**：分子工具和样本登记在同一个平台，是标杆；但它是云端、英文、按席位收费。
- **LabNest 的路线**：工具不是外挂，而是实验的一部分。带着实验进入，结果存回实验；而且出现在日程卡片、执行页、文档和样本上。

## 4. 设计

### 4.1 五条原则

1. **在实验里打开工具**：带着上下文进来，包括实验、日程段、步骤、样本（ID、名称、分组、顺序）、相关库存批次和引物。
2. **结果存回原处**：不用导出再上传。
3. **一个成果多处可见**：日程卡片、执行页的步骤、文档“/”、样本的“所在孔”、实验页的“工具”栏。
4. **工具读 LabNest 的数据，并写明来源**：例如“浓度 512 ng/µL，批次 2311A，10/30 测”。
5. **不新建平行的存储**：每类成果落在已有的落点，实验页只做汇总（Q282）。

### 4.2 联动地图

| 工具 | 读入 | 写回 | 出现在 |
| --- | --- | --- | --- |
| 质粒工作台 | 质粒产品与批次、引物产品、测序附件 | 序列版本、特征、核查记录、图谱快照 | 产品页和批次页、转染步骤、日程卡片、文档 |
| 计算器 | 质粒长度、批次浓度、样本数和分组 | 计算结果和步骤事件、配液卡 | 执行页步骤、准备清单 |
| 自由板布局 | 实验样本（带 ID）和分组 | 板布局块或附件 | 文档、样本所在孔、执行页、日程卡片 |
| qPCR 板布局 | 样本、分组、引物产品（靶基因与参照基因） | 板布局（新增 JSON）和 Excel | 同上 |
| CNV 板布局 | 样本、探针 | 板布局和样本表 | 同上 |
| qPCR 分析 | 板布局、仪器导出 | 结果数据集（Cq → ΔCt → ΔΔCt）和工作簿附件 | 结果页、研究方案的判定 |
| CNV 分析 | 同上 | 结果数据集（拷贝数） | 同上 |
| 可视化 | 结果数据集 | 图（附件） | 结果、报告 |

### 4.3 一个例子：SRGN 过表达后测 qPCR

1. 研究方案里，Copilot 建出实验“SRGN-3×FLAG 过表达后 qPCR”，日程初稿为 4 段（[多日排程](../../structured-protocol/multi-day-schedule-20261101/PLAN.md)）。
2. 第 2 天“转染”卡片显示：质粒批次 2311A“已核查：信号肽–3×FLAG–成熟链连接区”；配液卡未建 ⚠。点一下，转染计算器带着质粒长度、批次浓度和 6 个孔打开，确认后配液卡存回这一段。
3. 第 4 天“qPCR”卡片显示：板布局未建 ⚠。点一下，qPCR 板布局带着 6 个样本和 GAPDH、SRGN 两对引物打开，完成后板布局回到实验，样本页显示“所在孔 A1–A3”。
4. qPCR 分析导出的结果表解析成结果数据集，对回 6 个样本；研究方案的判定标准（如“SRGN 相对表达 ≥ 5 倍”）旁显示实际值。
5. 日历里第 4 天的事件写着“板布局 ✓ · 引物 2 对 ✓ · SYBR 余量 2 板”。

### 4.4 工具页（做成特色）

```
工具
┌ 这周的实验要用 ─────────────────────────────────────────┐
│ 11/04 EXP-012 转染：配液卡未建 → [打开转染计算器]          │
│ 11/06 EXP-012 qPCR：板布局未建 → [打开 qPCR 板布局]        │
└────────────────────────────────────────────────────────┘
规划  质粒工作台 · 自由板布局 · qPCR 板布局 · CNV 板布局
配制  计算器（31 种）
分析  qPCR 分析 · CNV 分析 · 可视化
最近的成果  板布局 3 · 计算 12 · 核查 2 · 分析 1（按实验列出）
```

- 质粒工作台放在第一位。
- 卡片保留现有的“预览”和“打开”。
- 工具清单测试改为检查登记的完整性，不再写死数量。

### 4.5 带上下文打开、结果回传

- 统一的打开方式：`?experiment=<id>&block=<段>&step=<步骤>`。
- 统一的桥：沿用自由板布局和计算器之间的 postMessage 约定（校验来源和 `requestId`）。
  - `labnest:context`：LabNest 发给工具，内容是样本、分组、批次、引物等；
  - `labnest:result`：工具发回 LabNest，内容是板布局 JSON、计算结果等。
- qPCR、CNV 规划器从“注入文字”改为桥接。需要改上游工具（它们是课题组自己的独立产品）；改好之前保留现在的注入方式。

### 4.6 实验页的“工具”栏

只汇总，不新存。数据来自：

- 板布局：文档里的板布局块和 `plate_layout` 附件；
- 计算：类型为“计算”的结果；
- 配液卡：`executionPlanJson` 里的回执；
- 质粒：用量记录 → 批次 → 核查记录；
- 分析：分析类结果和数据集。

按日程段分组显示。没有日程段的实验按时间排列。

### 4.7 日程段里的“工具缺口”

按段内的步骤推断需要什么：

- 步骤属于 qPCR 或 CNV 规程，或提到孔板 → 需要板布局；
- 步骤的材料引用了质粒批次 → 需要核查过的批次和转染配液卡；
- qPCR 规程的引物材料 → 需要引物产品（带序列）。

缺了就在卡片和“今天”里列出，点一下带上下文打开对应工具；齐了显示 ✓。规则写在代码里，可以测试，不用 AI。

## 5. 问题与推荐

**Q282 联动的存储方式。** 推荐：
- 不新建统一的“工具成果”表。各类成果仍落在已有的地方：板布局块或附件、计算结果、配液卡回执、核查记录（质粒工作台新增）、结果数据集。
- 实验页新增“工具”栏，按日程段汇总显示（4.6）。

备选：新建 `ToolRun` 表，记录每次使用的工具和产出。

**Q283 带上下文打开与回传。** 推荐：
- 所有工具统一用 postMessage 桥（4.5）。上下文包括实验、日程段、步骤、样本（ID、名称、分组、顺序）、相关批次和引物。
- qPCR、CNV 规划器改用桥接，需要改上游工具；改好之前保留现在的注入。

备选：继续只靠网址参数和注入。

**Q284 qPCR / CNV 规划器的板布局回传。** 推荐：
- 上游工具新增 JSON 导出，字段对齐自由规划器 v2，带样本 ID。
- LabNest 把它读成板布局块，回填样本的“所在孔”；Excel 仍作附件保存。

备选：LabNest 去解析它们导出的 Excel。

**Q285 分析结果回流。** 推荐：
- 把 qPCR 分析和 CNV 分析的结果表解析成结果数据集：每个样本、每个靶标一行（Cq、ΔCt、ΔΔCt、相对表达或拷贝数）。
- 按样本 ID（没有时按名称）对回实验样本；对不上的行列出来，由人指定。
- 工作簿仍作附件，解析结果注明来自哪张表、哪个版本的工具。
- 研究方案的判定标准旁显示对应的实际值（[Copilot 工作流](../../ai/copilot-workflow-20261101/PLAN.md) 第 9 节）。

备选：继续只存工作簿，不读数值。

**Q286 计算器读库存、质粒和样本。** 推荐：
- 转染、连接、DNA/RNA 换算、稀释四类计算器加“从库存选”：
  - 从质粒产品的序列取长度；
  - 从批次取浓度和测定日期；
  - 从库存取储液浓度；
  - 从实验取样本数和分组，作为份数。
- 结果旁写明数据来源；缺数据时照旧手填。

备选：只做转染计算器。

**Q287 日程段里的工具缺口。** 推荐：
- 按 4.7 的规则推断每段需要的工具成果，缺了在卡片和“今天”里列出，点一下带上下文打开对应工具。
- 只提示，不阻止开始实验。

备选：只在执行页提示，不进日程。

**Q288 “/”新增的引用。** 推荐：
- 写作编辑器的“/”加两项：
  - “质粒图谱”：插入带版本号的图谱快照，点开进工作台。序列改了，快照仍是当时的版本，并提示“已有新版本”；
  - “实验”：引用实验编号，悬停显示日期和状态。
- Protocol 编辑器不加（理由同 Q248：规程可重复使用，不放具体实验的东西）。

备选：只加“质粒图谱”。

**Q289 工具页改版。** 推荐：
- 按 4.4 分三区：
  - “这周的实验要用”：来自日程的缺口和快捷入口；
  - 按实验阶段分组的工具卡（规划 / 配制 / 分析），质粒工作台在首位；
  - “最近的成果”：各实验的板布局、计算、核查、分析。
- 工具清单测试改为检查登记的完整性，不写死数量。

备选：只加质粒工作台卡片，页面结构不变。

**Q290 实验产出库存批次。** 推荐：
- 允许实验在“产出”里登记库存批次。第一批只开放质粒和菌株类：小提、大提、甘油菌。
- 新批次自动带上来源实验和用到的上游批次（例如“由 2311A 转化后挑 3 号克隆大提”），之后可以做测序核查。
- 样本的产出方式不变。

备选：产出仍只能是样本，质粒批次在库存里手工新建。

## 7. 验收要点（建议）

- 4.3 的例子能从头走到尾：转染卡片显示质粒核查状态；计算器带着长度和浓度打开，配液卡回到这一段；qPCR 板布局带着样本和引物打开，回传后样本页显示所在孔；分析结果对回样本，判定标准旁显示实际值。
- 工具缺口：去掉板布局后，卡片和“今天”出现提示；补上后变 ✓。
- 计算器的来源说明正确；数据缺失时可以手填，并标“手填”。
- 旧路径：现有的注入、附件上传在新桥接上线前照常可用。
- 不新增工具成果表；实验页的“工具”栏来自已有记录。

## 8. 不做什么、风险

- 不把上游工具复制进 LabNest 重写；改上游工具另立项目。
- 不让工具直接写库存数量：扣减仍走执行完成时的用量确认。
- **风险：桥接接口要和上游工具一起维护。** 约定带版本号；LabNest 遇到不认识的版本时回退到附件。
- **风险：按名称对样本可能对错。** 优先按 ID；只能按名称时列出对应关系，由人确认后才写入。
