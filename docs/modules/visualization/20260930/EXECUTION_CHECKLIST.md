# Visualization Studio：Codex 执行清单

编制日期：2026-09-30。用途：作为后续 Codex 开发任务的执行合同与验收清单。

**本轮只编写清单，没有启动下面的开发任务。** 所有待办均未完成；已有清理和调研成果见 [REVIEW.md](REVIEW.md)。

**产品边界修订（2026-09-30，用户最新决定）：Visualization Studio 是独立产品，LabNest 通过链接接入。** 本条取代此前“独立版与内嵌版同步、三处源码共同维护”的要求。旧报告里的源码比对和运行记录仍是历史事实，不再是未来开发合同。本轮修订未切换线上入口或删除旧源码。

## 一、目标与范围

将现有 Visualization Studio 改进为“数据准备 → 作图或分析 → 结果复用 → 项目恢复 → 论文图表导出”的完整工作区。保留当前绘图引擎、科学方法边界和图形质量，优先复用已有能力。

Studio 独立拥有产品界面、源码、版本、部署、项目文件、AI 模型设置和计算服务。LabNest 的职责是工具目录与跳转入口，直接打开 Studio，不使用 iframe 或复制其页面/运行代码。首期链接不传递科研数据或模型凭证；未来数据互通另用明确、版本化的接口设计。

按以下三个交付批次推进：

| 批次 | 必做任务 | 可交付结果 |
|---|---|---|
| 第一批 P0 | VIS-00～VIS-08、VIS-18，加本批 VIS-90/91 | 独立 Studio 完成数据与作图闭环，LabNest 通过已验证链接打开产品 |
| 第二批 P1 | VIS-09～VIS-14，加本批 VIS-90/91 | 多面板论文拼图、出版导出、统计结果表、基线资料表、常用配对预设 |
| 第三批 P2 | VIS-15～VIS-17，加本批 VIS-90/91 | 可选 R 计算服务与首个经验证的差异分析/富集流程 |

用户指定某批时，只执行该批及其必要前置任务；不要自动扩展到后续批次。用户直接要求“按清单开始”而未指定批次时，默认执行**第一批 P0 到验收和适用的交付环节完成**，不在每个小步骤反复询问。

不以工具数量为验收指标，不把对方 233 个入口逐个复制。第一批不改配色体系，不新增远端上传，不重写现有计算模块，不开发泛癌数据库、MR、免疫浸润、自动机器学习或第二套 qPCR 分析器。
