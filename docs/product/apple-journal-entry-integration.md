# Apple Journal 到 LabNest Entry 的融合评估

> 状态：产品评估 + 阶段 1/2 实施记录
>
> 日期：2026-08-08
>
> 依据：用户提供的 2 分 38 秒屏幕录制 `Screen Recording 2026-08-08 at 20.56.22.mov`，以及当前 LabNest 仓库中的 Entry、Attachment、Search 与 Prisma 实现。

## 1. 结论

Apple Journal 的核心交互非常适合成为 LabNest Entry 的展示与采集方向，但应融合其“时间线 + 富媒体内容块 + 轻量记录”的方法，而不是照搬个人日记的全部语义。

最值得优先融合的是：

1. 按月分组的单列时间线，而不是当前等宽小卡片网格。
2. 图片、音频、手绘、地点或实验上下文与正文共同组成一个 Entry。
3. Entry 卡片直接展示媒体拼贴、标题、摘要、日期和科研元数据。
4. 在同一编辑器顶部集中提供图片、拍照、上下文位置和录音入口。
5. 保存后可直接搜索 Entry 的标题与正文，并逐步扩展到附件名、音频转写和关联对象。

不建议直接照搬的是：个人日记连续打卡、情绪化 Insights、消费级地理足迹和装饰性贴纸系统。它们应分别改造成科研记录完整度、实验时间线、实验室位置/仪器上下文和图片标注能力。

## 2. 证据标记

- **录屏明确展示**：在本次视频中可以直接观察到。
- **当前已有基础**：LabNest 当前代码或数据模型已经具备部分能力。
- **建议实现**：产品方向判断，不代表当前代码已经支持。
- **待确认**：录屏不足以确认完整行为，不应作为已存在功能写入需求。

本文不是 Apple Journal 的完整官方功能说明，也不推断录屏之外的系统能力。

## 3. 录屏中的 Journal 功能清单

### 3.1 Journal 首页与时间线

**录屏明确展示：**

- 主内容区按月份分组，例如 September 2024、July 2024、May 2024。
- 每条 Entry 是一张宽卡片，而不是只展示标题的列表。
- 多张照片会自动形成大小不一的媒体拼贴；视频缩略图带时长。
- 卡片在媒体下方展示标题或摘要、具体日期和更多操作菜单。
- 页面顶部始终保留新增按钮和搜索框。
- 左侧栏有 Journal 集合、Entry 数量、Insights 和 Places 概览。
- 保存测试 Entry 后，Insights 从 0 更新为 1 Entry，并展示年度记录数、记录天数和累计字数。

**对 LabNest 的意义：**

- Entry 首屏应优先表现“这次记录里发生了什么”，媒体和实验上下文应比标签堆叠更突出。
- Project 可以承担 Journal 集合的角色，Research Plan 可作为更细一级的上下文，不必新建重复的个人 Journal 分类模型。

### 3.2 新建与编辑 Entry

**录屏明确展示：**

- 点击顶部加号进入编辑页面。
- 编辑页显示记录日期、独立标题行和正文区域。
- 右上角勾选按钮用于完成或保存。
- 顶部工具栏集中放置照片、相机、地点和录音入口。
- 富文本浮层包含粗体、斜体、下划线、删除线和列表类格式。
- 一张粉色手柄图片曾以内嵌内容出现在正文区域。

**待确认：**

- 录屏不能证明粉色手柄来自 Journal 内置贴纸库；更可能是粘贴、拖入或系统输入内容。因此本项目只把它归为“正文内嵌图片”，不建立独立贴纸需求。
- 录屏没有明确演示自动保存、版本历史、撤销恢复或多人协作。

### 3.3 图片与相机

**录屏明确展示：**

- 照片入口打开系统照片选择器。
- 选择器支持照片库搜索、收藏、最近保存、视频、截图、相簿和媒体类型等分类。
- 界面提示一次最多选择 14 个项目，并可连同位置元数据加入。
- 编辑工具栏具有独立相机入口。

**对 LabNest 的意义：**

- 最有价值的不是接入个人照片库分类，而是支持一次选择多张实验图片，并在 Entry 中形成可读的拼贴预览。
- 相机入口适合快速拍摄培养皿、显微镜屏幕、仪器状态、样本标签和异常现象。
- 原始图片必须作为附件保留；裁剪、压缩、标注图只能作为派生版本，不能覆盖原件。

### 3.4 地点与上下文

**录屏明确展示：**

- 地点入口打开可搜索的地点选择器。
- 选择器会列出既往 Journal 中出现的地点。
- 选中地点后，地点以独立彩色内容条出现在 Entry 中。
- 左侧 Places 卡片用地图方式汇总既往地点。

**对 LabNest 的意义：**

- 不应优先复制个人 GPS 地图。
- 更适合改造成受控的科研上下文：实验室、房间、工作台、仪器、冰箱、培养箱或样本存储位置。
- 位置应优先链接到 LabNest 中已有对象或受控词表，避免只有不可计算的自由文本。

### 3.5 音频录制

**录屏明确展示：**

- 首次录音会请求麦克风权限。
- 录音在右侧独立面板中进行，显示实时波形、时间轴、录制时长、播放/暂停和前后 15 秒跳转控件。
- 完成录音后，音频以带播放按钮、时长和大幅波形的内容块插入 Entry。

**待确认：**

- 录音面板出现了类似文本或对话的图标，但视频没有演示转写结果，不能据此认定 Journal 已在本次流程中完成语音转文字。

**对 LabNest 的意义：**

- 适合记录双手被占用时的实验观察、仪器异常声音、临时决策和口述偏差。
- 音频原件应保留；波形图和未来的自动转写属于派生数据。
- 自动转写必须标记为机器生成并允许人工校正，不能直接替代原始实验记录。

### 3.6 手绘与标注

**录屏明确展示：**

- Entry 中可以插入较大的手绘画布。
- 画布提供选择、笔型、颜色、图形或对象以及文本等工具入口。
- 笔型菜单明确出现 Pen、Monoline、Marker、Pencil、Crayon、Fountain Pen、Reed、Watercolor 和 Eraser。
- 手绘内容保存后成为 Entry 的一个可再次编辑或查看的内容块。

**对 LabNest 的意义：**

- 科研场景不需要复刻全部艺术笔刷；首版更需要箭头、矩形、圆形、自由笔、文本、颜色、撤销和橡皮擦。
- 最重要的用途是标注显微图、凝胶图、孔板布局、切片区域、仪器界面和异常位置。
- 应同时保存可继续编辑的笔画数据和渲染预览，不能只保存一张不可修改的截图。

### 3.7 搜索

**录屏明确展示：**

- 在顶部搜索框输入 `cell` 后，页面显示 `1 Entry`。
- 命中的 Entry 以完整富媒体卡片出现，而不是只有一行标题。
- 搜索结果保留音频波形、地点、正文和手绘预览。

**对 LabNest 的意义：**

- 搜索结果应能直接判断记录是否相关，并深链到具体 Entry。
- 后续索引范围应包括标题、纯文本正文、标签、Project、Research Plan、附件文件名、人工确认后的音频转写和关联科研对象。

## 4. 当前 LabNest Entry 的真实基础

### 4.1 已有能力

- `Entry` 已有标题、纯文本正文、发生时间、Project、Research Plan、标签、来源类型、记录状态和 State。
- 新建 Entry 时可选择 Protocol 版本，并进一步形成 Experiment、Protocol Run、初始 Result、对象链接和待审核动作。
- Attachment 已支持本地文件存储、元数据、通用目标链接和 25 MB 的 V1 单文件限制。
- Search 已能检索数据库中的 Entry 标题、正文和 State。
- 全局已经存在 Project、Research Plan、Protocol、Experiment、Result、Inventory、Sample、Item Link 等科研对象。

### 4.2 当前缺口

- `/entries` 当前是两列小卡片网格，没有按月时间线和媒体主视觉。
- Entry 正文仍是单个纯文本字段，没有有序的富媒体内容块。
- Entry 列表把附件数和相关项暂时写成 `0` 或空数组，没有查询真实 AttachmentLink 和 ItemLink。
- 新建 Entry 表单不能在同一流程中上传并排序图片、音频或手绘内容。
- 没有 Entry 详情、编辑、草稿恢复、修订历史和 Entry 级深链接。
- 搜索结果目前只回到 `/entries`，不能直接定位某条 Entry；附件名和转写内容也未进入索引。
- Attachment 尚未记录文件哈希、派生关系、预览图、媒体时长、图片尺寸或音频波形元数据。

## 5. 可以融合的内容与优先级

| Journal 能力 | LabNest 融合方式 | 当前基础 | 优先级 | 判断 |
| --- | --- | --- | --- | --- |
| 单列、按月时间线 | `/entries` 按 `occurredAt` 分月，宽卡片展示 | 已有时间字段 | P0 | 可直接融合 |
| 富媒体 Entry 卡片 | 图片拼贴 + 标题 + 摘要 + 日期 + 科研元数据 | 有 Attachment 模型，但列表未接线 | P0 | 应优先融合 |
| Project 作为 Journal 集合 | 左侧或顶部按 Project 切换，Research Plan 作为次级筛选 | 已有 Project/Research Plan | P0 | 可直接融合，避免新模型 |
| 搜索完整 Entry | 命中后显示富媒体卡片并深链到详情 | 已有基础文本搜索 | P0 | 可融合，需详情路由 |
| 多图上传与排序 | 新建页支持拖放、多选、预览、重排和删除待上传项 | 有上传 API | P1 | 可融合，需重做创建流程 |
| 富文本格式 | 标题、段落、列表、检查项、强调、链接、代码块 | 只有纯文本 `body` | P1 | 可融合，需结构化正文 |
| Entry 详情与编辑 | 查看、编辑、复制、导出、归档和关联对象 | 尚无详情/编辑路由 | P1 | 富媒体前置能力 |
| 音频录制与波形 | 浏览器录音，原音频作为 Attachment，波形为派生预览 | Attachment 可存文件 | P1 | 可融合，需客户端录音组件 |
| 科研上下文位置 | 实验室、工作台、仪器、存储位置或样本位置引用 | 有 Inventory location 和对象链接 | P1 | 推荐做语义改造后融合 |
| 图片标注/手绘 | 简化画布；保存可编辑笔画与 PNG/SVG 预览 | 尚无画布数据结构 | P2 | 可融合，复杂度中等 |
| 相机直拍 | 浏览器摄像头或移动端文件捕获，直接进入待上传区 | 有上传 API | P2 | 可融合，需权限与设备测试 |
| Insights | 改为 Entry 完整度、未复核记录、待办、项目活跃度和记录覆盖 | 可从现有模型聚合 | P2 | 适合科研化改造 |
| Places 地图 | 仅在确有跨地点采样需求时增加地图；实验室内部先用受控位置 | 暂无地理模型 | P3 | 暂不优先 |
| 连续打卡/情绪激励 | 不作为科研记录的核心 KPI | 有自由文本 State | P3 | 不建议照搬 |
| 装饰性贴纸 | 普通内嵌图片或科研图像标注即可 | 有 Attachment 基础 | P3 | 不单独建设 |

## 6. 推荐的目标 Entry 形态

### 6.1 列表卡片

每张宽卡片建议按以下顺序显示：

1. 首图或多图拼贴；没有图片时可显示音频、手绘、结果摘要或纯文本封面。
2. Entry 标题和 2–4 行正文摘要。
3. 发生日期与时间。
4. Project、Research Plan、记录状态和来源。
5. 真实附件数、关联对象数和待审核动作数。
6. 更多菜单：查看、编辑、复制、导出和归档。

卡片按月分组，默认单列。大屏可以让正文区和科研上下文形成内部双栏，但不建议恢复成两张 Entry 并排的小卡片。

### 6.2 编辑器

编辑器建议分为三层：

- **顶部固定信息**：日期、标题、Project、Research Plan、记录状态。
- **内容区**：可排序的 text、image、file、audio、drawing、location/context 和 object-link 内容块。
- **科研正式化区**：Protocol、Experiment、Result 与 Proposed Action；保持当前“用户审核后再正式化”的边界。

正文应保持连续写作体验。Protocol-Based Experiment 等较重字段可以折叠或放在侧栏，避免快速记录时先面对整张复杂表单。

## 7. 建议的数据与审计边界

富媒体 Entry 不应只把 HTML 塞进 `body`。建议在保留纯文本摘要字段的同时增加结构化内容，例如：

```text
Entry
  body              # 可搜索的纯文本摘要或兼容字段
  contentJson       # 有序内容块，只保存文本和附件/对象引用

Entry content block
  id
  type              # text | image | file | audio | drawing | context_ref | object_ref
  order
  payload

Attachment
  original file
  SHA-256
  MIME type / size
  media metadata
  derived-from relation
```

科研记录还需要以下约束：

- 原始附件不可被标注图、压缩图或转写文本覆盖。
- 音频转写、OCR、图像预览和波形均标记为派生内容。
- 保存创建时间、修改时间，并为正式记录增加修订历史或审计事件。
- 删除、替换附件和把 Entry 正式化为 Experiment 时记录来源与操作者。
- 自动提取或 AI 生成的内容必须显示待确认状态。

## 8. 推荐实施顺序

### 阶段 0：已完成的小修复

- `New Entry` 按钮文字固定为单行；窗口变窄时按钮整体换位，但标签内部不拆成两行。

### 阶段 1：先完成 Journal 式展示骨架

- `/entries` 改为按月分组的单列宽卡片。
- Project 作为 Journal 集合筛选。
- 新增 `/entries/[id]` 详情页和 Entry 深链接。
- 查询真实 AttachmentLink、ItemLink 和 ProposedAction 数量。
- 没有附件时保持高质量纯文本卡片，有附件时显示媒体封面或拼贴。

这一阶段可以先不迁移富文本数据，风险最低，也最能快速确认视觉方向。

### 阶段 2：建立富媒体采集基础

**实施状态：已完成（2026-08-08）。**

- 已增加结构化 `Entry.contentJson`，正文以安全的轻量 Markdown 内容块保存，同时保留纯文本 `body` 供搜索和旧数据兼容。
- 新建与编辑 Entry 共用轻量 Composer，支持多图/文件拖放、照片选择、移动端相机入口、本地预览、排序和移除。
- 草稿正文与待上传原始文件保存在浏览器 IndexedDB；刷新页面后可以恢复。
- Entry 与附件在同一保存流程中持久化；数据库失败时回滚 Entry 事务并清理已写入文件，界面保留草稿供重试。
- Attachment 已增加 SHA-256、图片尺寸/预览元数据、派生来源与派生类型字段；旧附件可通过 `npm run attachments:backfill-metadata` 补齐。
- AttachmentLink 已保存内容顺序；Entry 详情页和时间线按结构化顺序读取媒体。
- 已增加 `/entries/[id]/edit`，可以继续添加、删除和重排 Entry 媒体；被移出 Entry 的原始 Attachment 不会被静默覆盖。

**本阶段明确不包含：**浏览器录音、音频波形、自动转写和手绘标注。这些仍属于阶段 3。

### 阶段 3：录音与标注

- 使用浏览器 MediaRecorder 实现录音、计时、播放和上传。
- 生成波形预览；转写作为独立、可校正的派生内容。
- 增加简化手绘/图片标注工具，保存笔画源数据和渲染预览。

### 阶段 4：科研化搜索与 Insights

- 搜索附件名、转写、Project、Research Plan 和关联对象，并返回完整 Entry 卡片。
- 增加与科研执行相关的 Insights：未复核 Entry、缺少 Project/Protocol 的记录、待处理动作、按项目的记录覆盖和长期未更新实验。
- 只有出现明确的跨地点采样需求后，再评估地理地图。

## 9. 第一轮融合的建议范围

第一轮建议只实现以下六项：

1. 按月单列时间线。
2. Journal 式宽 Entry 卡片。
3. Project 集合切换。
4. Entry 详情页与深链接。
5. 真实附件/关联对象计数与图片预览。
6. 轻量多图/文件上传入口。

这六项能建立正确的产品骨架，同时不立即引入录音、复杂画布、转写和地图的权限与数据治理成本。确认展示方向后，再进入富媒体内容块和录音阶段。
