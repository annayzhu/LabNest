## 1. 本次必须交付什么

1. 打通“快速记录 → 实验 / 实验结果”的整理流程，保留原始记录和时间。
2. 修复快速记录中四类已报告问题：插入表格界面错乱、设置二级标题后异常跳转、四张照片显示七个文件且出现奇怪条目、移动图片变成复制。

4. 对核心富文本操作验证完整链路：输入 → 编辑 → 撤销/重做 → 保存 → 离开 → 回读 → 只读展示 → 已有导出/打印。
5. 在桌面、窄窗口和移动视口完成回归，明确真机测试与浏览器模拟的区别。
6. 提交代码、必要的数据修复方案、自动化测试、页面验收矩阵和简明变更说明。存在未解决问题时逐项列明，不能笼统宣布全部完成。

本文件是独立的新专项。此前已调试完成的任务不整体重开；与本轮共享的编辑器、附件、时间和布局链路作为回归范围。Entry 的中文名称统一为“快速记录”。本次不以更换编辑器技术栈、全面重写系统或复刻 Word 的全部功能为前提。

## 3. 快速记录与实验、结果如何联动

### 3.1 产品原则：先记录，后整理

快速记录是低负担的原始记录入口。用户可以先输入文字、拍照或上传图片，暂时不填类型、不选研究方案、不选实验，也能正常保存。

后续使用“归入…”建立主要归属。在实验或结果页面直接显示该记录的内容和原记录时间，而不只是给一个必须跳转才能看的链接。快速记录仍保留原 ID、正文、图片和来源；默认不复制成第二份可独立修改的正文。

“归入”表示这条记录主要属于哪里；已有“关联项”可以表达其他参考关系。不要增加两套意义重叠的选择器，也不要把记录类型、实验执行状态、审核状态混成一个字段。优先扩展现有关系和界面。

### 3.2 类型与目标

记录类型默认“未分类”，可选“实验记录”“观察/结果”“想法”，允许修改。类型是辅助整理，不能仅凭类型自动新建实验、结果或推断科学结论。

| 内容 | 默认操作 | 目标页面中的表现 |
|---|---|---|
| 实验过程、操作、临时偏差 | 归入已有实验；或新建实验后归入 | 在该实验的记录区域显示这条原始记录 |
| 观察现象、测量结果、图片 | 先选择所属实验，再归入已有结果；或新建结果后归入 | 在对应结果的来源记录区域展示，并保留所属实验关系 |
| 想法、疑问、后续计划 | 保持独立；需要时关联研究方案、实验等 | 不强行创建实验或结果 |
| 混合内容 | 用户选主要归属，可添加其他关联 | 本轮不自动拆文、不擅自复制到多个正文 |
| 暂不能判断 | 保持未分类、未归入 | 仍可搜索和再次整理 |

观察可以是阴性、失败、不确定或初步发现。“归入结果”只是信息归档，不能据此改为已验证、已审核或成功实验。

### 3.3 界面流程

**快速记录页：**标题附近显示原记录时间与紧凑的“归入…”入口；已有归属时显示可点击目标名称，并在更多菜单提供“更改归属”“取消归入”。正文和图片是页面主体，不加多层目录或大型统计卡片。

**归入实验：**选择“实验” → 搜索已有实验 → 预览实验名称、编号和研究方案 → 确定。没有合适目标时提供“新建实验并归入”，只填现有系统要求的必要信息。

**归入结果：**选择“实验结果” → 选择或确认所属实验 → 从该实验的结果中选择，或“新建结果并归入”。若当前已有实验上下文可以预填，但必须清晰展示；选中的结果与所属实验不一致时禁止产生矛盾关系。

**想法：**可先保留独立状态，通过已有关联项补充研究方案等关系。不要要求想法必须归入实验才能完成整理。

**目标页面：**在现有记录区加入该条目的标题、原记录时间、原作者和正文/图片预览，提供“查看原始记录”“编辑原始记录”。默认编辑的是同一份来源内容；目标自身已有正文不能被覆盖。

完成归入后保留当前阅读位置，用简短提示和“查看目标”入口反馈即可，不强制跳到另一页面。快速记录总列表仍可检索该记录；提供“未归入 / 已归入”筛选，默认视图沿用当前产品习惯。

### 3.4 关系与内容一致性

以下是业务约束，字段名和数据库实现由执行者按实际项目确定，不要求另起一套模型：

- 一条快速记录本轮默认只有一个主要归属，其他对象通过普通关联表达。
- 单一主要归属、结果所属实验和操作权限应在服务端提交时再次校验，不能只依赖前端选择器过滤。两个窗口同时改归属也不得生成两条主要归属或矛盾关系。
- 归入结果后可在所属实验中被聚合检索，但不能再生成第二条相同的原始记录。
- 重复点击、网络重试和恢复请求必须只产生一次有效归入；新建目标并归入也应避免重复目标和无归属半成品。
- 当前内容尚未保存时，先完成有效保存再确认归入；保存失败保留原归属和草稿，不显示归入成功。图片上传未完成时明确显示上传状态，“归入成功”不能替代“上传成功”。归属更新只修改相关关系，不能携带旧正文覆盖另一个窗口的新内容。
- 改归属或取消归入只改变关系，不删除来源正文、附件，不重写原记录时间。
- 目标页的来源内容采用同一记录的引用；来源修改后应按现有版本规则展示，并保留修改时间。不要制造两个可独立保存、互相覆盖的编辑器。
- 若现有审核/签署流程已经冻结结果或报告，则沿用版本锁定规则，保留所引用的来源版本，不能用来源后续修改静默改变已审核内容。冻结规则也约束引用的新增、取消和转移；来源之后改归属或删除，不得使冻结目标保留的来源版本和附件消失。普通草稿无需额外强加审批流程。
- 如果用户明确需要复制为独立文档，作为单独的“复制”操作，保留来源标记；不能把默认归入偷偷实现成复制。
- 混合内容的局部摘录、批量智能分类可留作后续功能。本轮保证整条归入和附加关联可用，不为此推迟四个缺陷修复。
- 权限按现有规则校验；归入关系不自动扩大来源访问范围。目标读者无权读取来源时显示清晰状态，不能泄露正文、缩略图或文件。
- 删除目标不级联删除快速记录；使用现有归档/软删除能力保留可恢复来源，显示归属失效并允许重新归入。删除来源前应按现有机制提示其被引用情况，避免静默破坏目标。

### 3.5 时间必须保真

| 时间概念 | 用途 | 规则 |
|---|---|---|
| 首次记录时间 | 用户最初建立这条快速记录的时间 | 归入、更名、编辑、刷新、移动附件后均不覆盖 |
| 实际实验/观察时间 | 用户需要补录事件发生时间时使用 | 与记录时间区分；未知时不自动等同于首次记录时间 |
| 最近修改时间 | 正文或有效元数据变更 | 单独保存、展示，不冒充首次记录时间 |
| 归入时间 | 建立归属关系的时间 | 用于追溯，不替换原记录在时间线中的发生顺序 |
| 新目标创建时间 | 新建实验/结果对象的真实时间 | 不回填成旧快速记录时间；来源记录仍展示旧时间 |

例如：10 月 6 日 09:15 创建快速记录，10 月 8 日归入实验，该来源卡片仍标注“记录于 10 月 6 日 09:15”。如果实际实验时间是 10 月 5 日，另行标注，不能混为同一字段。

核查服务端存储、客户端显示和导出采用的时区。保留可还原的时间戳与已知时区/偏移信息，显示遵循账户设置；不要重复加八小时。历史数据如果只有日期或缺乏时区依据，保留精度并标明未知，不凭空补出 00:00 或 08:00。离线记录若存在，应区分设备记录时间与服务器接收时间。迁移不得以批量处理时间覆盖历史值。

## 4. 四个用户已报告问题：必须单独闭环

### RT-01：插入 → 表格选项格式错乱

当前尚不能确认问题只在菜单还是也影响插入后的表格，因此两处都检查。

**复现：**在快速记录空文档、已有长文、含图片文档中打开“插入 → 表格”；分别在页面顶部与接近底部操作，插入 3×4 表格，输入中英文及数字；保存、离开、回读。桌面、窄窗口、手机视口都执行。

**检查：**表格选择网格、文字、图标和悬停提示是否对齐；菜单是否被裁切、遮挡、偏移或超出视口；点击格子是否选择正确行列；插入后单元格边框、内边距、行高、文字基线和工具条是否正常。检查嵌套滚动容器、弹层定位、全局表格样式及编辑/只读样式的差异。

**目标：**菜单可读、可点、可触摸；表格默认适合内容区。窄屏宽表格在表格容器内滚动，不撑坏整页。不以压缩到难以阅读或全局隐藏溢出的方式掩盖问题。已有增删行列、合并、宽度等功能若存在，必须回归；不要求为了本轮新增全部 Word 表格能力。

### RT-02：把一行设为二级标题后页面异常跳转

**复现：**构造超过两屏的混合文档，在中部和底部分别选中一段正文，使用工具栏设为 H2；继续输入，再切换为正文、撤销、重做。分别覆盖折叠工具栏、侧栏展开、自动保存触发、图片加载完成及软键盘弹出的情况。记录光标位置、选区和各级滚动容器，不只看页面最外层。

**目标：**格式应用于选中段落；光标/选区仍在该处；文档不跳到顶部、底部或其他段落，路由不发生意外导航。标题行高改变或光标原本在视口外时可进行必要的最小滚动。用户继续打字应落在原操作位置。

**待验证方向：**工具栏点击丢失选区、错误聚焦或滚动命令、格式操作意外提交表单、锚点/目录联动、组件重建、每次保存后重载整篇文档、异步回写重置光标、图片尺寸变化引起布局移动。

按实际事件与状态变化确定根因。不要用延时滚回固定位置、永久禁止滚动、全局拦截鼠标默认行为或每次强制聚焦文末来遮盖症状；这些做法可能破坏中文输入、触摸和无障碍操作。

### RT-03：只加入四张照片却显示七个文件，出现 download 等条目

**第一步：核查原故障记录。**在获授权的当前账户内按原创建时间找到用户所说的最新快速记录，记录其 ID、环境和读取时间。不能因为列表第一条变化就检查错对象。先只读核查，随后使用副本或隔离测试数据复现，不覆盖用户正文。

输出七个条目的核对表：界面名称、逻辑附件 ID、原始文件名、类型/大小、来源操作、上传状态、正文引用位置、关联的原始图片、是否为缩略图/预览派生物。逐项解释多出来的三项来自哪里；没有数据不能猜。

**统一计数口径：**

- 主“附件”数量 = 当前文档有效引用的原始图片和独立附件的逻辑附件 ID 并集大小。
- 同一原始图片出现在正文并在附件列表展示，只计一项；同一逻辑图片被有意插入两处，图片位置有两处，但附件数仍为一。
- 缩略图、预览图、压缩派生图、临时 blob 地址、上传占位、失败上传和纯 URL 链接，不计为额外原始附件。上传中/失败项以独立状态提示，不伪装成已保存文件。
- 四张不同照片且没有其他附件的测试记录，保存后应为“4 个附件”，可显示“图片 4”。四张图片加一份真正上传的 PDF，则应为五个附件。
- 用户再次明确上传同名或相同字节文件的行为，与同一次上传的重复请求不同。不要按文件名或内容哈希无差别合并、删除用户有意保留的文件。重试去重应依赖同一次操作的稳定标识和已确认的关系。

**download 条目排查：**可能是真实原始文件名、下载按钮文案串入文件名、粘贴 HTML 被误识别成附件、临时下载对象错误登记等。以上仅为假设。必须核查来源；不能仅凭名称删除。缺失名称时使用合理可读的显示名，并保留能够找到原文件的身份信息。

**修复验收：**界面、接口有效关联和存储对象关系一致。不要仅修改前端显示数字，也不要以存储桶对象总数代表附件数。历史异常先生成只读诊断与拟处理清单；对确认的错误引用提供可回滚、可重复执行的修复，禁止按名字或日期直接批量删除原文件。存在其他文档引用时必须保护。

### RT-04：移动图片时意外复制

**复现：**同一文档内，把一张图片拖到前面、后面、段落中、图片之间以及表格附近；包括页面滚动后的拖动。每次检查正文节点、附件关系和上传请求，再撤销、重做、保存回读。

**行为合同：**

| 动作 | 正确结果 |
|---|---|
| 同一文档内普通拖动 | 移动原图片节点，旧位置消失，新位置出现；原附件 ID 不变，无新增上传 |
| 放回原位、拖出后取消、无效落点 | 原图不丢失、不复制，不产生孤立附件 |
| 明确“复制”或项目已有复制快捷操作 | 才允许新增图片位置；与移动可区分 |
| 外部文件拖入或粘贴截图 | 走正常导入流程，一次操作只登记一次 |
| 跨文档放置 | 按项目既定复制/引用规则处理，权限清晰；不得默认删掉来源 |
| 手机不便拖动 | 提供可发现的上移/下移或剪切后粘贴等可靠等价操作 |

优先检查编辑器内部移动与外部文件导入是否同时触发、拖放事件是否被重复处理、浏览器提供的多种数据格式是否被重复解析、旧节点是否被正确移除。不要只隐藏重复的视觉节点。

一次图片移动应是一次完整的撤销操作。撤销恢复原位置，重做回到目标位置；图片数量和有效附件数始终不变。移动不能重新上传原图，也不能改变原始记录时间。

## 5. 全站文本输入：先列清单，再逐个打开

### 5.1 盘点方法

结合路由、实际导航、共享组件和动态弹窗盘点，不能只搜索某个编辑器组件。区分富文本、普通单行输入、多行输入、可编辑表格、搜索/筛选、下拉搜索，不要把所有字段强制改成富文本。

下列是最低检查范围，实际不存在的入口填“不适用 + 依据”，实际还有的入口必须补入：

| 页面或入口 | 要覆盖的文本输入与展示 |
|---|---|
| 快速记录 | 新建、编辑、详情、标题、正文、插入菜单、关联项、附件 |
| 研究方案 | 新建/编辑、正文、备注、右侧元数据与关联项 |
| 实验规程 | 正文、步骤、表格、图片说明、元数据抽屉、模板 |
| 实验 | 新建/编辑、计划、执行记录、备注、偏差/异常 |
| Run / Record | 当前步骤输入、表格填写、证据、手机记录及回读 |
| 实验结果 | 新建/编辑、观察、分析说明、关联的来源记录 |
| 报告 | 正文、结果引用、图注、预览、已有导出/打印 |
| 评论、讨论、模板等 | 项目实际存在的编辑入口及弹层 |
| 库存、试剂、样本及其他业务模块 | 项目实际存在的名称、备注、描述等输入 |
| 工具和计算器 | 文本参数、注释、预设命名、粘贴数据等实际输入 |
| 全站通用控件 | 搜索、筛选、重命名、标签、关联对象检索、设置 |

同一组件被六个页面调用，也要在六个真实页面中分别操作。不同页面的滚动容器、侧栏、弹窗和自动保存逻辑可能造成不同结果。

### 5.2 每个实际入口的检查动作

1. 打开真实页面并记录 URL/路由、模块、编辑器类型和进入方式。
2. 空状态、已有内容、长标题/长段落、错误提示、只读/编辑切换分别查看。
3. 输入中文、英文、数字、标点，选择文本后执行该处已有的格式或编辑动作。
4. 检查标签、输入框、图标、按钮、帮助提示的基线与间距；检查明显的挤压、空白、遮挡、错位和水平溢出。
5. 检查浮层展开与关闭、键盘选择、触摸、滚动后定位、窗口缩放后定位。
6. 对有保存功能的字段执行保存、离开、回读；富文本再检查只读和已有输出路径。
7. 截图并填写结果。涉及焦点、跳转、拖放、抖动的缺陷，必须有操作录屏或可重放的交互记录，截图不能替代。

### 5.3 最低视口与环境

- 桌面：1440×900。
- 常用笔记本：1366×768；检查顶部工具条和弹窗不会挤掉主要编辑区。
- 窄窗口：约 820×900；结合实际断点补查断点两侧。
- 手机：390×844，补查 360px 宽；覆盖软键盘出现、收起以及横竖屏切换能够测试的部分。
- 桌面缩放 100% 与 125% 至少覆盖核心流程。
- 浏览器以项目实际支持范围为准。至少验证主要桌面浏览器；若支持 Safari 或 Firefox，补查焦点、粘贴、拖放和表格。
- 真机 iOS/Android 输入、相册选择和触摸拖动，如当前可用则实测；没有真机时明确标记待测。移动视口或模拟 WebKit 不能冒充真机验收。

每个文本入口至少完成桌面与窄屏/移动视口检查；每种编辑器实现必须走完完整编辑用例。仅桌面存在的控件，验证移动端替代入口或明确的产品行为。

## 6. 富文本编辑的统一行为要求

### 6.1 输入、格式与光标

- 中文拼音输入过程中不得丢字、重复、提前提交或把尚未确定的文字拆散；自动保存、快捷键和输入法候选不能互相抢事件。
- Enter、Shift+Enter、Backspace、Delete 在正文、标题、列表、表格和图片相邻位置的表现保持一致且可预期。
- 加粗、斜体、下划线、标题、字体/字号、对齐、列表、缩进、链接等现有功能，格式状态与当前选区一致；执行后选区不落到别处。
- 只有确有必要时把当前光标滚入视口；不因自动保存、侧栏变化或格式菜单关闭而跳到文首/文末。
- 全选、复制、剪切、粘贴、撤销/重做遵循平台快捷键；撤销只影响当前文档，不混入其他记录。
- 未完成输入时切换页面遵循已有草稿机制，不能静默丢失；不要通过频繁弹框打断正常编辑。

### 6.2 表格

- 插入、修改、选择单元格、增删行列等已支持操作，在编辑、回读和只读中结构一致。
- 表头、边框、内边距、数值与文字可读；单元格工具条不会被隐藏或盖住当前输入。
- 覆盖从 Word/Excel 粘贴普通表格和制表符数据的现有行为；不支持的格式应可靠降级，不能错列、丢值或生成破坏布局的隐藏元素。
- 宽表、长单词、长链接只能在合理容器内换行/滚动；不要让整页被横向撑开。
- 表格中的图片、列表、标题如现有编辑器支持，需要与普通文档行为一致。

### 6.3 图片、粘贴与文件

- 覆盖文件选择、多图上传、外部拖入、截图粘贴、内部拖动、剪切粘贴、复制粘贴，以及手机已有的相册/拍照入口。
- 同一次粘贴中的 HTML 图片与文件对象只能按正确的单一路径处理，不能一个动作插入两张。
- 图片提前保留合理尺寸或比例，加载后不大幅推动正在编辑的段落；缩放与顺序在保存回读后保持。
- 上传失败可重试，取消有效；切换记录、慢网和请求重试不应把图片挂到错误文档。
- 移除图片节点与删除底层文件要区分；仍被其他位置/文档引用的文件不能误删。
- 文件名、类型、预览、下载与实际对象对应；无需暴露内部 ID、临时 URL 和无意义的下载占位文案。

### 6.4 保存、版本与内容转换

- 先识别现有正文权威格式及每条转换链路，再修改；禁止假设所有模块使用同一格式或库。
- 自动保存不得替换正在编辑的整篇文档、重建编辑器或清空撤销栈。
- 慢网下旧请求晚返回，不能覆盖更新内容；快速切换两条记录时保存目标必须正确。
- 成功提示必须对应真实保存成功；失败保留本地内容，状态简短明确，可重试。
- 对已有多标签页/多人同时修改情形，沿用并核查冲突处理；至少不允许无提示的旧内容覆盖新内容，不为本轮强建复杂协同系统。
- 旧记录能继续读取和编辑；必要迁移必须可回滚。检查 HTML/JSON/Markdown 等实际转换是否丢失图片身份、表格、对齐和标题。
- 编辑、只读、结果引用、报告预览及已有导出/打印保持必要内容一致。不要宣称从技术上保证 Word 全格式无损兼容。

### 6.5 布局与操作效率

- 工具栏按操作分组，常用操作可见；低频操作进更多菜单。压缩重复文案与无效留白，不靠极小字号和点击区域挤空间。
- 表格插入菜单、标题菜单、字号、颜色、链接等浮层有统一对齐，随滚动和视口正确定位，不超出屏幕或被侧栏裁切。
- 触摸目标有足够面积，相邻按钮不易误触；键盘焦点可见，菜单能够用键盘打开、选择和退出。
- 内部编号、重复中英文、与当前任务无关的防御性长段说明不常驻。保存失败、权限冲突和真实数据问题仍要说明清楚。
- 若既有功能在手机不适合拖动，提供等价的移动/排序方式；不要仅隐藏功能。

## 7. 调试方法与执行顺序

### 阶段 A：核对实际运行环境

记录本机启动目录、当前分支/提交、未提交修改、启动命令、实际访问地址、应用构建/缓存状态、测试账户和浏览器。历史上下文曾使用 localhost:3000，但它不代表执行者当前环境，应以实际运行实例为准。

先阅读仓库适用说明并保护已有改动。确认浏览器看到的是本次代码，避免源码已改但开发服务、缓存或旧资源仍未更新。不要为排除缓存清掉用户草稿和离线数据。

### 阶段 B：建立四个缺陷的复现与全站入口表

先复现 RT-01～04 并记录基线；对原故障记录先做只读诊断，再用隔离副本操作。实际无法复现时记录精确尝试条件，并保留为未闭环，不能写“未发现问题”后结束。

建立所有实际文本入口的清单，同时查明各自采用的编辑器、保存链路、附件登记方式和共用组件。仅在必要时查阅当前依赖版本对应的官方文档，不凭记忆编造接口。

### 阶段 C：修复数据与核心交互

按 P0 → P1 顺序修复，优先定位共用根因。涉及两种不同编辑器时分别修复和核验；不能在没有回归的情况下为统一外观强行迁移所有历史文档。

为图片移动/上传去重、附件计数、归属关系和时间不变、保存请求乱序添加有意义的回归测试。布局小改不需要逐像素单元测试，使用实际视觉验收；关键交互应有浏览器操作测试。

### 阶段 D：实现快速记录归入

复用现有实体、关系、权限、选择器和版本机制，完成整条记录的归入、更改、取消、目标展示与来源回看。不要把新功能做在只有独立工具页面可见的另一套代码里。

### 阶段 E：两轮验收

第一轮对每个入口执行视觉与基础交互检查；第二轮围绕修复涉及的共享组件、四个报告问题及跨页面完整流程回归。发现新问题后修复并重跑受影响项目，不需为凑轮数重复无关测试。

验收以真实应用路由为主，组件演示或静态截图是辅助证据。浏览器自动化必须经过用户会使用的按钮和菜单，不得直接调用内部编辑命令后宣称交互通过。

全部合成测试数据必须标记“测试”，与真实科研记录隔离。

- `docs/qa/entry-richtext-audit.md`：实际入口矩阵、缺陷编号、根因、修复和剩余项。
- `docs/qa/entry-richtext-acceptance.md`：本验收矩阵的执行结果、测试环境及对应证据路径。
- `docs/qa/evidence/entry-richtext/`：脱敏截图、录屏或自动化交互追踪；四个问题保留修复前后证据。
- 必要的回归测试与历史异常诊断/修复脚本：使用仓库已有测试体系和迁移方式。

验收报告至少包含：运行地址、提交版本、浏览器及视口、测试数据标识、已检查入口数量、通过/失败/阻塞项目、构建与测试命令结果。不要在截图和日志中暴露真实科研隐私或上传敏感原图到公开位置。

### 10.3 停止条件

完成授权范围内的实现和验证后再交付。关键依赖阻塞时，先完成不受阻塞的工作，再明确缺少什么、影响哪些验收；不要因拿不到真机就停止桌面修复，也不能因为自动化通过而忽略用户复现的操作问题。

数据完整性及核心交互缺陷仍存在时，不得标为本专项完成。达到可测标准后停止无目的的反复测试，保留清晰证据和真实剩余项，供用户确认实际体验。
