## 修复和回退边界

两种迁移均须先 dry-run 保存原记录与差异；没有原 ID 映射、原文指纹变化、用户开始执行或版本发生新编辑时停止。规程修复新增 Draft 修订，不写入科研批准。历史修复仅允许 planned/draft 且没有完成、计时、事件或库存动作，保存父记录／步骤锁，普通进度和计时也使用共同父锁。

正式迁移之前另作 PostgreSQL 自包含备份、附件目录／内容指纹；不能用隔离副本备份代替。回退代码保留旧 app 镜像；数据回退先把迁移前 dump 恢复到新的隔离数据库，核对原步骤、冻结正文与关联 ID，再按该记录清单选择性恢复。迁移后的真实执行记录不得被整库旧备份覆盖。回退流程尚未实际执行，不将“有备份”写成“恢复演练通过”。
