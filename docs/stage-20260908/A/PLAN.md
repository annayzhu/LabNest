# A：采购 / Inventory 独立重构计划

起点 `1aed227f34e0dbe3558fbb30fcd503aaaef3dd4a`。不属于 Calculator 重构；使用独立分支/PR、隔离数据库和验收记录。

## 已核对的现状

- InventoryItem 已有稳定ID、批号、位置、父子分装关系；currentQuantity 为必填 Float 默认0，不能表达未知量。
- InventoryTransaction 已有实验/步骤/采购关联和唯一 clientMutationId；继续复用，不建立第二个扣减账本。
- PurchaseRequest 可选 linkedInventoryItemId 与 procurementQuoteLineId，具备独立采购基础。
- ProcurementInquiry / QuoteLine 保留候选与采购决定；现有学校模板导出不能替代通用实际购买/分批收货/凭证状态。

## 实施顺序

1. 管理方式与未知数量：增量兼容字段区分信息追溯/包装/精确管理；既有记录保留明确原余额，不将其一律改成未知。开始数量管理通过有日期/操作者来源的盘点事务，禁止反推历史。
2. 实物容器：沿用 InventoryItem 产品/批次与分装身份，添加稳定容器记录和流转历史；多瓶批量登记由服务端分配编号。领用/转交/归还不会复制容器或把领用当耗尽；包装库存可领用数由实际容器状态确定。
3. 余量观察：追加观察记录，估计/实测、登记时间、操作者、实验来源独立；不从两次观察差值创建精确消耗。
4. Run 使用记录：允许自由名称与可选库存/容器来源，保存预计和实际、来源、扣减状态；复用既有事务唯一键和单位换算。保存实验与提交扣减分开，失败行保留待处理，已领瓶不二次扣仓库瓶。
5. 独立采购：直接购买、候选报价、分批收货、凭证状态分离；每收货行明确是否入库及实际量，追加收货记录并绑定幂等键。报销导出从实际购买取值并留存快照，不混入未选报价。
6. 独立 CSV / Excel 导入：列映射→预览→逐行错误→确认重复策略，区分当前余额/到货/历史；不凭名称合并跨品牌批号物料。补关联只修改关系，不重复入库。

## 兼容与安全边界

保留现有编号、交易、关联和分装ID。数据库只做增量迁移，并在隔离数据库验证旧样本；本轮没有生产迁移授权。既有权限和未识别用户状态照实保留：没有登录身份时不能伪造“本人”，记录手工填写的领用人和未识别操作者。

包装与容量仅在明确规格时转换；跨维度需要浓度/适用参数。所有数量校验在服务端执行。数量观察、起始盘点与精确消耗分别存储，交易重试最多提交一次，更正保留关联。

## 验收

按总清单 T01—T19 逐项记录已通过/失败/未执行，测试仅使用合成记录。关键用例：5瓶领1瓶→仓库4/持有1；转交归还保持同一ID和开封日期；250→180 mL估计不生成70mL消耗；重复提交不二次扣减；独立采购导入/库存导入无前置依赖。函数/接口/浏览器/数据库回读证据分开。
