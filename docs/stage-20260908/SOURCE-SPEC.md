## A. 采购与 Inventory 独立重构

### A1. 模块独立，按需关联

必须支持以下使用组合：

- 只记录实验，不使用采购或库存。
- 只使用采购，包括询价、采购决定、实际购买明细与报销材料整理。
- 只使用库存，直接登记或导入当前物料。
- 只管理部分关键试剂，其他试剂保留在实验记录中。
- 同时使用各模块，按需建立关联。

不用某模块时，其他模块仍可创建、保存、导入、查询和导出，不要求补造前置记录，不持续催促用户启用未使用的功能。

关联是可选的，但已经执行的库存变动必须可追溯。界面隐藏某个模块不能删除历史数据或改变既有权限。

### A2. 每种物料可采用不同管理程度

| 管理程度 | 记录内容 | 数量要求 |
| --- | --- | --- |
| 仅在实验中记录 | 名称、可选品牌及用量 | 不要求建立库存 |
| 信息追溯 | 品牌、货号、批次、位置等适用信息 | 不强制填写余量 |
| 按包装管理 | 瓶、盒、包的入库、领用、持有人和使用状态 | 不强制每次登记 mL 或 µL |
| 精确用量管理 | 具体库存或分装及实际消耗 | 扣减前需要有效数量、单位和来源 |

同一实验室可以混合采用上述方式。不能仅根据价格自动决定管理规则。

“数量未记录”与“数量为零”分别表示；信息追溯物料不因未填数量而被误报为缺货。由轻度管理转为数量管理时，通过实际盘点建立有日期的起始余额，不推算或补造过去的消耗。变更管理方式保留历史，不追溯执行旧 Run 的扣减。

同种产品、不同批次、实际瓶和分装需能区分；常规使用合并展示，需要追踪时再展开。不要要求用户为了录入一瓶试剂先完成复杂的多级建档。

### A3. 培养基按瓶流转——已确认场景

示例：仓库原有5瓶培养基，张三领走1瓶。

| 项目 | 结果 |
| --- | --- |
| 仓库可领用数量 | 4瓶 |
| 张三持有 | 1瓶，尚未用完 |
| 该瓶信息 | 来源批次、瓶编号、持有人、位置、领用时间和使用状态 |
| 库存含义 | 领用是流转，不是立即耗尽；在管瓶数不代表等量满瓶余量 |

支持以下操作：

- 领用：选择物料与数量，领用人默认本人，位置可使用常用值。
- 开封：可标记并记录日期；领用时不自动假定已开封。
- 转交：更新持有人及位置，保留流转历史。
- 归还：保留开封、余量及其他适用状态；部分使用后的归还不显示成完整未开封库存。
- 用完：明确结束该瓶的可用状态。

同批多瓶可合并登记，追踪实物时由系统分配稳定的瓶编号，避免额外逐瓶建档负担。归还、转交和领用不应反复创建互不关联的同一实物记录。

### A4. 可选登记估计剩余量

允许在 Run 收尾或瓶子详情中填写“本次实验结束后，约剩多少 mL”。

显示示例：约剩180 mL · 已开封 · 张三持有；同时显示最近更新日期。

- 选填，默认标记“估计”；有实际测量时可选择“实测”。
- 未填写时保留上次值和原日期；从未登记显示“余量未记录”。
- 保存本次值、登记人、时间、估计／实测属性及可选关联实验，保留历史。
- 上次约250 mL、本次约180 mL，不自动生成“本次消耗70 mL”。
- 余量观察、余额校准与精确消耗分别处理，不与已提交的扣减重复计量。
- 按瓶数量和瓶内余量分别维护；填了余量不会再次减少仓库瓶数。
- 用紧凑行内控件登记，不新增常驻的大表单或嵌套卡片。

### A5. Run 中记录使用与库存扣减分开

Run 中提供“本次使用的试剂与耗材”，允许同表混合管理。

1. Consumption 表或 Calculator 带入预计物料及用量，保存其来源；预计值与实际确认值分别记录。
2. 库存中不存在的物料可以直接记录名称，不强制新建库存。
3. 可记住常用关联；实际换批次、换瓶时可调整。不要仅凭同名自动确定来源。
4. 实验收尾时只汇总需要扣减的项目，确认实际用量后批量提交。不管理库存的行不生成逐项跳过的待办。
5. 未确认、库存不足或换算条件不满足时，可以保存实验；对应扣减保留清晰的待处理状态，不能假报成功。
6. 使用个人已经领出的培养基，只关联该瓶，不再从仓库扣一瓶。
7. 实验失败不自动退回已经用掉的试剂；未执行的步骤不自动形成实际消耗。
8. 复制实验不复制已执行交易；重复提交、请求重试和离线同步不得重复扣减。
9. 更正已有扣减需保留原记录和更正关系，不静默改写历史。

同一物料在共享库存中的数量规则应保持一致。保留现有权限边界；某行无法扣减时不能丢失该次实验的其他记录。

单位规则：同维度换算保持物理量；包装与容量需要明确规格；质量与体积等跨维度转换需要适用浓度或其他必要参数。“1盒”“100次反应”“500 µL”不得直接互换。

### A6. 采购独立流程

采购需要支持：

- 直接录入或导入供应商报价，保留未选报价及采购决定。
- 跳过询价，直接登记已下单、已收货或历史实际购买记录。
- 只导入实际购买明细，整理报销材料，不必启用库存。
- 记录分批收货；按收货行选择不加入库存、新建库存或补充已有库存。
- 从库存发起采购需求并带入已有信息，由用户决定是否购买。

询价、采购、收货和报销材料状态分别表达，允许“已收货、发票待补”等状态。不要要求全部用户走完整审批链，也不要绕过已有权限。

报价比较表、采购申请／清单、报销明细分别导出。实际购买数量和金额可能与报价不同，报销明细依据实际购买记录及凭证信息整理。导出文件不等于报销已提交或已完成。

现有学校自购模板保留为一种模板，不作为所有物料录入的必填合同。按所选模板在导出阶段校验必要字段，保留来源和导出记录，避免后续改价让历史导出失去依据。

### A7. 各自导入与历史兼容

采购与库存分别提供 Excel／CSV 导入入口，支持列名对应、预览、错误定位和重复处理。

- 采购导入不要求库存记录；库存导入不要求采购来源。
- 必填信息按用途区分：报价不要求批号，位置追踪不要求采购价格，报销模板字段在对应阶段补齐。
- 区分导入当前余额、新增到货和历史明细，不能每次上传都累加库存。
- 后续补关联采购与库存只建立关联，不重复入库。
- 不把未知数量或缺失金额静默变成零；不能仅凭名称合并不同品牌、规格或批次。
- 保留既有库存编号、交易、实验关联及分装关系；需要迁移时提供兼容策略与验证证据，不在生产环境擅自运行迁移。

## B. 全站 UI 与共享交互

### B1. 页面覆盖与平整布局

建立全站页面覆盖表，包括首页、各模块列表、详情、编辑、设置、侧栏和弹出面板。不得只改 Inventory 或只改一个示例页面。

主页面和右侧属性栏均取消装饰性的卡片嵌套。分组使用标题、细分隔线、对齐、字号和少量底色。输入控件保留必要的边界；工具目录允许单层可点击卡片。

布局按任务选择：库存使用目录与紧凑表格；询价采用对照表；采购采用状态列表；详情采用身份信息、标签页与记录；正文以文档为主体；设置采用分类导航与连续表单。统一视觉语言，但不要把所有页面都改成同一种网格。

减少重复说明、冗余留白和重复导航，保留可读字号和可操作的触控范围。桌面及手机都要检查，手机最高160%缩放仍可用。

### B2. 右侧上下文属性面板

采用类似 Adobe Illustrator 的属性交互：从右侧滑出、收起，可固定展开，随选中对象切换内容。

- 同一页面使用一个主要属性面板，不叠加多个属性侧栏。
- 物料显示管理方式、分类与预警；实际瓶显示批号、持有人、位置、开封日期等；采购行显示规格与供应商；图片显示尺寸、图注和替换等属性。
- 面板内部使用紧凑分组，低频属性折叠；不再嵌套圆角卡片、阴影和多层底色。
- 标题固定，内容采用一个主要滚动区域，避免分组各自出现滚动条。
- 切换选中对象时保留未提交内容，不能误写到新对象。
- 实际用量、更新余量等高频输入保留在主界面。
- 手机采用覆盖式面板，不把正文挤成狭窄的一列。

### B3. 大量关联对象

研究方案关联大量 Protocol 时，右侧显示数量与少量摘要，默认最多3项，通过“管理全部”在同一研究方案的主工作区管理。

采用列表行显示名称、编号及必要版本／状态；支持搜索、筛选、批量添加和解除关联。切换视图保留研究方案未保存内容。解除关联不能删除原 Protocol，不自动改变历史 Run 使用的版本。

同类规则用于大量实验、结果和附件关联。默认展示数量和置顶方式可结合现有组件调整，但必须保持侧栏长度可控且能方便访问全部记录。

### B4. 全站数值与单位控件

覆盖采购、Inventory、Run、Calculator、表格及其他带单位输入。

- 数值与单位同排、一体呈现，不各占大框；唯一单位直接显示，可切换单位提供简洁菜单。
- 宽度适配内容，数字列与单位列对齐，支持长数值、科学计数法及复合单位。
- 已有值可原位编辑；高级属性按需出现。
- 同一物理量切换单位保持实际值，例如180 mL与180000 µL等价。跨维度换算要求必要参数。
- 输入时允许合法的未完成状态，例如小数点或指数尚未输入完整；提交时按字段规则校验，不让非法负库存通过。
- 空值不等于零，估计值保持估计属性。
- 支持 Tab 连续填写，适当使用 Enter确认、Esc取消；不能拦截中文输入法候选词确认。
- 普通属性可提供即时预览；领用、扣减等明确显示提交范围和执行状态。
- 手机键盘、触控、160%缩放、错误提示及焦点位置必须验证。

## C. 全站文本编辑器修复

覆盖 Protocol、研究方案、实验、结果、报告、随手记录、结果模板说明，以及 Run 中相关内容的展示。

### C1. 图片保存后不可见、打印空白

用户在实验板块反馈：插图后保存看不见图片、打印为空白。优先排查上传、正文转换、保存、附件关联、数据库回读、访问地址和只读渲染整条链路。

区分引用丢失、关联异常、原文件缺失和加载失败，不预先认定原图已丢失。不能通过清除旧记录解决显示问题；保留原图、历史版本及 Run 快照。

实际验证：插图→上传完成→保存→刷新→重新编辑→只读查看→打印或已有正式导出。检查图片真实加载成功，而不是仅检查存在图片标签或附件编号。不能将未完成上传表示为已保存。

编辑页和只读页的打印都要检查文字、图片和表格，不得空白或遗漏关键内容。

### C2. 中文图注与图片属性

- 图注支持中文输入法选词、回车确认、中英文混输、修改、保存与再编辑。

- 修改显示尺寸保留原图，不把显示操作变成原文件修改。
- 实验等页面的元数据视图与 Protocol 保持一致：主工作区内容边界与上方工具栏对齐；右侧属性使用统一面板规则。

### C3. 全文与表格字号

所有文档文本都可修改字号，包括正文、标题、列表、图注及表格文字。

- 支持选中文字、单个单元格、多单元格、整行与整表的修改。
- 提供明确的全文字号操作，覆盖所有章节及表格；局部操作只影响选中范围。
- 混合字号选区显示“多种字号”，不误报单一值。
- 不破坏标题层级、列表、表格结构和其他格式语义。
- 在保存、刷新、再编辑、只读、打印及已有正式导出中保留字号。
- 区分文档字号和系统 UI 缩放，不能用整体页面缩放代替文本字号设置。

## E. 验收清单与交付

### E1. 必测场景

所有条目初始为待验证，不因文档形成或代码合入自动通过。

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| T01 | 只记录实验 | 没有采购或库存也能保存、完成Run |
| T02 | 只用采购 | 独立导入、比较、记录购买与导出，不强制入库 |
| T03 | 只用库存 | 直接导入当前库存，不补造采购历史 |
